### 6-复2 DNS 域名系统

域名系统的主要功能是什么？域名系统中的**本地域名服务器、根域名服务器、顶级域名服务器以及权限域名服务器**有何区别？

<details>
<summary>答案</summary>

**功能**：把便于记忆的域名转换为 IP 地址。

**四种域名服务器区别**：

| 类型 | 地位 | 职责 |
|------|:--:|------|
| 根域名服务器 | 最高层、最重要 | 知道所有顶级域名服务器的 IP，无法解析时首先求助根 |
| 顶级域名服务器 | 管理者 | 管理对应顶级域下注册的所有二级域名 |
| 权限域名服务器 | 区级管辖 | 负责一个"区"内所有主机的域名→IP 映射 |
| 本地域名服务器 | 最接近用户 | 接收用户的 DNS 查询请求 |

> DNS 的管辖范围以**区(zone)**为单位，不是以域(domain)为单位。

</details>

### 6-习3 域名解析过程

举例说明域名转换的过程。域名服务器中的**高速缓存**的作用是什么？

<details>
<summary>答案</summary>

**域名解析过程**（以查询 y.abc.com 为例）：

1. 主机向**本地域名服务器**发出递归查询
2. 本地域名服务器向**根域名服务器**查询
3. 根返回 **com** 顶级域名服务器 IP
4. 本地向 **com** 顶级域名服务器查询
5. 顶级返回 **abc.com** 权限域名服务器 IP
6. 本地向 **abc.com** 权限域名服务器查询
7. 权限返回 **y.abc.com** 的 IP
8. 本地将结果返回给主机

主机→本地：**递归查询**；本地→其他：**迭代查询**（逐步问）。

**高速缓存的作用**：
- 存放最近查询过的域名→IP 映射
- 大大减轻根域名服务器的负荷
- 减少 DNS 查询请求和回答报文的数量
- 每个记录有计时器，过期删除（平衡准确性与开销）

</details>

### 6-习4 DNS 瘫痪后还能发邮件吗

设想有一天整个互联网的 DNS 系统都瘫痪了（这种情况不大会出现），试问还有可能给朋友发送电子邮件吗？

### 6-复4 FTP 工作原理

文件传送协议 FTP 的主要工作过程是怎样的？为什么说 FTP 是**带外传送控制信息**的？主进程和从属进程各起什么作用？

<details>
<summary>答案</summary>

**工作过程**：
1. FTP 服务器主进程打开熟知端口 21，等待客户连接
2. 客户连接 → 主进程启动从属进程处理请求
3. 建立**两个并行的 TCP 连接**：控制连接（21）+ 数据连接（20）
4. 控制连接**整个会话期间保持**，传送命令；数据连接传输文件，传完即关

**带外控制**：
控制信息在分离的**控制连接**（端口 21）中传送，不在**数据连接**（端口 20）中传送→ 称为"带外"(out of band)。

**主进程**：接收新请求，启动从属进程后回到等待状态。
**从属进程**：处理单个请求（控制进程 + 数据传送进程）。

</details>

### 6-复5 FTP vs TFTP

简单文件传送协议 TFTP 与 FTP 的主要区别是什么？各用在什么场合？

<details>
<summary>答案</summary>

| | FTP | TFTP |
|--|-----|------|
| 运输层 | TCP | **UDP** |
| 端口 | 21/20 | **69** |
| 交互 | 支持 | 不支持 |
| 命令集 | 完整 | 简单 |
| 差错改正 | TCP 保证 | 自己实现 |
| 身份鉴别 | 有 | 无 |
| 优点 | 功能强大可靠 | 代码小、可用于 UDP 环境 |

TFTP 工作类似停止等待协议：每次 512 字节数据，确认后续发下一块。

**适用场景**：只需要简单复制文件而不需要 FTP 全部功能时，TFTP 是很好的选择。

</details>

### 6-习14 HTTP 判断正误

请判断以下论述的正误，并简述理由。

1. 用户点击某网页，该网页有 1 个文本文件和 3 张图片。此用户可以发送一个请求就可以收到 4 个响应报文。
2. 有以下两个不同的网页：`www.abc.com/m1.html` 和 `www.abc.com/m2.html`。用户可以使用同一个 HTTP/1.1 持续连接传送对这两个网页的请求和响应。
3. 在客户与服务器之间进行非持续连接，只需要用一个 TCP 报文段就能够装入两个不同的 HTTP 请求报文。
4. 在 HTTP 响应报文中的主体实体部分永远不会是空的。

<details>
<summary>答案</summary>

**(1) 错误。** 非持续 HTTP 需要 4 个 TCP 连接分别发送 4 个请求和响应。持续 HTTP 可以在一个 TCP 连接上连续传送，但也需要 4 个独立的请求和响应。

**(2) 正确。** 两个网页在同一个服务器（域名相同），HTTP/1.1 持续连接可以在同一个 TCP 连接上传送。

**(3) 错误。** 非持续连接下，**每个** HTTP 请求报文必须使用**新的 TCP 连接**。

**(4) 错误。** 某些情况下（如 404 Not Found），服务器返回的响应主体可以为空。

</details>

### 6-习15 URL 解析时延计算

假定你在浏览器上点击一个 URL，但这个 URL 的 IP 地址以前并没有缓存在本地主机上。因此需要用 DNS 自动查找和解析。假定要解析到所要找的 URL 的 IP 地址共经过 **n 个 DNS 服务器**，所经过的时间分别为 RTT₁, RTT₂, …, RTTₙ。假定从要找的网页上只需要读取一张很小的图片（即忽略这张小图片的传输时间）。从本地主机到这个网页的往返时间是 **RTTw**。试问从点击这个 URL 开始，一直到本地主机的屏幕上出现所读取的小图片，一共要经过多少时间？

<details>
<summary>答案</summary>

分两步：

1. **DNS 解析**：RTT₁ + RTT₂ + … + RTTₙ
2. **建立 TCP 连接 + 请求文档**：2 × RTTw（TCP 三次握手 1.5RTT + 请求响应 0.5RTT？）

> 标准答案：建立 TCP 连接和请求万维网文档需要 2RTTw。

**总时间 = RTT₁ + RTT₂ + … + RTTₙ + 2RTTw**

</details>

### 6-复21 电子邮件信封与内容

电子邮件的**信封**和**内容**在邮件的传送过程中起什么作用？和用户的关系如何？

<details>
<summary>答案</summary>

**信封**：传输程序根据信封信息（特别是收件人地址）来传送邮件，保证邮件能正确传送到收件人的邮箱。

**内容**：在传送过程中不暴露。用户可以传送任意格式，但应让收件人能读取。

**与用户的关系**：信封保证送达，内容决定信息价值。如果用户不读取邮箱，就不会看到邮件。

</details>

### 6-复22 电子邮件地址格式

电子邮件的地址格式是怎样的？请说明各部分的意思。

<details>
<summary>答案</summary>

格式：**收件人邮箱名@邮箱所在主机的域名**

- `@` 读作 "at"，表示"在"的意思
- 收件人邮箱名（用户名）：在邮件服务器的计算机中**唯一**
- 邮箱所在主机的域名：在互联网中**唯一**
- 两者结合 → 整个地址在互联网范围内唯一

例：`username@163.com`

</details>

### 6-习23 SMTP 通信三阶段

试简述 SMTP 通信的**三个阶段**的过程。

<details>
<summary>答案</summary>

**1. 连接建立**
- SMTP 客户扫描邮件缓存，发现有邮件 → 使用熟知端口 25 与接收方 SMTP 服务器建立 TCP 连接

**2. 邮件传送**
- `MAIL FROM:<发件人地址>` — 发件人
- `RCPT TO:<收件人地址>` — 收件人（可多个，先确认再发送避免浪费资源）
- `DATA` — 开始传送邮件内容

**3. 连接释放**
- 邮件发送完毕 → `QUIT` 命令 → 释放 TCP 连接

> 注意：邮件在互联网中间的邮件服务器不会落地。

</details>

### 6-习35 SNMP 为什么用 UDP

SNMP 使用 UDP 传送报文。为什么不使用 TCP？

<details>
<summary>答案</summary>

- UDP 无连接，开销小
- SNMP 通过**周期性发送**探询报文来监视网络资源
- 丢失一个报文 → 过一段时间后再发一个
- 这比使用 TCP 更快（不需要连接建立和释放）

</details>

### 6-习46 应用层协议为何选 TCP 或 UDP

1. 简单讨论一下为什么有的应用层协议要使用 TCP，而有的却要使用 UDP？
2. 为什么 MIME 画在 SMTP 之上？
3. 为什么路由选择协议 RIP 放在应用层？

<details>
<summary>答案</summary>

**(1) TCP vs UDP 的选择：**
- 需要可靠传送 → 用 **TCP**（HTTP, FTP, SMTP 等）
- 数据丢失可容忍，或通过其他机制弥补 → 用 **UDP**（DNS, RIP, SNMP 等）
- TCP 开销大，UDP 开销小

**(2) MIME 在 SMTP 之上：**
- MIME 不是独立的邮件传送协议
- 它扩展了 SMTP 邮件的内容格式（支持多媒体、非 ASCII 文本）
- MIME 不能单独使用，依赖 SMTP 传输

**(3) RIP 在应用层：**
- RIP 使用 **UDP（端口 520）**传送
- 在协议栈中，使用 UDP 即位于应用层

</details>

### 6-习51 P2P 文件共享

现在流行的 P2P 文件共享应用程序都有哪些特点？存在哪些值得注意的问题？

<details>
<summary>答案</summary>

**特点**：
1. 不使用集中式文件服务器，分布式对等传输
2. 每个对等方既可以是客户也可以是服务器
3. 大文件划分为许多小文件，从多个对等方下载
4. 精心设计的协议可以使大文件下载很快

**问题**：
1. 版权保护
2. 安全性（恶意文件、隐私泄露）
3. 具体信息受商业利益保护，难以获得

</details>
