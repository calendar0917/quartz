**1.** 时延带宽积的物理含义是？

A. 链路上传输一个比特所需的时间
B. 以比特为单位的链路长度——即管道中最多可容纳的比特数
C. 数据从发送到接收的总时延与带宽的比值
D. 链路上单位时间可通过的数据量

<details>
<summary>答案</summary>

**B**

时延带宽积 = 传播时延 × 带宽。它表示从发送端发出但尚未到达接收端的比特数，即管道中最多可容纳的比特数。只有当管道充满比特时，链路才被充分利用。

</details>

**2.** 根据排队论，当信道利用率 U 增大时，时延 D 会如何变化？

A. 时延线性增大：D = D0 × U
B. 时延指数增大：D = D0 × 2^U
C. 时延非线性急剧增大：D = D0 / (1−U)
D. 时延不变，与利用率无关

<details>
<summary>答案</summary>

**C**

根据排队论，时延与利用率的关系为 D = D0 / (1−U)。当 U 趋近于 1 时，时延趋向于无穷大。这就是为什么网络不能满负荷运行。

</details>

**10.** 某主机 IP 地址为 172.16.100.50/18，默认网关是 172.16.64.1。现该主机向 172.16.130.20 发送数据。ARP 将解析谁的 MAC 地址？

A. 172.16.130.20（目的主机）
B. 172.16.64.1（默认网关）
C. 172.16.100.50（本机）
D. 先查 ARP 表，没有则广播请求 172.16.130.20 的 MAC

<details>
<summary>答案</summary>

**A**

/18 的网络地址为 172.16.64.0（100.50 AND 255.255.192.0 = 64.0）。目的地址 172.16.130.20：130 AND 192 = 128 ≠ 64 → 不在同一子网？等等。

172.16.100.0/18？不，主机在 172.16.64.0/18 子网内。目的主机 172.16.130.20 的前 18 位是什么？

172.16.100.50：第三字节 01100100。前 2 位 = 01 → 属于 172.16.64.0/18。
172.16.130.20：第三字节 10000010。前 2 位 = 10 → 属于 172.16.128.0/18。

**不在同一子网！** 因此主机需要把数据报发给默认网关。

故应先通过 ARP 解析**默认网关 172.16.64.1** 的 MAC 地址。

答案：**B**

</details>

**14.** 在 RIP 协议中，"坏消息传播得慢"是指？

B. 链路故障信息需要逐跳更新，经过较长时间才能传播到所有路由器

<details>
<summary>答案</summary>

**B**

</details>

### 1. 奈氏准则与香农公式（6 分）

请分别说明奈氏准则和香农公式的含义，并解释它们的区别和联系。

1. 奈氏准则给出了什么限制？适用于什么条件？
2. 香农公式给出了什么限制？适用于什么条件？
3. 奈氏准则说"最高码元速率 = 2W"，如果每个码元携带 4 比特信息，信息传输速率能否无限提高？香农公式如何约束这一想法？

<details>
<summary>答案</summary>

**1. 奈氏准则**（2 分）：
在**无噪声**、带宽为 W Hz 的低通信道中，码元传输的最高速率 = **2W 码元/秒**。超过此上限会产生严重的码间串扰。奈氏准则只限制码元速率，不直接限制信息传输速率。

**2. 香农公式**（2 分）：
在**有噪声**的信道中，极限信息传输速率 C = W × log2(1+S/N) bit/s。这是**绝对的、不可突破的上限**，无论采用多么复杂的编码技术。

**3. 联系与区别**（2 分）：
即使每个码元携带更多比特来提高信息速率，也不能突破香农公式的限制。香农公式说明的是信噪比和带宽决定的信息传输速率的物理极限。
- 奈氏准则：**激励**工程师探索更先进的编码技术，让每个码元携带更多比特
- 香农公式：**告诫**工程师存在不可突破的绝对极限

</details>

### 2. TCP 的连接建立与释放（6 分）

请画图说明 TCP 的三报文握手建立连接和四报文挥手释放连接的全过程。

1. 写出三次握手每一步的 SYN、ACK 标志位和序号/确认号的变化
2. 写出四次挥手每一步的状态变化
3. 为什么建立连接是三次而释放连接是四次？为什么释放连接时主动关闭方需要等待 2MSL？

<details>
<summary>答案</summary>

**1. 三报文握手**（2 分）：

```
客户端 A                        服务器 B
  |── SYN=1, seq=x ──────────────→|  (A 进入 SYN-SENT)
  |←── SYN=1, ACK=1, seq=y, ack=x+1 ──|  (B 进入 SYN-RCVD)
  |── ACK=1, seq=x+1, ack=y+1 ───→|  (A,B 进入 ESTABLISHED)
```

SYN 报文不携带数据但消耗一个序号。第三个 ACK 可携带数据。

**2. 四报文挥手**（2 分）：

```
A(主动关闭)                      B(被动关闭)
ESTABLISHED                     ESTABLISHED
  |── FIN=1, seq=u ──────────────→|  FIN-WAIT-1
  |←── ACK=1, seq=v, ack=u+1 ────|  CLOSE-WAIT
FIN-WAIT-2                        (半关闭：A→B方向关)
  |←── FIN=1, ACK=1, seq=w, ack=u+1 ──| LAST-ACK
  |── ACK=1, seq=u+1, ack=w+1 ──→|
TIME-WAIT(等2MSL)                CLOSED
CLOSED
```

**3. 为什么不同**（2 分）：
- 三次握手：服务器在收到 SYN 后，将 SYN+ACK 合并为一个报文发送
- 四次挥手：双方都需要关闭各自的发送方向（全双工关闭）。A 发 FIN 关闭 A→B 方向后，B 可能还有数据要发给 A，所以 B 先发 ACK 确认 A 的 FIN，等自己的数据发完再发 FIN。因此 ACK 和 FIN 分开发送，共四步
- 等 2MSL 的原因：① 保证最后一个 ACK 能到达 B（B 超时会重传 FIN）；② 防止"已失效的连接请求报文段"出现在新连接中

</details>

### 3. RIP 与 OSPF 综合对比（6 分）

请从以下方面对比 RIP 和 OSPF：

| 对比项 | RIP | OSPF |
|--------|-----|------|
| 路由算法类型 | | |
| 交换的信息 | | |
| 交换的对象 | | |
| 最大跳数/规模 | | |
| 封装方式 | | |
| 收敛速度 | | |
| "坏消息传播慢" | | |

并简要说明：为什么说 OSPF 适用于大规模网络而 RIP 不适用？

<details>
<summary>答案</summary>

| 对比项 | RIP | OSPF |
|--------|-----|------|
| 路由算法类型 | **距离向量** | **链路状态** |
| 交换的信息 | **全部路由表** | 与邻居的**链路状态** |
| 交换的对象 | 仅**相邻**路由器 | **所有**路由器（洪泛法）|
| 最大跳数 | **15**（16=不可达）| **无限制** |
| 封装方式 | UDP（端口520）| 直接 IP 数据报（协议89）|
| 收敛速度 | 慢（坏消息传播慢）| **快** |
| 坏消息传播慢 | **有**（主要缺点）| **无** |

**OSPF 适用于大规模网络的原因**：
1. 没有 15 跳的限制
2. 交换的是链路状态而非完整路由表，通信量更小
3. 收敛速度快，拓扑变化能迅速传播
4. 支持区域划分，减少了网络通信量和维护的状态数量
5. 支持 CIDR、负载均衡、鉴别功能

### 4. 电子邮件系统（6 分）

请画出电子邮件系统的三个主要构件及其使用的协议，并说明：

1. 发件人发送邮件的完整流程
2. 收件人读取邮件的完整流程
3. 为什么发送和读取使用不同的协议？MIME 在系统中起什么作用？

<details>
<summary>答案</summary>

**三个主要构件**：

```
发件人UA ──SMTP──→ 发送方邮件服务器 ──SMTP──→ 接收方邮件服务器 ──POP3/IMAP──→ 收件人UA
           (推)                          (推)                          (拉)
```

**1. 发送流程**（2 分）：
- 发件人用 UA 撰写邮件 → UA 通过 SMTP（端口 25）将邮件"推"到发送方邮件服务器的邮件缓存
- 发送方邮件服务器定期扫描缓存，发现邮件后，通过 SMTP 与接收方邮件服务器建立 TCP 连接
- 经过 MAIL FROM → RCPT TO → DATA 命令序列发送邮件内容
- 发送完毕后发送 QUIT 释放连接
- **注意**：邮件在传输过程中不在中间服务器落地

**2. 读取流程**（1 分）：
- 收件人启动 UA，通过 POP3（端口 110）或 IMAP（端口 143）从接收方邮件服务器的用户邮箱中"拉"取邮件
- POP3：下载到本地，服务器可删除
- IMAP：联机操作，邮件保留在服务器

**3. 为什么分开 + MIME**（3 分）：
- 发送用 SMTP，读取用 POP3/IMAP，因为**操作语义不同**：
  - SMTP 是"推"——发送方主动将邮件推向接收方
  - POP3/IMAP 是"拉"——收件人主动从服务器拉取邮件
- **MIME 的作用**：SMTP 只能传 7 位 ASCII 文本。MIME 扩充了邮件内容格式，支持：
  - 非 ASCII 文本（如中文）
  - 二进制附件（图片、音频、视频等）
  - 多种内容类型（通过 Content-Type 标识）
- MIME 不替代 SMTP，而是在 SMTP 之上增加编码和类型描述

</details>

### 4. TCP 拥塞控制 + 序号确认综合（8 分）

主机 A 和 B 建立 TCP 连接。A 的初始序号为 0，B 的初始序号为 0。连接建立后，A 的 ssthresh = 16 MSS，cwnd = 1 MSS，MSS = 1000 字节。

以下按时间顺序列出 A→B 的所有发送事件和 B 的反馈：

1. A 发送数据：序号 0~2999（3 个报文段，每个 1000 字节）
2. A 收到 B 的确认：确认号 = 1000
3. A 发送数据：序号 3000~5999（3 个报文段，每个 1000 字节）
4. A 收到 B 的确认：确认号 = 2000
5. A 发送数据：序号 6000~7999（2 个报文段）
6. 序号 6000 的报文段丢失，序号 7000 的报文段到达 B
7. B 发送确认：确认号 = 6000
8. A 收到确认号 = 6000 的确认（这是第一个重复确认）

**(a) (2 分)** 在事件 2 后（A 收到确认号=1000），A 的 cwnd 是多少？处于什么阶段？

**(b) (3 分)** 在事件 8 后（A 收到确认号=6000，第一个重复确认），A 的 cwnd 和 ssthresh 是多少？假设在收到 3 个重复 ACK 之前又陆续收到了 B 对序号 7000~8999 的确认（累积确认号 = 6000），A 会立即重传哪个报文段？

**(c) (3 分)** 如果 A 没有采用快重传，而是等到超时才重传。假设超时发生后 A 重新开始慢开始。超时前 cwnd = 8 MSS。超时后第一个 RTT 内 A 发送了几个报文段？第三个 RTT 呢？ssthresh 的值是多少？

<details>
<summary>答案</summary>

**(a) 事件 2 后**（2 分）：

事件 1：A 发送 3 个报文段（序号 0,1000,2000），每个 1000 字节。cwnd 初始 = 1。

等等——题目说"事件 1 A 发送数据：序号 0~2999（3个报文段）"，但初始 cwnd=1，A 怎么一次发出 3 个报文段？

需要重新理解：TCP 虽然 cwnd=1，但 A 的发送窗口可能由 rwnd 决定。如果 rwnd 足够大，A 可能连续发送。

实际上，如果严格按 cwnd=1，A 只能发一个。但题目说 A 发了 3 个，说明可能 cwnd 已经增长或 rwnd 足够大。我们按题目描述来，忽略 cwnd 初始约束。

事件 2 后 A 收到确认号=1000 → 确认了序号 0~999。

在慢开始阶段：每收到一个新确认，cwnd += 1 MSS。
A 收到一个 ACK（确认了 1000 字节 = 1 MSS），cwnd = 1 + 1 = **2 MSS**。

A 处于**慢开始**阶段（cwnd=2 < ssthresh=16）。

**(b) 事件 8 后**（3 分）：

事件 4 后 A 收到确认号=2000 → cwnd = 4？等等，要仔细追踪。

实际上这题不需要逐步追 cwnd。事件 8 时，A 收到确认号=6000，但这是**第一个重复确认**（因为序号 6000 的报文段丢失了）。

此时 A 还没触发快重传（需要 3 个重复 ACK）。但题目问的是"在收到 3 个重复 ACK 之前"，陆续收到了 B 对序号 7000~8999 的累积确认=6000，也就是 B 持续发重复的 ACK=6000。

当 A 收到**第 3 个重复 ACK**（确认号都是 6000）时：
- A 知道序号 6000 丢失了
- 执行**快重传**：立即重传序号 **6000** 的报文段（1000 字节，序号 6000~6999）

此时 cwnd 和 ssthresh 的值取决于之前的状态。假设此时 cwnd = 8（在拥塞避免阶段）：
- ssthresh = cwnd/2 = 4
- cwnd = ssthresh = 4

**(c) 无快重传，等超时**（3 分）：

超时前 cwnd = 8 MSS，ssthresh 初始 = 16。

超时：ssthresh = max(cwnd/2, 2) = max(4, 2) = 4，cwnd = 1。

- **第一个 RTT**（超时后）：cwnd = 1 → 发送 **1 个报文段**（1 MSS = 1000 字节）
- **第二个 RTT**：cwnd = 2 → 发送 2 个报文段
- **第三个 RTT**：cwnd = 4 → 发送 **4 个报文段**（cwnd = ssthresh = 4，即将进入拥塞避免）

ssthresh = **4 MSS**。

</details>
