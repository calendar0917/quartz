## 1. CRC 计算（第3章核心考点）

要发送的数据为 **1011001**，生成多项式 $P(X) = X^4 + X^2 + X + 1$。

1. 求应添加在数据后面的余数（写出完整模 2 除法过程）
2. 发送方最终发送的数据是什么？
3. 若收到 **1011001_0011**，接收方能发现错误吗？请验证。

<details>
<summary>答案</summary>

**(1)** $P(X) = X^4 + X^2 + X + 1$ → 除数 **P = 10111**（5 位，n=4）

原始数据 M = 1011001，加 4 个 0 → **10110010000**

模 2 除法：

```
           1001100  ← 商
       _____________
10111 ) 10110010000
        10111
        -----
           01010  (前面补0补足)
           00000
           -----
            10100
            10111
            -----
             00110
             00000
             -----
              01100
              00000
              -----
               11000
               10111
               -----
                11110
                10111
                -----
                 10010
                 10111
                 -----
                  01010
                  00000
                  -----
                   10100
                   10111
                   -----
                    0011  ← 余数 R = 0011
```

**(2)** 发送数据 = M + R = **10110010011**

**(3)** 收到 10110010011，用除数 10111 除：
- 模 2 除法后余数 = 0 → **不能发现**错误（这个余数恰巧为 0？不，收到的恰好是正确数据）

如果收到的是 **10110010010**（末尾不同），那么：
- 模 2 除法余数 ≠ 0 → 能发现错误

> 任何 1 位出错都能检测到（只要出错后余数不为 0）。

</details>

## 2. IP 数据报分片（第4章核心考点）

一个 IP 数据报总长 **3820 字节**（固定首部 20 字节），标识为 **7777**。经过 MTU = **1420 字节**的网络。

写出每个分片的：总长度、标识、MF、片偏移。

<details>
<summary>答案</summary>

- 数据部分 = 3820 − 20 = **3800 字节**
- 每片最大数据部分 = 1420 − 20 = **1400 字节**（8 的倍数）
- 3800 = 1400 + 1400 + 1000 → 3 片

| 分片 | 总长度 | 数据长度 | 标识 | MF | 片偏移 |
|:--:|:--:|:--:|:--:|:--:|:--:|
| 1 | 1420 | 1400 | 7777 | 1 | 0 |
| 2 | 1420 | 1400 | 7777 | 1 | 175 |
| 3 | 1020 | 1000 | 7777 | 0 | 350 |

片偏移：
- 片 1：0 / 8 = **0**
- 片 2：1400 / 8 = **175**
- 片 3：(1400+1400) / 8 = 2800 / 8 = **350**

</details>

## 3. IP 首部检验和（第4章计算考点）

IP 首部前 10 行 16 位分组如下（检验和字段尚未计算，已置 0）：

```
0100 0101 0000 0000   (版本4, 首部长度5, 区分服务0)
0000 0000 0001 1100   (总长度28)
0000 0000 0000 0001   (标识1)
0000 0000 0000 0000   (标志+片偏移，全0)
0000 0100 0001 0001   (TTL=4, 协议=17)
0000 0000 0000 0000   (检验和字段，先置0)
0000 1010 0000 1100   (源地址 前16位)
0000 1110 0000 0101   (源地址 后16位)
0000 1100 0000 0110   (目的地址 前16位)
0000 0111 0000 1001   (目的地址 后16位)
```

按 16 位分组，计算检验和。用二进制反码求和，写出过程。

<details>
<summary>答案</summary>

反码求和（逐二进制加法，最高位进位加到最低位）：

```
  0100 0101 0000 0000
+ 0000 0000 0001 1100
─────────────────────
= 0100 0101 0001 1100

+ 0000 0000 0000 0001
─────────────────────
= 0100 0101 0001 1101

+ 0000 0000 0000 0000  (检验和字段，无变化)
─────────────────────
= 0100 0101 0001 1101

+ 0000 0100 0001 0001
─────────────────────
= 0100 1001 0010 1110

+ 0000 0000 0000 0000
─────────────────────
= 0100 1001 0010 1110

+ 0000 1010 0000 1100
─────────────────────
= 0101 0011 0011 1010

+ 0000 1110 0000 0101
─────────────────────
= 0110 0001 0011 1111

+ 0000 1100 0000 0110
─────────────────────
= 0110 1101 0100 0101

+ 0000 0111 0000 1001
─────────────────────
= 0111 0100 0100 1110
```

取**反码**得检验和：**1000 1011 1011 0001**

</details>

## 4. 子网划分（第4章核心考点）

某单位分配地址块 **172.16.0.0/22**。需要 5 个子网，需求如下：

| 子网 | 所需主机数 |
|:--:|:--:|
| A | 500 |
| B | 200 |
| C | 100 |
| D | 50 |
| E | 20 |

给出分配方案（每个子网的网络地址和前缀长度）。

<details>
<summary>答案</summary>

/22 的地址块共 2¹⁰ = 1024 个地址。

按主机数从大到小，计算所需主机位数（$2^n - 2 \geq \text{主机数}$）：

- A 需 500 → 2⁹−2=510≥500 → 9 位主机号 → 前缀 /23
- B 需 200 → 2⁸−2=254≥200 → 8 位 → /24
- C 需 100 → 2⁷−2=126≥100 → 7 位 → /25
- D 需 50 → 2⁶−2=62≥50 → 6 位 → /26
- E 需 20 → 2⁵−2=30≥20 → 5 位 → /27

分配方案（从大到小依次）：

| 子网 | 地址块 | 前缀 | 地址数 |
|:--:|--------|:--:|:--:|
| A | 172.16.0.0 | /23 | 512 |
| B | 172.16.2.0 | /24 | 256 |
| C | 172.16.3.0 | /25 | 128 |
| D | 172.16.3.128 | /26 | 64 |
| E | 172.16.3.192 | /27 | 32 |

> 验证：地址范围 172.16.0.0 ~ 172.16.3.223，在 /22 块内（0.0~3.255）。

</details>

## 5. 路由聚合（第4章考点）

将以下 8 个 /24 地址块进行最大可能的聚合：

- 192.168.16.0/24
- 192.168.17.0/24
- 192.168.18.0/24
- 192.168.19.0/24
- 192.168.20.0/24
- 192.168.21.0/24
- 192.168.22.0/24
- 192.168.23.0/24

<details>
<summary>答案</summary>

第三字节的二进制：

| 地址 | 第三字节 | 前 5 位 |
|------|:--:|:--:|
| 16 | 0001 0000 | 0001 0 |
| 17 | 0001 0001 | 0001 0 |
| 18 | 0001 0010 | 0001 0 |
| 19 | 0001 0011 | 0001 0 |
| 20 | 0001 0100 | 0001 0 |
| 21 | 0001 0101 | 0001 0 |
| 22 | 0001 0110 | 0001 0 |
| 23 | 0001 0111 | 0001 0 |

第三字节的前 5 位 = **00010**，相同。
加上前两字节 192.168 = 16 位。

共同前缀 = 16 + 5 = **21 位**。

聚合结果：**192.168.16.0/21**

> 掩码 255.255.248.0，包含 2³ = 8 个 C 类地址。

</details>

## 6. TCP 拥塞控制（第5章核心考大题）⭐⭐⭐

TCP 连接建立，**ssthresh = 16**（报文段）。初始 **cwnd = 1**。每次事件写 cwnd 和 ssthresh：

| 事件 | cwnd | ssthresh |
|------|:---:|:---:|
| 初始 | | 16 |
| 经过 2 个 RTT（无拥塞）| | |
| 经过 4 个 RTT（无拥塞）| | |
| 经过 5 个 RTT 时发生**超时** | | |
| 超时后经过 3 个 RTT（无拥塞）| | |
| 此时收到 **3 个重复 ACK** | | |

<details>
<summary>答案</summary>

| 事件 | cwnd | ssthresh | 解释 |
|------|:---:|:---:|------|
| 初始 | **1** | 16 | |
| 经过 2 个 RTT | **4** | 16 | 慢开始：1→2→4 |
| 经过 4 个 RTT | **16** | 16 | 慢开始：8→16。cwnd=ssthresh，可慢开始可拥塞避免 |
| 经过 5 个 RTT（超时）| **1** | **8** | 超时：ssthresh=cwnd/2=16/2=8, cwnd=1 |
| 超时后经过 3 个 RTT | **4** | 8 | 慢开始：1→2→4 |
| 收到 3 个重复 ACK | **4** | **4** | 快恢复：ssthresh=cwnd/2=4/2=2? 不！cwnd=4 时收到 3 个重复 ACK → ssthresh=2, cwnd=ssthresh=2 |

> 等等，仔细看：超时后经过 3 个 RTT → cwnd=4, ssthresh=8。此时 cwnd<ssthresh 还在慢开始。

> 收到 3 个重复 ACK：ssthresh = cwnd/2 = 4/2 = 2，cwnd = ssthresh = 2，然后进入拥塞避免。

| 事件 | cwnd | ssthresh |
|------|:---:|:---:|
| 初始 | **1** | 16 |
| 经过 2 个 RTT | **4** | 16 |
| 经过 4 个 RTT | **16** | 16 |
| 经过 5 个 RTT（超时）| **1** | **8** |
| 超时后经过 3 个 RTT | **4** | 8 |
| 收到 3 个重复 ACK | **2** | **2** |

</details>

## 7. TCP 序号与确认号（第5章计算考点）

主机 A 向 B 发送**三个 TCP 报文段**：序号分别为 **200**、**500**、**900**。B 正确收到所有报文段，发回的确认号依次为 500、900、1100。

1. 三个报文段各携带多少字节数据？
2. 若第二个报文段（序号 500）丢失，B 收到第三个报文段（序号 900）后发的确认号是什么？

<details>
<summary>答案</summary>

**(1)** 各报文段数据量：
- 第一个（序号 200→500）：500 − 200 = **300 字节**
- 第二个（序号 500→900）：900 − 500 = **400 字节**
- 第三个（序号 900→1100）：1100 − 900 = **200 字节**

**(2)** 第二个报文段丢失，B 收到序号 900 的报文段：
- B 发现不是按序到达，缺少序号 500~899 的数据
- B 期望收到的是序号 **500**
- 所以确认号 = **500**

</details>

## 8. CSMA/CD 最短帧长（第3章计算考点）

CSMA/CD 网络数据率 **10 Gbit/s**，网络最大端到端距离 **2.5 km**，信号传播速率 **200000 km/s**。求能够使用此协议的**最短帧长**（以字节为单位）。

<details>
<summary>答案</summary>

单程传播时延 τ = 2.5 km ÷ 200000 km/s = **1.25 × 10⁻⁵ s** = 12.5 μs

争用期 = 2τ = 2 × 12.5 = **25 μs**

最短帧长 = 数据率 × 争用期 = 10 × 10⁹ × 25 × 10⁻⁶
= 10¹⁰ × 2.5 × 10⁻⁵
= **250000 bit**

= 250000 ÷ 8 = **31250 字节**

</details>

## 9. RIP 路由更新（第4章考点）

路由器 R5 当前路由表：

| 目的 | 距离 | 下一跳 |
|:--:|:--:|:--:|
| N1 | 2 | R2 |
| N2 | 4 | R3 |
| N3 | 1 | 直接 |
| N5 | 6 | R4 |
| N6 | 8 | R4 |
| N7 | 10 | R4 |

现收到 **R4** 发来的路由信息：

| 目的 | 距离 |
|:--:|:--:|
| N2 | 3 |
| N4 | 2 |
| N5 | 3 |
| N6 | 9 |
| N7 | 5 |
| N8 | 6 |

求 R5 更新后的路由表。

<details>
<summary>答案</summary>

**第一步**：收到的报文全 +1，下一跳全改为 R4：

| 目的 | 新距离 | 新下一跳 |
|:--:|:--:|:--:|
| N2 | **4** | R4 |
| N4 | **3** | R4 |
| N5 | **4** | R4 |
| N6 | **10** | R4 |
| N7 | **6** | R4 |
| N8 | **7** | R4 |

**第二步**：逐项与 R5 原路由表比较：

- N1：未收到 → 保留 (N1, 2, R2)
- N2：新距离 4 = 原距离 4，但下一跳不同(R3 vs R4) → **不更新**，保留原 (N2, 4, R3)
- N3：未收到 → 保留 (N3, 1, 直接)
- N4：原表没有 → **加入** (N4, 3, R4)
- N5：新距离 4 < 原距离 6 → **更新** (N5, 4, R4)
- N6：新距离 10 > 原距离 8 → **不更新**，保留 (N6, 8, R4)
- N7：新距离 6 < 原距离 10 → **更新** (N7, 6, R4)
- N8：原表没有 → **加入** (N8, 7, R4)

**更新后路由表**：

| 目的 | 距离 | 下一跳 |
|:--:|:--:|:--:|
| N1 | 2 | R2 |
| N2 | 4 | R3 |
| N3 | 1 | 直接 |
| N4 | 3 | R4 |
| N5 | 4 | R4 |
| N6 | 8 | R4 |
| N7 | 6 | R4 |
| N8 | 7 | R4 |

</details>

## 10. 最长前缀匹配（第4章考点）

路由器转发表：

| 前缀 | 下一跳 |
|------|:--:|
| 10.0.0.0/8 | R1 |
| 10.1.0.0/16 | R2 |
| 10.1.2.0/24 | R3 |
| 10.1.2.128/25 | R4 |
| 0.0.0.0/0 | R5 |

分别求目的地址的下一跳：

1. **10.1.2.200**
2. **10.1.3.50**

<details>
<summary>答案</summary>

**(1) 10.1.2.200**：

| 前缀 | 掩码 | AND 结果 | 匹配？ |
|------|------|---------|:--:|
| 10.0.0.0/8 | 255.0.0.0 | 10.0.0.0 | ✓ |
| 10.1.0.0/16 | 255.255.0.0 | 10.1.0.0 | ✓ |
| 10.1.2.0/24 | 255.255.255.0 | 10.1.2.0 | ✓ |
| 10.1.2.128/25 | 255.255.255.128 | 10.1.2.128 | ✓ |

四条都匹配 → 选**最长前缀** /25 → 下一跳 **R4**

**(2) 10.1.3.50**：

| 前缀 | AND 结果 | 匹配？ |
|------|---------|:--:|
| 10.0.0.0/8 | 10.0.0.0 | ✓ |
| 10.1.0.0/16 | 10.1.0.0 | ✓ |
| 10.1.2.0/24 | 10.1.2.0 | ✗ (3≠2) |
| 10.1.2.128/25 | 10.1.2.0 | ✗ |

前两条匹配 → 选最长前缀 /16 → 下一跳 **R2**

</details>
