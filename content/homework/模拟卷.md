A. 5 ms
B. 838.9 s
C. 843.9 s
D. 1.258 s

<details>
<summary>答案</summary>

**B**

同一个 AS 内只能选用**一种**路由协议。因为 OSPF 是全局链路状态算法，RIP 是距离向量算法，两者不能混合使用。

### 1. CSMA/CD 协议（6 分）

简述 CSMA/CD 协议的工作流程，并说明**争用期**的概念以及为什么需要**截断二进制指数退避算法**。（6 分）

<details>
<summary>答案</summary>

**工作流程**（3 分）：

1. 准备发送 → 检测信道（载波监听）
2. 若信道忙 → 持续监听；若信道空闲（96 bit 时间内）→ 开始发送，同时进行碰撞检测
3. 未检测到碰撞 → 继续发送直到完毕，发送成功
4. 检测到碰撞 → 立即停止发送，发送人为干扰信号强化碰撞 → 等待随机时间后重新尝试

**争用期**（1.5 分）：
争用期 = 端到端往返时延 2τ，又称碰撞窗口。只有在争用期内才能检测到碰撞。10 Mbit/s 以太网中争用期为 51.2 μs。

**截断二进制指数退避**（1.5 分）：
碰撞后各站随机退避一段时间再重发，退避时间 = r × 2τ。r 从 [0, 2ᵏ−1] 中随机选，k=min(重传次数,10)。目的是让重传推迟的平均时间随碰撞次数增加，降低再次碰撞的概率，保证系统稳定。

</details>

### 2. ARP 协议（6 分）

请说明 ARP 协议的作用和工作流程。分别说明：发送方和接收方在**同一局域网**内，以及发送方和接收方在**不同局域网**时，ARP 的工作过程有何不同？（6 分）

<details>
<summary>答案</summary>

**作用**（1 分）：从已知 IP 地址解析出对应的 MAC 地址。

**同一局域网内**（2.5 分）：

1. 发送方查 ARP 高速缓存 → 若有直接使用
2. 若无 → 本局域网**广播**发送 ARP 请求分组（含发送方 IP+MAC、目标方 IP，目标 MAC 填 0）
3. 目的主机收到 → **单播**回复 ARP 响应分组（含自己的 MAC 地址）
4. 发送方将 IP→MAC 映射写入 ARP 缓存 → 封装 MAC 帧 → 发送数据

**不同局域网**（2.5 分）：

发送方不直接找目的主机，而是用 ARP 找到**本网络上的路由器（默认网关）**的 MAC 地址，将 IP 数据报发给路由器。

路由器接收后，在自己的 ARP 缓存中查找下一跳（可能是目的主机或下一个路由器）的 MAC 地址，逐跳转发，直到到达目的主机。

**关键区别**：同一局域网内 ARP 解析对象是目的主机；不同局域网内解析对象是路由器。

</details>

### 3. TCP 拥塞控制（6 分）

请分别说明 TCP 拥塞控制中的以下四个算法的作用和执行时机：慢开始、拥塞避免、快重传、快恢复。并说明"乘法减小"和"加法增大"的含义及使用场景。（6 分）

<details>
<summary>答案</summary>

**慢开始**（1.5 分）：连接建立或超时后使用。cwnd 初始 = 1，每收到新确认 cwnd+1 → 每 RTT 翻倍（指数增长）。目的：探测网络负载能力。

**拥塞避免**（1.5 分）：当 cwnd ≥ ssthresh 时启用。每 RTT cwnd+1（线性增长）。目的：让窗口缓慢增长，避免突发拥塞。

**快重传**（1 分）：发送方连续收到 3 个重复 ACK 时，不等超时就立即重传丢失的报文段。可提高吞吐量约 20%。

**快恢复**（1 分）：收到 3 个重复 ACK 后：ssthresh = cwnd/2，cwnd = ssthresh，直接进入拥塞避免（不执行慢开始）。认为网络未拥塞，快速恢复到较高速率。

**乘法减小 MD**（0.5 分）：超时时执行。ssthresh = cwnd/2，cwnd = 1。迅速减少注入网络的分组数。

**加法增大 AI**（0.5 分）：拥塞避免阶段执行。每 RTT cwnd+1。让窗口缓慢线性增大。

AIMD（加法增大 + 乘法减小）是 TCP 拥塞控制的核心思想。

</details>

### 4. DNS 域名解析（6 分）

请画出 DNS 域名解析的**迭代查询**过程（以 www.example.com 为例），说明每一步涉及哪个域名服务器。并说明**递归查询和迭代查询**的区别，以及 DNS 高速缓存的作用。（6 分）

<details>
<summary>答案</summary>

**迭代查询过程**（3 分）：

```
主机 m.xyz.com 查询 www.example.com 的 IP：

① 主机 → 本地域名服务器    "请解析 www.example.com"（递归请求）
② 本地 → 根域名服务器      "www.example.com？"
   根回复："去问 .com 顶级域名服务器"
③ 本地 → .com 顶级域名服务器
   顶级回复："去问 example.com 权限域名服务器"
④ 本地 → example.com 权限域名服务器
   权限回复："IP 是 a.b.c.d"
⑤ 本地 → 主机              "IP 是 a.b.c.d"
```

**递归 vs 迭代**（1.5 分）：
- 递归查询：被查询的服务器**代为完成全部**后续查询，返回最终结果（或报错）
- 迭代查询：被查询的服务器**只返回下一步**应该问哪个服务器，由请求方继续查询
- 主机→本地：一般是递归；本地→根/顶级/权限：一般是迭代

**高速缓存**（1.5 分）：
存放最近查询过的域名→IP 映射，减少 DNS 查询报文数量，大大减轻根域名服务器负荷。每个记录有计时器，过期删除，平衡准确性和网络开销。

</details>

### 1. CRC 循环冗余校验（8 分）

要发送的数据为 **1010001101**。采用 CRC 的生成多项式为 $P(X) = X^5 + X^4 + X^2 + 1$。

**(2)** 发送数据 = M + R = **1010001101**01110

- 收到 1010001101**0**0110（假设原为 101000110101110）

| 客户 A | 4000 个地址 |

| 客户 C | 500 个地址 |

1. **（4 分）** 按从大到小的顺序，为每个客户分配一个合适的 CIDR 地址块（写出网络地址和前缀长度）。
2. **（4 分）** 该 ISP 对外只需要向外发布一个路由聚合后的前缀即可。这个聚合后的前缀是什么？若客户 A 内部又划分为 8 个一样大的子网，每个子网的网络前缀是多少？

<details>
<summary>答案</summary>

**（1）分配方案**（4 分）：

/18 地址块共 2¹⁴ = 16384 个地址。按主机数从大到小：

- A 需 ≥4000 → 2¹²−2=4094≥4000 → 12 位主机号 → 前缀 /20
- B 需 ≥1000 → 2¹⁰−2=1022≥1000 → 10 位主机号 → 前缀 /22
- C 需 ≥500 → 2⁹−2=510≥500 → 9 位主机号 → 前缀 /23

| 客户 | 地址块 | 前缀 | 地址数 |
|:--:|--------|:--:|:--:|
| A | 202.112.64.0 | /20 | 4096 |
| B | 202.112.80.0 | /22 | 1024 |
| C | 202.112.84.0 | /23 | 512 |

验证：
- A：64.0/20 → 202.112.64.0 ~ 202.112.79.255 ✓
- B：80.0/22 → 202.112.80.0 ~ 202.112.83.255 ✓
- C：84.0/23 → 202.112.84.0 ~ 202.112.85.255 ✓

均在 202.112.64.0/18 内（64.0 ~ 127.255）。

**（2）路由聚合**（4 分）：

ISP 对外发布：
三个子块都在 202.112.64.0/18 内 → **202.112.64.0/18**

客户 A 内部分 8 个等大子网：
A 的地址块 202.112.64.0/20。8 = 2³，需 3 位子网号。
子网前缀 = 20 + 3 = **/23**（每个子网 2⁹ = 512 个地址）。

### 3. IP 数据报分片（8 分）

一个 IP 数据报总长 **4500 字节**，首部固定长度 20 字节，**标识 = 9999**。现经过一个网络，该网络的 MTU = **1200 字节**。

1. **（3 分）** 该数据报应当被划分为几个分片？写出每个分片的**总长度、标识、MF、片偏移**。
2. **（2 分）** 若该数据报首部的 DF 标志位被设为 1，会发生什么？
3. **（3 分）** 若第一个分片在传输中丢失，目的主机能否正确重组该数据报？为什么？ICMP 会发送什么报文？

<details>
<summary>答案</summary>

**(1) 分片计算**（3 分）：

- 数据部分 = 4500 − 20 = **4480 字节**
- 每片最大数据部分 = 1200 − 20 = **1180 字节**
- 1180 需是 8 的倍数：1180 ÷ 8 = 147.5 → 向下取整 = 147, 即 1176 字节
- 4480 = 1176 + 1176 + 1176 + 952

| 分片 | 总长度 | 标识 | MF | 片偏移 |
|:--:|:--:|:--:|:--:|:--:|
| 1 | 1196 | 9999 | 1 | 0 |
| 2 | 1196 | 9999 | 1 | 147 |
| 3 | 1196 | 9999 | 1 | 294 |
| 4 | 972 | 9999 | 0 | 441 |

片偏移：
- 片 1：0 / 8 = **0**
- 片 2：1176 / 8 = **147**
- 片 3：(1176×2) / 8 = 2352 / 8 = **294**
- 片 4：(1176×3) / 8 = 3528 / 8 = **441**

**(2) DF = 1**（2 分）：

DF 标志位 = 1 表示**不允许分片**。由于数据报总长（4500）超过 MTU（1200），路由器必须丢弃该数据报，并向源站发送 **ICMP 终点不可达**（类型 3，代码 4：需要分片但 DF 置位）。

**(3) 第一个分片丢失**（3 分）：

**不能正确重组。** IP 分片重组需要所有分片都到达。第一个分片丢失意味着：
- 缺少数据的最前面部分（片偏移 0~1176 字节）
- 无法还原为完整的原始数据报

目的主机会等待一段时间，超时后丢弃所有已收到的分片。可能会发送 **ICMP 时间超过**差错报告报文。

</details>

### 4. TCP 拥塞控制窗口计算（8 分）

假设 TCP 连接建立后，**ssthresh 初始值 = 8 MSS**，**cwnd 初始值 = 1 MSS**。此后的传输过程中，发生了以下事件序列：

| RTT | 事件 |
|:---:|------|
| 1~3 | 正常传输，无拥塞 |
| 4 | 正常传输，无拥塞 |
| 5 | 正常传输，无拥塞 |
| 6 | **发生超时** |
| 7~8 | 超时后恢复正常 |
| 9 | 收到**3 个重复 ACK** |
| 10 | 正常传输，无拥塞 |

1. **（4 分）** 填写表格，写出每个 RTT 开始时（发送前）的 **cwnd** 和 **ssthresh** 值。

| RTT | cwnd | ssthresh | 当前阶段 |
|:---:|:---:|:---:|------|
| 1 | | 8 | |
| 2 | | | |
| 3 | | | |
| 4 | | | |
| 5 | | | |
| 6 | | | |
| 7 | | | |
| 8 | | | |
| 9 | | | |
| 10 | | | |

2. **（2 分）** 在第几个 RTT 中，TCP 从慢开始切换到拥塞避免？为什么？
3. **（2 分）** 第 9 RTT 收到 3 个重复 ACK 后，cwdn 和 ssthresh 的值是如何得出的？此时 TCP 进入什么阶段？

<details>
<summary>答案</summary>

**(1) 完整表格**（4 分）：

| RTT | cwnd | ssthresh | 当前阶段 |
|:---:|:---:|:---:|------|
| 1 | **1** | 8 | 慢开始 |
| 2 | **2** | 8 | 慢开始 |
| 3 | **4** | 8 | 慢开始 |
| 4 | **8** | 8 | 慢开始/拥塞避免（cwnd=ssthresh）|
| 5 | **9** | 8 | 拥塞避免 |
| 6 | **1** | **5** | 超时→慢开始 |
| 7 | **2** | 5 | 慢开始 |
| 8 | **4** | 5 | 慢开始 |
| 9 | **2** | **2** | 3个重复ACK→快恢复→拥塞避免 |
| 10 | **3** | 2 | 拥塞避免 |

详细推导：

- RTT=1：cwnd=1, ssthresh=8，慢开始
- RTT=2：cwnd=2（翻倍），慢开始
- RTT=3：cwnd=4（翻倍），慢开始
- RTT=4：cwnd=8（翻倍），cwnd=ssthresh=8，可慢开始可拥塞避免
- RTT=5：cwnd=9（线性+1），拥塞避免

- RTT=6：**超时**
  ssthresh = max(cwnd/2, 2) = max(9/2, 2) = max(4.5→4?, 不对。cwnd=9，一半=4.5，但 ssthresh 是整数。取 4)
  实际上 cwnd 是 MSS 的整数倍，这里 cwnd=9（RTT5 发完后），超时→ ssthresh=4（向下取整），cwnd=1

- RTT=7：cwnd=2（慢开始翻倍），ssthresh=4
- RTT=8：cwnd=4（慢开始翻倍），cwnd=ssthresh=4

- RTT=9：收到 **3 个重复 ACK**
  当前 cwnd=4 → ssthresh=cwnd/2=2，cwnd=ssthresh=2
  进入拥塞避免

- RTT=10：cwnd=3（线性+1），拥塞避免

**(2)**（2 分）：

在 **RTT=4** 时，cwnd = ssthresh = 8，此时既可以在慢开始也可以在拥塞避免。严格来说，从 RTT=5 开始 cwnd 线性增长，所以是 RTT=5 明确进入拥塞避免。

**(3)**（2 分）：

收到 3 个重复 ACK（非超时），执行**快恢复**：
- ssthresh = cwnd / 2 = 4 / 2 = **2**（乘法减小）
- cwnd = ssthresh = **2**
- 进入**拥塞避免**阶段（加法增大）

</details>
