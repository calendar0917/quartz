# 第1章 操作系统概述 —— 从裸机到OS

---

## 1.1 如果没有操作系统，计算机怎么用？

想象你面前有一台**没有安装操作系统的计算机**。你想运行一个程序，怎么办？

**串行处理时代**的做法：
1. 你走到登记表前，写下"我要用计算机2小时"
2. 轮到你了，你把程序卡片塞进读卡机
3. 手动加载编译器、源程序、链接库...
4. 程序跑完了，你拿走打印结果

问题是：**90%的时间花在了人的操作上**，CPU大部分时间在等你。

这就引出了第一个需求：**能不能让计算机自动处理一批作业？**

---

## 1.2 操作系统的演进：每一步都在解决一个问题

```
串行处理 ──→ 简单批处理 ──→ 多道批处理 ──→ 分时系统 ──→ 实时系统
  无OS       Monitor        并发           交互        时限
```

### 第一阶段 → 第二阶段：引入Monitor

**解决了什么**：作业自动衔接，不再需要人在两作业之间手动切换。

**带来的新能力**：
- **内存保护**：不能让用户程序破坏Monitor
- **定时器**：防止一个作业独占机器
- **特权指令**：I/O等危险操作只能由Monitor执行
- **两种运行模式**：用户模式 + 内核模式

**新问题**：CPU经常空闲等I/O → 利用率低（因为I/O设备比CPU慢几个数量级）

### 第二阶段 → 第三阶段：多道程序

**核心思想**：内存里同时放多个作业。当作业A等I/O时，CPU切去执行作业B。

这就是**并发**的起源。多道批处理系统的特征：多道性、调度性、无序性、**无交互能力**。

**新问题**：用户无法和程序交互——你提交一批作业，可能几小时后才知道结果（说不定中间有个逗号写错全崩了）。

### 第三阶段 → 第四阶段：分时系统

**核心思想**：多个用户通过终端同时用一台机器，CPU快速轮流执行每个用户的程序（**时间片**）。

差别在哪里？批处理看的是**吞吐量**（每小时完成多少作业），分时看的是**响应时间**（敲回车后多快能出结果）。

| | 批处理 | 分时 |
|--|--------|------|
| 目标 | 处理器利用率最大化 | 响应时间最小化 |
| 指令来源 | 作业控制语言（无交互） | 终端键盘（实时交互） |
| 典型用户 | 计算中心 | 个人用户 |

### 第四阶段 → 第五阶段：实时系统

**核心思想**：必须在**规定时间**内完成对事件的响应。

- **硬实时**：错过了截止时间 = 灾难（火箭控制、核电站）
- **软实时**：越快越好，偶尔错过也可接受（视频播放、在线交易）

**关键区别**：实时系统的正确性不仅仅取决于计算结果，**还取决于产生结果的时间**。

## 1.3 操作系统到底做什么？

一句话：**OS = 资源管理者 + 服务提供者 + 硬件抽象层**

### 四大管理功能

**1. 处理机管理**（核心）
- 以**进程**为基本单位
- 包括：进程控制、进程同步、进程通信、调度
- 教科书原话："对处理机的管理可归结为对进程的管理"

**2. 存储器管理**
- 内存分配 → 每个作业"各得其所"
- 内存保护 → 互不干扰
- 地址映射 → 逻辑地址转物理地址
- 内存扩充 → 用虚拟技术让"小内存跑大程序"

**3. 设备管理**
- 缓冲管理 → 缓解CPU-I/O速度差
- 设备分配 → 谁用哪个设备
- 设备处理（驱动程序）→ 实际操控硬件

**4. 文件管理**
- 文件存储空间管理 → 磁盘上怎么放
- 目录管理 → 按名存取
- 文件读写和保护 → 安全+方便

### 四大基本特征（考试必考）

| 特征 | 本质 | 一句话理解 |
|------|------|-----------|
| **并发** | 宏观同时，微观交替 | 单核电脑上你听歌+写文档，感觉是同时在干，其实是快速切换 |
| **共享** | 资源被多个并发进程共用 | 大家都用同一台打印机 → 需要排队（互斥共享）；都读同一个文件 → 可以一起（同时共享） |
| **虚拟** | 一个物理实体变多个逻辑对应物 | 内存明明只有8GB，程序以为自己独占4GB地址空间 → 虚拟内存 |
| **异步** | 执行过程走走停停 | 程序运行时间不固定：取决于调度、I/O、其他进程的行为 |

**为什么并发是最基本的？** 因为共享、虚拟、异步都是以并发为前提的。没有多道程序并发执行，就不需要资源共享、不需要虚拟化、也没有执行的不确定性。

### 操作系统安全需求

四个维度：可用性（系统不中断）、保密性（未授权不能读）、数据完整性（未授权不能改）、可靠性（身份认证正确）。

这四点对应了：
- **可用性** → 中断处理、系统稳定性
- **保密性** → 内存保护、文件权限
- **完整性** → 互斥/同步、文件锁
- **可靠性** → 用户登录、加密通信

## 1.4 并发 vs 并行：一个永恒的混淆点

这是考试中最容易搞错的概念。记一张表就够了：

| | 并发(Concurrency) | 并行(Parallelism) |
|--|-------------------|-------------------|
| 时间 | 同一**时间间隔** | 同一**时刻** |
| 硬件 | 单处理器即可 | 必须多处理器/多核 |
| 例子 | 一个人交替打电话和发邮件 | 两个人分别打电话和发邮件 |
| 进程/程序 | 只有**动态**的进程才能并发 | 只有多CPU时进程才能并行 |

**程序是静态的，无法并发。进程是动态的，可以并发执行。**

## 1.5 操作系统体系结构：代码怎么组织？

OS是一个大型软件工程产物，它的代码结构经历了几代演变：

### 无结构（整体式）

> 就是一堆子程序互相调用，没有模块划分。

像早期UNIX内核：所有功能混在一起。跑起来能跑，但想改一个地方？不知道会影响哪里。

### 模块化结构

> 按功能划分模块，模块间通过接口交互。

评价标准：**高内聚、低耦合**。
- 内聚：模块内部联系的紧密程度
- 耦合：模块之间的相互依赖程度

### 分层结构

> 每一层只能调用直接下层，单向依赖。

有点像网络协议栈。优点：每层职责清晰、易验证正确性。缺点：层层传递 → 效率降低。

**名言**：_"Any problem in computer science can be solved by another layer of indirection."_

### 微内核结构

> 内核只保留最基础的功能（进程管理、低级内存管理、中断处理），其他服务作为**用户态进程**运行。

通信方式：**客户进程 → 内核 → 服务器进程**，通过消息传递。

**优缺点对比**：

| | 整体式/模块化 | 微内核 |
|--|-------------|--------|
| 效率 | 高（直接函数调用） | 低（消息传递+模式切换） |
| 可扩展性 | 差 | 好（加一个服务器即可） |
| 可靠性 | 差（一个模块崩了可能全崩） | 好（服务进程隔离） |
| 可移植性 | 差 | 好 |

**华为鸿蒙**就是基于微内核架构——面向全场景、分布式，微内核天然适合移植到不同硬件平台。

## 1.6 系统调用：用户程序如何请求OS服务？

这是贯穿全课的基础机制。

一个运行在**用户态**的程序不可以直接操作硬件（内存保护、特权指令限制）。那它怎么读文件、申请内存？

**答案：通过系统调用——主动触发一次从用户态到内核态的切换。**

### 完整流程（考试常考简答题）

```
① 用户进程准备好参数
② 执行陷入指令（trap / 访管指令）→ 这是"敲门"
③ CPU保存当前现场（PC、寄存器等）
④ CPU切换到内核态
⑤ 跳转到对应的系统调用处理程序
⑥ 执行具体操作（如分配内存、读磁盘）
⑦ 如果资源不可用→进程进入阻塞态，调度其他进程
⑧ 资源可用后→进程就绪→获得CPU→继续执行
⑨ 系统调用完成，恢复现场，返回用户态
```

### 一个关键考点

**问题**：进程调度程序、时钟中断处理程序、命令解释程序分别在哪种模式下执行？

| 程序 | 模式 | 原因 |
|------|------|------|
| 进程调度程序 | **内核模式** | 调度是OS核心功能，涉及进程切换，必须在内核态 |
| 时钟中断处理 | **内核模式** | 中断发生时CPU自动切换到内核态 |
| 命令解释程序(shell) | **用户模式** | shell是用户程序，通过系统调用请求OS服务 |

**理解方法**：凡是**中断、异常、系统调用**发生时，CPU一定在内核模式。这些是进入内核态的三种"门"。

## 1.7 几个常考的"前导概念"

### 前趋图

有向无循环图(DAG)。节点表示程序段，有向边表示前趋关系。

```
    P1 ──→ P2 ──→ P4 ──→ P6
      \             ↗
       → P3 → P5 ──┘
```

P1必须最先执行，P6最后执行。**这是后面同步和PV操作的基础——PV操作本质上就是在编码这种"谁先谁后"的约束。**

### 临界资源与临界区

- **临界资源**：一次只能被一个进程使用的资源（打印机、共享变量）
- **临界区**：进程中访问临界资源的代码段

这两个概念在概述中提一次，在后面同步章节会详细展开。这里先记住：**多个进程并发执行引发了对临界区的需求。**

## 本章关键理解题

**1. 为什么有了多道批处理系统还要分时系统？**

因为多道批处理没有交互能力。用户提交作业 → 等几小时 → 拿到结果 → 发现拼写错误 → 再提交。这种体验无法接受。分时系统让每个用户都有"自己独占计算机"的感觉。

**2. 并发性为什么是OS最基本的特征？**

因为并发是所有其他特征的前提：
- 有了并发 → 资源共享才有意义
- 有了并发 → 才需要虚拟技术（多个进程同时以为自己独占资源）
- 有了并发 → 程序执行才变得不可预测（异步性）

**3. 微内核的效率为什么比整体式内核低？**

每次用户进程请求服务需要两次模式切换（用户→内核→用户）和消息传递，而整体式内核只需要一次函数调用。

**4. 覆盖技术和交换技术的区别？**

- **覆盖**：同一个进程内的模块复用内存空间，由程序员自己设计覆盖结构
- **交换**：不同进程之间换入换出内存，由OS自动管理

覆盖是"自己内部腾地方"，交换是"把别人踢出去给其他人腾地方"。
