# 第3章 虚拟内存管理 —— 小内存跑大程序

---

## 6.0 核心问题

物理内存只有4GB，但我想跑一个需要8GB地址空间的程序。怎么办？

**答案**：不需要把整个程序都放进内存。根据**局部性原理**，程序在任何短时间内只会访问一小部分代码和数据——把这部分放在内存里就够了，其余留在磁盘上。需要的时候再调进来。

这就是**虚拟内存**。

---

## 6.1 局部性原理——虚拟内存成立的根基

### 为什么程序不会随机乱跳？

- **时间局部性**：刚访问过的指令/数据很快会再被访问。原因：循环、栈、热点变量。
- **空间局部性**：访问了地址X，X附近的地址很可能也会被访问。原因：顺序执行、数组遍历。

如果程序的访问完全随机，虚拟内存就会变成灾难——每次访问都缺页，全部时间花在换页上。

---

## 6.2 请求分页的工作机制

在基本分页基础上，加两个能力：

1. **请求调入**：页面不在内存时，产生缺页中断，OS从磁盘调入
2. **页面置换**：内存满了时，选一个页面换出到磁盘

### 页表新增字段

| 字段 | 作用 | 与基本分页的区别 |
|------|------|-----------------|
| 状态位P | 该页是否在内存中 | 基本分页假设所有页都在 |
| 访问位A | 最近被访问过吗 | 供置换算法使用 |
| 修改位M | 被修改过吗 | 换出时是否需要写回磁盘 |
| 外存地址 | 该页在磁盘上的位置 | 基本分页不需要 |

### 缺页中断的完整流程

```
CPU访问逻辑地址 → 查页表 → P=0（不在内存）→ 产生缺页中断
                                                    ↓
                              ┌───────────── 有空闲页框？
                              │                     ↓ 否
                              │ 是              选择一个页面淘汰
                              ↓                     ↓
                       从磁盘调入该页          该页被修改过？
                              ↓                  是 ↓ 否
                       更新页表和TLB         写回磁盘  直接覆盖
                              ↓                     ↓
                       重新执行那条指令   ←──────────┘
```

**两个特殊性**：
- 缺页中断在指令**执行期间**产生（普通中断在指令执行完后）
- 一条指令可能触发**多次**缺页（如指令在第1页，操作数在第5页）

## 6.3 页面置换算法——本章核心

**问题**：内存满了，新页面要进来，踢谁出去？

不同选择 = 不同缺页率 = 不同性能。下面**用同一个例子逐步推导每种算法**。

### 统一例题

页面走向（引用串）：**7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2**（共13次访问）

分配**3个页框**，初始为空。

---

### OPT（最优置换）——理论标杆

**规则**：淘汰**将来最长时间不被访问**的页面。

这需要预知未来，所以不可能实现——但它是衡量其他算法好坏的标尺。

```
访问: 7  0  1  2  0  3  0  4  2  3  0  3  2
─────────────────────────────────────────────
帧1:  7  7  7  2  2  2  2  2  2  2  2  2  2
帧2:     0  0  0  0  0  0  4  4  4  0  0  0
帧3:        1  1  1  3  3  3  3  3  3  3  3
缺页: ×  ×  ×  ×     ×     ×        ×
```

推导过程（关键决策点）：
- t=3(访问2)：帧中有7,0,1。未来：7在t=10不再出现,0在t=4出现,1在t=?不再出现。淘汰7（最久不用或不再用的优先淘汰，7和1都不再出现，随意选一个，通常选最早进来的→淘汰7）。实际上此例中1也不会再出现，选谁都可以，但课件中淘汰的是7。替换为2。
- t=5(访问3)：帧中有2,0,1。未来：2在t=8,0在t=6,1不再出现→淘汰1
- t=7(访问4)：帧中有2,0,3。未来：2在t=8,0在t=10,3在t=9→淘汰0（最远在t=10）
- t=10(访问0)：帧中有2,4,3。未来：2在t=12,4不再出现,3在t=11→淘汰4

**缺页次数：9次**（包括前3次冷启动）

---

### FIFO（先进先出）

**规则**：谁最早进来谁先出去。像队列一样。

```
访问: 7  0  1  2  0  3  0  4  2  3  0  3  2
─────────────────────────────────────────────
帧1:  7  7  7  2  2  2  2  4  4  4  0  0  0
帧2:     0  0  0  0  3  3  3  2  2  2  2  2
帧3:        1  1  1  1  0  0  0  3  3  3  3
缺页: ×  ×  ×  ×     ×  ×  ×  ×  ×  ×
```

推导过程：
- t=3(访问2)：帧中7,0,1。最早进来的是7→淘汰7
- t=4(访问0)：0在帧中→命中，不换
- t=5(访问3)：最早的是0→淘汰0
- t=6(访问0)：0不在帧中，最早的是1→淘汰1，装入0
- t=7(访问4)：最早的是2→淘汰2
- ...以此类推

**缺页次数：10次**

#### Belady异常

FIFO的一个反直觉现象：**页框数增加时，缺页次数可能反而增加！**

经典例子：页面走向 1,2,3,4,1,2,5,1,2,3,4,5
- 3个页框：缺页**9**次
- 4个页框：缺页**10**次

**只有FIFO会出现Belady异常。** LRU、OPT都不会。这是FIFO的重要缺陷。

---

### LRU（最近最久未使用）

**规则**：淘汰**过去最长时间未被访问**的页面。

直觉：用过去预测未来——最久没用的，将来大概率也不会用。

```
访问: 7  0  1  2  0  3  0  4  2  3  0  3  2
─────────────────────────────────────────────
帧1:  7  7  7  2  2  2  2  4  4  4  0  0  0
帧2:     0  0  0  0  0  0  0  2  2  2  2  2
帧3:        1  1  1  3  3  3  3  3  3  3  3
缺页: ×  ×  ×  ×     ×     ×  ×     ×
```

推导（关键点）：
- t=3(访问2)：帧中7(上次t=0),0(上次t=1),1(上次t=2)。最久未使用=7→淘汰7
- t=5(访问3)：帧中2(上次t=3),0(上次t=4),1(上次t=2)。最久=1→淘汰1
- t=6(访问0)：0在帧中→命中！（注意和FIFO不同——0虽然进来得早，但它在t=4刚被访问过，不是"最久未使用"的）
- t=7(访问4)：帧中2(上次t=3),0(上次t=6),3(上次t=5)。最久=2→淘汰2

**缺页次数：10次**

**LRU vs FIFO的关键差别**：FIFO看"什么时候进来的"，LRU看"什么时候最后被用过"。

---

### CLOCK（时钟/NRU）

**规则**：LRU的简化近似。不记录精确的访问时间，只记录"最近有没有被访问过"。

**实现**：
- 所有页面组成环形链表
- 每个页面有访问位R（访问时置1）
- 缺页时从指针位置开始扫描：
  - R=0 → 淘汰这一页
  - R=1 → 置R=0，指针前移，继续

**关键**：命中时指针**不移动**，只把R置1。

#### 推导：7, 0, 1, 2, 0, 3, 0, 4（3页框）

```
t=0: 装入7(R=1), 指针→0号帧之后
     帧: [7,R=1] [空] [空]  指针→帧1
t=1: 装入0(R=1), 指针→帧2
     帧: [7,R=1] [0,R=1] [空]  指针→帧2
t=2: 装入1(R=1), 指针→帧0
     帧: [7,R=1] [0,R=1] [1,R=1]  指针→帧0

t=3: 访问2,缺页。指针在帧0。
     帧0: 7,R=1 → 置R=0, 指针→帧1
     帧1: 0,R=1 → 置R=0, 指针→帧2
     帧2: 1,R=1 → 置R=0, 指针→帧0（一圈回来）
     帧0: 7,R=0 → 淘汰7! 装入2(R=1), 指针→帧1
     帧: [2,R=1] [0,R=0] [1,R=0]

t=4: 访问0,命中! 置0的R=1。指针不动。
     帧: [2,R=1] [0,R=1] [1,R=0]

t=5: 访问3,缺页。指针在帧1。
     帧1: 0,R=1 → 置R=0, 指针→帧2
     帧2: 1,R=0 → 淘汰1! 装入3(R=1), 指针→帧0
     帧: [2,R=1] [0,R=0] [3,R=1]

t=6: 访问0,命中! 置R=1。
t=7: 访问4,缺页。指针在帧0。
     帧0: 2,R=1 → 置R=0, 指针→帧1
     帧1: 0,R=1 → 置R=0, 指针→帧2
     帧2: 3,R=1 → 置R=0, 指针→帧0
     帧0: 2,R=0 → 淘汰! 装入4(R=1), 指针→帧1
```

**缺页6次**（含3次冷启动）

### 改进型CLOCK

增加修改位M。优先淘汰(A=0,M=0)的页面，因为这种页面不需要写回磁盘。

扫描顺序：先找(0,0)→找不到则找(0,1)同时把A都清0→再找(0,0)→...

## 6.4 综合计算题型

### 题型一：地址转换+缺页+置换

**题目**：页面大小1KB，4个页框装着0/1/2/3号页面。在t=260时访问17CAH。用FIFO。

**Step 1**：拆地址
```
17CAH = 0001 0111 1100 1010
页面大小1KB = 2^10 → 低10位是偏移
偏移 = 11 1100 1010 = 3CAH
页号 = 0001 01 = 5
```

**Step 2**：第5页不在页表中→缺页！

**Step 3**：FIFO找最早进入的页面淘汰→查装入时刻→淘汰最早的

**Step 4**：第5页装入对应的页框，算物理地址

---

### 题型二：有效访问时间

$$EAT = (1-p) \times t_{mem} + p \times t_{fault}$$

其中p=缺页率，$t_{fault}$包含磁盘I/O时间。

**例**：内存10ns，缺页处理21ms。要求性能降低≤10%：
$$EAT \leq 1.1 \times 10ns = 11ns$$
$$(1-p) \times 10 + p \times 21\times10^6 \leq 11$$
$$p \leq \frac{1}{21\times10^6} \approx 4.76 \times 10^{-8}$$

结论：缺页率必须极低，**低于五千万分之一**。所以好的置换算法至关重要。

---

### 题型三：程序写法对缺页的影响

数组 int a[100][100]，按**行优先**存储。每页存200个整数。2页数据空间。

**程序A（按行访问）**：
```c
for(i=0; i<100; i++)
    for(j=0; j<100; j++) a[i][j]=0;
```
每行100个元素，2行=200个=1页。访问完一行接着访问下一行，每2行换一次页。
缺页 = 100行 / 2行/页 = **50次**

**程序B（按列访问）**：
```c
for(j=0; j<100; j++)
    for(i=0; i<100; i++) a[i][j]=0;
```
访问 a[0][0], a[1][0], a[2][0]...——每访问一个元素就跳100个整数（半页），几乎每次都缺页。
缺页 = 10000 / 2 = **5000次**

**100倍的差距！** 启示：程序的访问模式要与数据存储顺序一致，充分利用空间局部性。

## 6.5 工作集与抖动

### 工作集(Working Set)

某段时间窗口内进程实际访问的页面集合。

**关键**：分配的页框数 ≥ 工作集大小 → 缺页率低。如果 < 工作集 → 频繁缺页。

### 抖动(Thrashing)

**现象**：系统花更多时间在换页上而不是执行程序。

**因果链**：
```
多道程序度太高
 → 每个进程分到的页框太少
 → 工作集放不下
 → 频繁缺页
 → 大量磁盘I/O
 → CPU空闲率上升
 → 调度器以为可以加载更多进程
 → 更多缺页
 → 恶性循环！
```

**预防**：
1. 局部置换——自己缺页只换自己的页，不影响别人
2. 用工作集算法控制多道程序度
3. L=S准则（缺页间隔≈缺页处理时间→最佳平衡点）
4. 挂起部分进程
