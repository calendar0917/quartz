# 第3章 基本内存管理 —— 程序怎么装进内存

---

## 5.0 一个根本问题

程序写的时候用的是"从0开始"的逻辑地址，但物理内存已经被操作系统和其他进程占了一部分。怎么把程序放进去？放在哪？地址怎么对应？

这就是内存管理的三大任务：**分配空间、地址转换、保护隔离**。

---

## 5.1 从源代码到内存——三步走

```
源代码 ──编译──→ 目标模块(.o) ──链接──→ 装入模块(.exe) ──装入──→ 内存
```

### 三种地址空间

- **名空间**：源代码中的变量名、函数名（如 `int count`）
- **逻辑空间**：编译后以0为起点的地址（如 JMP 300）
- **物理空间**：内存中的实际地址（如 JMP 1300）

**地址映射**就是：逻辑空间 → 物理空间

### 三种装入方式——理解"什么时候做地址转换"

| 方式 | 何时转换 | 举例 | 核心限制 |
|------|----------|------|----------|
| **绝对装入** | 编译时 | 编译器直接生成物理地址1300 | 必须放固定位置，改位置要重新编译 |
| **静态重定位** | 装入时 | 装入器把所有地址+基址 | 装入后**不能移动** |
| **动态重定位** | 执行时 | 靠硬件（重定位寄存器）每次访问时加基址 | 需要硬件支持（**主流方式**） |

#### 动态重定位——为什么是主流

```
逻辑地址200 → 重定位寄存器(值=1000) → 物理地址 = 1000+200 = 1200
```

优势：程序可以在内存中**移动**（改寄存器值就行），可以**分散存放**（分页的基础），可以**共享**。

---

## 5.2 连续分配——最直觉的方案

### 思路：给每个进程分一块连续的内存区域

#### 固定分区

预先把内存切成若干块，每块装一个进程。

**问题**：小程序放在大分区里 → **内部碎片**（分区内浪费的空间）

#### 动态分区

根据进程实际大小分配。进程来了就切一块，走了就回收。

**问题**：频繁分配回收后，产生很多零散的小空闲区 → **外部碎片**

### 动态分区的四种分配算法

关键在于"空闲区很多，选哪一块给进程？"

| 算法 | 空闲链排序 | 选择策略 | 直觉 |
|------|-----------|----------|------|
| **首次适应(FF)** | 地址递增 | 第一个够大的 | "从头找，碰到合适的就用" |
| **循环首次适应(NF)** | 地址递增(循环) | 从上次位置继续 | "不总从头找，均匀分布" |
| **最佳适应(BF)** | 容量递增 | 最小的够大的 | "精打细算，刚好够用" |
| **最差适应(WF)** | 容量递减 | 最大的那块 | "大方切割，剩余还能用" |

#### 用一个例子理解区别

空闲区：20K(地址100), 60K(地址200), 40K(地址300)。进程需要25K。

- **FF**：从地址最小的开始找 → 20K不够 → 60K够 → 选60K，剩35K
- **NF**：假设上次从地址200开始 → 60K够 → 选60K
- **BF**：按大小排 20K,40K,60K → 40K是最小够用的 → 选40K，剩15K
- **WF**：按大小降序 60K,40K,20K → 60K最大 → 选60K，剩35K

**FF的优势**：高地址部分保留了大的空闲区，以后来了大进程能放得下。这是考试中常考的分析题。

#### 紧凑（Compaction）

外部碎片太多怎么办？把所有进程往一端移动，合并所有碎片为一个大空闲区。前提：**动态重定位**（否则移动后地址就错了）。

## 5.3 离散分配——突破"连续"的限制

连续分配的根本问题：必须找一块足够大的**连续**区域。碎片化严重时可能找不到。

**离散分配的核心思想**：允许一个进程的不同部分放在不同的物理位置。

### 分页存储管理

#### 核心模型

```
逻辑空间（程序视角）          物理内存（实际）
┌────┐ 第0页                  ┌────┐ 第0帧
├────┤ 第1页    ──页表映射──→  ├────┤ 第1帧
├────┤ 第2页                  ├────┤ 第2帧
├────┤ 第3页                  ├────┤ 第3帧
└────┘                        └────┘
```

- **页(Page)**：逻辑空间切成等大的块
- **帧/页框(Frame)**：物理内存切成同样大小的块
- **页表**：记录"第i页放在第几帧"

#### 逻辑地址怎么拆

```
逻辑地址 A，页面大小 L
┌──────────────┬────────────┐
│  页号 P       │  页内偏移 d │
│  = A / L      │  = A % L    │
└──────────────┴────────────┘
```

**32位系统，4KB页面**：低12位 = 偏移（4KB=2^12），高20位 = 页号

#### 地址转换——完整推导一道题

**题目**：页面大小1KB，逻辑地址2500，页表中第2页对应物理块号10。求物理地址。

**Step 1：拆逻辑地址**
```
P = 2500 / 1024 = 2（取整）
d = 2500 % 1024 = 2500 - 2×1024 = 452
```

**Step 2：查页表**
第2页 → 物理块号10

**Step 3：算物理地址**
```
物理地址 = 块号 × 页面大小 + 偏移 = 10 × 1024 + 452 = 10692
```

#### 另一道典型题

**题目**：逻辑地址09C4H，页面大小1KB(=400H)。第2页在第10块。

**Step 1**（十六进制拆分）：
```
09C4H / 400H = 2...1C4H
即 页号P=2, 偏移d=1C4H
```

**Step 2**：查表得块号=10（十进制）= 0AH

**Step 3**：
```
物理地址 = 0AH × 400H + 1C4H = 2800H + 1C4H = 29C4H
```

**技巧**：如果页面大小是2^n，直接看二进制——低n位是偏移，高位是页号。1KB=2^10，所以09C4H = 0000 10 | 01 1100 0100，高6位=000010(=2)，低10位=01 1100 0100(=1C4H)。

### 快表（TLB）——解决"两次访存"问题

**问题**：每次访问数据需要**两次内存访问**：一次查页表，一次取数据。太慢了。

**解决**：用高速缓存存常用的页表项——TLB(Translation Lookaside Buffer)。

```
CPU发出逻辑地址 → 查TLB
  命中(hit) → 直接得到帧号，1次内存访问
  未命中(miss) → 查内存中的页表 → 更新TLB → 2次内存访问
```

**有效访问时间(EAT)**：

$$EAT = h \times (t_{TLB} + t_{mem}) + (1-h) \times (t_{TLB} + 2 \times t_{mem})$$

如果TLB访问时间可忽略：$EAT = h \times t_{mem} + (1-h) \times 2t_{mem} = (2-h) \times t_{mem}$

**例**：命中率85%，内存访问1.5μs，TLB忽略：
$EAT = (2-0.85) × 1.5 = 1.725μs$（比2次的3μs快多了）

### 二级页表——解决"页表太大"问题

**问题**：32位地址，4KB页面 → 2^20 = 100万个页表项。每项4B → 页表占4MB。一个连续的4MB空间很难找到。

**解决**：把页表本身也分页！

```
逻辑地址: ┌─── 10位 ───┬─── 10位 ───┬─── 12位 ───┐
           │ 页目录号P1 │ 页表页号P2 │  页内偏移d  │
           └────────────┴────────────┴─────────────┘
```

**转换过程**：P1 → 查一级页表 → 得到二级页表地址 → P2 → 查二级页表 → 得到物理帧号 → +d → 物理地址

**代价**：需要**3次**内存访问（但有TLB缓解）。

### 分段存储管理

#### 分页 vs 分段的设计哲学

| | 分页 | 分段 |
|--|------|------|
| **谁决定切分** | 系统自动 | 程序员按逻辑结构 |
| **大小** | 固定（4KB） | 可变（代码段、数据段各不同） |
| **地址维度** | 一维（线性地址） | 二维（段号+段内偏移） |
| **碎片** | 内部碎片（最后一页可能没装满） | 外部碎片（段大小不一） |
| **共享** | 不方便（共享一个过程要共享好几页） | 方便（以段为单位共享整个函数） |
| **动态链接** | 难 | 自然支持 |

**为什么分段便于共享？** 因为一个函数/模块恰好是一个段。共享时只需让两个进程的段表项指向同一物理区域。分页则需要找出该函数占了哪些页，逐页共享。

### 段页式

先按逻辑分段，段内再分页。兼具分段的逻辑清晰和分页的内存管理高效。

```
逻辑地址: 段号S + 段内页号P + 页内偏移d
转换：S → 查段表 → 得到该段的页表地址 → P → 查页表 → 得到帧号 → +d
```

## 5.4 伙伴系统（Buddy System）

**思想**：分区大小只能是2^k。

- 分配n字节 → 找最小的 2^i ≥ n
- 没有 2^i → 把 2^(i+1) 拆成两个 2^i（一对"伙伴"），一个分配，一个空闲
- 释放时 → 如果伙伴也空闲，合并为 2^(i+1)

**优点**：分配回收快。**缺点**：内部碎片可能较大（申请65K，分配128K）。
