# 第4章 设备与I/O管理 —— CPU和外设速度差千倍怎么办

---

## 7.0 核心矛盾

CPU纳秒级，内存百纳秒级，磁盘毫秒级，打印机更慢。如果CPU每发一个字节给打印机就停下来等，99.99%的时间都在空等。

这一章的所有技术都在解决一个问题：**让CPU尽量少等I/O，让设备尽量忙。**

---

## 7.1 I/O控制方式的演进——四代技术逐步减少CPU参与

### 第一代：程序控制I/O（忙等待/轮询）

```
CPU发命令 → 反复检查设备状态 → 就绪了 → 传一个字节 → 再检查...
```

CPU全程参与，全程等待。就像你站在打印机旁边一直盯着它出纸。

### 第二代：中断驱动I/O

```
CPU发命令 → 去做别的事 → 设备完成后发中断 → CPU响应，传一个字节 → 继续
```

**进步**：CPU和I/O设备可以**并行**。CPU发完命令就去执行其他进程了。

**问题**：每传一个字节就中断一次，如果传1MB数据要中断100万次。

### 第三代：DMA（直接存储器访问）

```
CPU告诉DMA控制器：从设备读数据到内存地址X，共N字节
 → DMA控制器接管，自己搬数据
 → 搬完了中断一次通知CPU
```

**进步**：数据传输不经过CPU，以**块**为单位。CPU只在开始和结束时参与。

**DMA控制器有四个寄存器**：
- CR(命令)：干什么操作
- MAR(内存地址)：数据搬到内存哪里
- DR(数据)：数据暂存
- DC(计数)：还剩多少字节

### 第四代：通道控制

```
CPU发一条I/O指令 → 通道（专用I/O处理器）执行一整套通道程序
 → 可以控制多个设备连续传输多个数据块
 → 全部完成后中断通知CPU
```

**进步**：CPU、通道、设备**三者并行**。一条命令搞定一批I/O操作。

| 代际 | CPU参与度 | 传输单位 | 中断频率 |
|------|-----------|----------|----------|
| 程序控制I/O | 全程 | 字节 | 无（忙等） |
| 中断驱动 | 每字节 | 字节 | 极高 |
| DMA | 每块 | 块 | 低 |
| 通道 | 每批 | 多块 | 极低 |

## 7.2 中断机制——OS的"心跳"

OS赖以活动的基础。**没有中断，OS就无法重新获得CPU的控制权**。

### 中断的分类

```
中断
├─ 外部中断（硬件中断）
│   ├─ I/O中断（设备完成操作）
│   └─ 硬件故障（电源、校验错）
└─ 内部中断
    ├─ 程序性中断/异常（除零、越界、缺页）
    └─ 系统调用（trap/访管中断）
```

### 中断响应过程

1. CPU执行完当前指令后检查中断信号
2. 保存断点（PC、PSW等）
3. 根据中断号查**中断向量表**找到处理程序入口
4. 切换到内核态
5. 执行中断处理程序
6. 恢复现场，返回

### 中断优先级

高 → 低：硬件故障 > 系统调用 > 外部中断(NMI > IRQ) > 程序异常

## 7.3 缓冲技术——在CPU和设备之间垫一层

### 为什么需要缓冲

```
CPU速度 >>>>>> 设备速度
```

不用缓冲：CPU每产生一个数据就等设备接收→CPU大量空闲。
用缓冲：CPU把数据扔到缓冲区就走，设备慢慢从缓冲区取。

### 缓冲类型

**单缓冲**：一个缓冲区。CPU把数据放进去，设备从这里取。但两者不能同时操作同一个缓冲区。

处理一块数据的时间 = **Max(C, T) + M**（C=计算时间，T=传输时间，M=搬移时间）

**双缓冲**：两个缓冲区轮换。CPU写1号时设备读2号。

处理一块数据的时间 ≈ **Max(C, T)**（M很小可忽略）

**直觉**：单缓冲像一条单行道，双缓冲像双向两车道。

**循环缓冲**：多个缓冲区组成环形队列，生产者消费者模型。

**缓冲池**：系统统一管理的公共缓冲区集合，所有进程共享。

## 7.4 I/O软件层次

```
用户层I/O软件        ← printf(), scanf() 等库函数
   │
设备独立性软件       ← 统一接口、设备命名、保护、分配
   │
设备驱动程序         ← 每类设备一个，翻译抽象命令为硬件操作
   │
中断处理程序         ← 响应设备中断
   │
硬件                 ← 实际I/O设备
```

**设备独立性**的含义：用户程序中使用逻辑设备名（如"printer"），OS负责映射到物理设备。这样换了打印机型号，程序不用改。

## 7.5 SPOOLing——化独占为共享

打印机是独占设备——一次只能一个进程用。但我们不想让进程排队等打印机。

**SPOOLing（假脱机）技术**：
1. 进程的打印数据先写到磁盘的**输出井**
2. 由SPOOLing输出进程按顺序从输出井取数据送给打印机
3. 进程以为自己在独占打印机，实际上多个进程"同时"打印

**本质**：用磁盘空间模拟了一个"虚拟打印机"——虚拟化思想。

## 7.6 磁盘调度（可能考计算）

磁盘访问时间 = 寻道时间 + 旋转延迟 + 传输时间。其中**寻道时间**占大头。

### 算法

**FCFS**：按请求顺序服务。公平但寻道距离大。

**SSTF（最短寻道时间优先）**：选离当前磁道最近的。寻道距离小但可能饥饿。

**SCAN（电梯算法）**：磁头朝一个方向移动到端，再反向。像电梯上下。

**C-SCAN（循环扫描）**：只朝一个方向服务，到端后直接回起点。更均匀。

#### 示例

请求队列：98, 183, 37, 122, 14, 124, 65, 67。当前磁头位置53。

**SSTF**：53→65→67→37→14→98→122→124→183，总移动=(12+2+30+23+84+24+2+59)=236

**SCAN（向增大方向）**：53→65→67→98→122→124→183→(到端)→37→14
总移动 = (183-53) + (183-14) = 130 + 169 = 299

（实际SCAN要看是否扫到磁盘物理端还是只到最远请求）

## 本章关键理解

1. 四种I/O方式是**递进关系**——每代都比上代减少了CPU的参与
2. 中断是OS获得控制权的根本机制
3. 缓冲本质上是"以空间换时间"
4. SPOOLing是虚拟化思想在设备管理中的体现
