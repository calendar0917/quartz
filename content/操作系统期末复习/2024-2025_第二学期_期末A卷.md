## 一、选择题（每小题 2 分，共 30 分）

**1.** 早期多道批处理系统的主要特性**不**包括（ ）

A、多个作业可同时驻留内存  
B、调度程序负责多个作业的调度  
C、多个作业可以并发执行  
D、用户可以通过终端键入命令  

<details>
<summary>答案与解析</summary>

**答案：D**

多道批处理系统的特征（课件原文）：**多道性、调度性、无序性、无交互能力**。

- A ✅：多道性——内存中同时存放多个作业
- B ✅：调度性——作业调度程序负责调度
- C ✅：并发执行——当一个作业等 I/O 时 CPU 切换执行另一个
- D ❌：**用户通过终端键入命令是分时系统的特征**。多道批处理使用作业控制语言（JCL），没有交互。

**区分口诀**：批处理=无交互，分时=交互+时间片，实时=截止时间。

</details>

**2.** 下列描述**不**属于微内核优点的是（ ）

A、简化了内核实现  
B、提供了灵活性，可移植性  
C、适用于分布式环境  
D、减少了用户态和内核态之间的通信开销  

<details>
<summary>答案与解析</summary>

**答案：D**

微内核的优缺点（课件原文）：

**优点**：提高了可扩展性、增强了可靠性、可移植性好、提供对分布式系统的支持。

**缺点**：运行效率有所降低——**消息传递开销 + 模式切换开销**。

- A ✅：内核功能少，实现简单
- B ✅：模块化强，容易移植
- C ✅：C/S 结构天然适合分布式
- D ❌：微内核**增加了**通信开销（用户进程→内核→服务器→内核→用户），不是减少！

</details>

**3.** 下列事件可**引起进程终止**的是（ ）

A、时钟中断到来  
B、进程访问的页不在内存  
C、进程试图访问不允许访问的内存单元  
D、分配给进程的页框被填满  

<details>
<summary>答案与解析</summary>

**答案：C**

进程终止的原因（课件原文）：
- **正常结束**：exit()
- **异常结束**：越界错误、保护错、非法指令、特权指令错、运行超时、等待超时、算术运算错（被 0 除）、I/O 故障
- **外界干预**：kill 进程、父进程请求、父进程结束

逐项分析：
- A：时钟中断→进程切换（就绪/运行之间），不终止
- B：缺页中断→OS 调入页面→继续执行，不终止
- C ✅：**访问不允许访问的内存→保护错→异常终止**
- D：页框满了→执行页面置换算法→不终止

</details>

**4.** 进程挂起的原因**不**包括（ ）

A、父进程请求挂起子进程  
B、I/O 操作阻塞当前进程  
C、周期性执行的进程可能会被挂起  
D、用户因调试而请求挂起进程  

<details>
<summary>答案与解析</summary>

**答案：B**

挂起和阻塞是**不同**的概念：
- **阻塞** = 在等某个事件（如 I/O 完成）
- **挂起** = 被换出到外存（内存紧张、OS 需要、用户请求、父进程请求）

I/O 操作导致的是**阻塞**（主动 block 自己），不是挂起。挂起是由 OS 或父进程**强制**执行的。

挂起的原因（课件原文）：
- 进程全部阻塞，处理器空闲 → 腾出内存
- 交换（内存空间紧张）
- OS 需要（后台进程、可能出故障的进程）
- 终端用户请求（调试）
- **父进程请求** ✅
- **周期性进程挂起** ✅
- **用户调试请求** ✅

B 是**阻塞**的原因，不是挂起的原因。

</details>

**8.** 实时操作系统与分时操作系统的主要区别在于（ ）

A、多任务处理能力  
B、响应时间的确定性  
C、用户数量  
D、内存管理方式  

<details>
<summary>答案与解析</summary>

**答案：B**

两者都能多任务、都支持多用户、都可以用类似的内存管理。关键区别：

- **分时系统**：追求响应时间**短**，但没有硬性截止时间
- **实时系统**：必须在**规定时间（deadline）内完成**。正确性 = 结果正确 + **时间正确**

总结：**分时 = 越快越好；实时 = 必须按时**。

</details>

**11.** 虚拟存储管理系统中存在"抖动"现象，其含义是（ ）

A、页面频繁换入换出  
B、屏幕出现闪烁现象  
C、CPU 利用率忽高忽低  
D、硬盘震动严重  

<details>
<summary>答案与解析</summary>

**答案：A**

**抖动（Thrashing）**：进程的页面被频繁换入换出，导致缺页率急剧增加、有效存取时间加长、系统吞吐量骤减。

**因果链**：
多道程序度过高 → 每个进程页框太少 → 工作集放不下 → 频繁缺页 → 大量 I/O → CPU 空闲 → 调度器再加进程 → 更频繁缺页 → 恶性循环！

</details>

**12.** 关于 DMA 技术，下列说法**错误**的是（ ）

A、数据传输是在 CPU 控制下完成的  
B、CPU 控制数据传输方向及位置  
C、DMA 的数据传输单位是块

<details>
<summary>答案与解析</summary>

**答案：A**

DMA 的核心特点：数据传输**不经过 CPU**，由 DMA 控制器直接在设备和内存之间搬数据。

- A ❌：数据传输在 **DMA 控制器控制下**完成，CPU 不参与数据搬运

- C ✅：DMA 以**数据块**为传输单位
- D ✅：DMA 完成后通过**中断**通知 CPU

**1.** 就绪的进程被交换到外存，不参与 CPU 的竞争，这个状态被称为 \\_\\_\\_\\_ 。

<details>
<summary>答案与解析</summary>

**答案：挂起状态 / 就绪挂起**

处于此状态的进程：在外存中、已具备除 CPU 外的所有条件、只要调入内存就能执行。对应"就绪且挂起（ready/suspended）"。

**区分**：阻塞/挂起 = 在外存 + 还在等事件。

</details>

**2.** 读取和修改程序状态字之类的控制寄存器的指令只能在 \\_\\_\\_\\_ 形式下执行。

<details>
<summary>答案与解析</summary>

**答案：内核模式 / 特权模式 / 管态**

PSW 中包含 CPU 的模式位、中断屏蔽位等关键状态。如果用户态程序能随意修改 PSW，就可以把自己提权到内核态——这是安全漏洞。所以只能在**内核模式**下修改。

</details>

---

**3.** 某信号量 S 的初始值为 3，经过 6 次 P 操作和 2 次 V 操作后，S 的值为 \\_\\_\\_\\_ 。

<details>
<summary>答案与解析</summary>

**答案：-1**

初始值 = 3  
P 操作 6 次：每次减 1 → S = 3 - 6 = -3  
V 操作 2 次：每次加 1 → S = -3 + 2 = **-1**

**S = -1 的含义**：资源已分配完，且还有 1 个进程在等待队列中。

</details>

**4.** 操作系统通过 \\_\\_\\_\\_ 技术实现 CPU 的虚拟化，使多个进程可以并发执行。

<details>
<summary>答案与解析</summary>

**答案：进程调度 / 分时 / 时间片轮转**

**CPU 虚拟化**：每个进程以为自己独占 CPU，实际上 OS 通过快速切换（调度）让多个进程共享 CPU。这种"快速切换"就是进程调度（时分复用技术）。

</details>

**5.** 文件系统的目录结构中，采用 \\_\\_\\_\\_ 结构可以允许文件名重复。

<details>
<summary>答案与解析</summary>

## 三、分析计算题（共 34 分）

### 第 1 题（6 分）—— SRT 调度

在一个分时系统中，有 A、B、C、D、E 五个非周期性进程，到达时间、执行时间如下。假设时间从 0 开始，采用**最短剩余时间优先（SRT）**调度算法：

| 进程 | 到达时间 | 执行时间 |
|------|----------|----------|
| A | 10 | 20 |
| B | 20 | 10 |
| C | 30 | 20 |
| D | 50 | 10 |
| E | 50 | 20 |

**（1）**五个进程的依次调度顺序是什么？（3分）  
**（2）**什么时间所有进程全部执行完毕？（3分）

<details>
<summary>答案与解析</summary>

#### 逐时刻推导（SRT = 谁剩余时间短谁上 CPU）

```
t=0: 无进程 → CPU 空闲
t=10: A到达(需20)。唯一进程，执行A。
t=20: B到达(需10)。A剩余=20-(20-10)=10。比较：B需10 = A剩10 →
      按惯例选先到达的A继续；或此处理论上可选任一个。
      假设A继续(两种选法最终完成时间不同但都合法)。
t=30: C到达(需20)。A已从t=20跑到t=30(剩0？不对…)
```

让我重新仔细推：

```
t=0-10: CPU 空闲（没有进程到达）
t=10: A到达(需20)。就绪=[A(20)]。执行A。
t=20: B到达(需10)。A剩余=20-(20-10)=10。B需10 = A剩10 →
      选择刚到的B或先到的A。假设选B(剩10)。
t=20: B开始执行（需10，即B从t=20跑到t=30）

实际上当A剩10和B需10相等时，选A继续还是B抢占都可以。我们假设B抢占：
t=30: B完成，C到达(需20)。A剩10，C需20。A更短→执行A。
t=40: A完成。就绪=[C(20)]→执行C。
t=50: D到达(需10)，E到达(需20)。C剩余=20-10=10。比较：D需10 < C剩10? 相等！
      假设D抢占C或C继续。若D抢占：
t=50: D开始执行。
t=60: D完成。就绪=[C(10), E(20)]。C更短→执行C。
t=70: C完成。执行E(20)。
t=90: E完成。
```

**但课件中标准做法通常是：剩余时间相等时，选服务时间更短的（或先到达的）继续执行。**

实际SRT的经典做法是：剩余时间相等时选原进程继续（减少切换开销）。所以我们严格按这个来：

```
t=10: A开始(剩20)
t=20: B到达(需10)。A剩10。B需10=A剩10→A继续。
t=30: B(需10)已等10, C到达(需20)。A剩0, A完成✓。就绪=[B(10),C(20)]。B更短→执行B。
t=40: B完成✓。就绪=[C(20)]。执行C。
t=50: D(10)和E(20)到达。C剩10。D需10=C剩10→C继续。
t=60: C完成✓。就绪=[D(10),E(20)]。D更短→执行D。
t=70: D完成✓。执行E(20)。
t=90: 全部完成。
```

**（1）调度顺序**：A → B → C → D → E  
**（2）全部完成时间**：**t=90**

如果是B抢占A的情况（剩余相等选新来的）：
t=10: A开始→t=20: B抢占→t=30: B完成→t=30: C到达，A剩10→A执行→t=40: A完成→t=50: D/E到达，C剩10→t=60: C完成→t=70: D完成→t=90: E完成。顺序为 A→B→...(实际B和A之间有个抢占切换)。最终完成时间=90。

两种判定规则（剩余相等时抢占或不抢占）下完成时间相同。

</details>

### 第 2 题（6 分）—— 银行家算法

考虑一个由四个进程和三种资源组成的系统状态：

| 资源 | R1 | R2 | R3 |
|------|----|----|----|
| 总量 | 9 | 2 | 6 |

已分配矩阵 A 和需求矩阵 C-A：

| 进程 | A(R1,R2,R3) | C-A = Need(R1,R2,R3) |
|------|-------------|---------------------|
| P1 | (1,0,0) | (2,2,2) |
| P2 | (6,1,2) | (0,0,1) |
| P3 | (2,1,1) | (1,0,3) |
| P4 | (0,0,2) | (4,2,0) |

当前剩余可用资源：**1 个 R2 和 1 个 R3**，即 Available = (0,1,1)。

**（1）**此时系统是否处于安全状态？（3分）  
**（2）**若是，给出安全序列；若否，分析原因。（3分）

<details>
<summary>答案与解析</summary>

#### 验证 Available

Available = 总量 - ΣAllocation：
- R1：9 - (1+6+2+0) = **0** ✓（与题目给的"R1=0个可用"一致）
- R2：2 - (0+1+1+0) = **0**？等等题目说"剩余可用资源为 1 个 R2 和 1 个 R3"

检查 Allocation 之和：R2=0+1+1+0=2，总量=2 → Available R2 = 0。但题目说 1 个 R2 可用。让我们用题目给的数据：Available = (0,1,1)。

#### （1）安全性检查

Work = Available = (0,1,1)

| 轮次 | 进程 | Need | Need ≤ Work? | 选取 | 释放后 Work |
|------|------|------|-------------|------|------------|
| 1 | P1 | (2,2,2) | 2>0 ❌ | — | — |
| 1 | P2 | (0,0,1) | 0≤0,0≤1,1≤1 ✅ | **P2** | (6,2,3) |
| 2 | P1 | (2,2,2) | 2≤6,2≤2,2≤3 ✅ | **P1** | (7,2,3) |
| 3 | P3 | (1,0,3) | 1≤7,0≤2,3≤3 ✅ | **P3** | (9,3,4) |
| 4 | P4 | (4,2,0) | 4≤9,2≤3,0≤4 ✅ | **P4** | (9,3,6) |

✅ 所有进程的 Finish 均为 true。**系统处于安全状态。**

**安全序列**：**P2 → P1 → P3 → P4**

</details>

### 第 3 题（12 分）—— 磁盘计算

某磁盘：平均寻道时间 4ms，转速 7500 rpm，每磁道 500 扇区，每扇区 512B，每 2 个连续扇区 = 1 块。文件大小固定为 250KB。

**（1）**旋转延迟？每块传输延迟？（6分）  
**（2）**文件如何放访问最快？需要多少 ms？（3分）  
**（3）**文件如何放访问最慢？需要多少 ms？（3分）

<details>
<summary>答案与解析</summary>

#### （1）旋转延迟和传输延迟

转速 = 7500 rpm = 7500/60 = 125 转/秒  
每转时间 = 1/125 = 0.008s = **8ms**  
**平均旋转延迟** = 8/2 = **4ms**（半圈）

每磁道 500 扇区 → 每块 = 2 扇区 → 每磁道 250 块  
每块传输时间 = 8ms / 250 = **0.032ms**（即 32μs）

---

#### （2）最快存放方式

**连续存放**在磁盘的相邻块上。

250KB / 1KB（每块）= **250 块**

全部放在同一磁道（250 块恰好占满一个磁道的 250 块）。

**最快访问时间** = 寻道 4ms + 旋转延迟 4ms + 传输 250×0.032ms  
= 4 + 4 + 8  
= **16ms**

（传输 250 块刚好是一整圈 = 8ms）

---

#### （3）最慢存放方式

每个块都在**不同磁道**上，随机分散。

每次读 1 块需要：寻道 4ms + 旋转延迟 4ms + 传输 0.032ms

250 块总时间 = 250 × (4 + 4 + 0.032)  
= 250 × 8.032ms  
= **2008ms ≈ 2 秒**

**最快 vs 最慢**：16ms vs 2008ms → 相差 **125 倍**！

这就是为什么连续文件访问快、磁盘碎片整理有意义。

</details>

### 第 1 题 —— 请求分页 + CLOCK/LRU（12 分）

页面大小 4KB，固定 4 页框。初始页表：

| 虚拟页号 | 页框号 | 有效位 |
|----------|--------|--------|
| 0 | 09H | 1 |
| 1 | 0CH | 1 |
| 2 | 0BH | 1 |
| 3 | — | 0 |
| 4 | 0AH | 1 |

驻留集：页0(帧9), 页1(帧C), 页2(帧B), 页4(帧A)。CLOCK 指针初始指向帧 9（页 0）。

依次访问虚拟地址：**1234H, 0BA5H, 2A05H, 4200H, 3321H**

**（1）a)** 用 CLOCK 算法，给出最终驻留集分布、use 位、指针位置。（5分）  
**（1）b)** 地址 3321H 的物理地址是多少（十六进制）？（3分）  
**（2）** 若改用 LRU，地址 3321H 的物理地址是多少？（4分）

<details>
<summary>答案与解析</summary>

#### Step 0：初始状态

驻留集（按页框号排列）：

| 帧号 | 页号 | use位 |
|------|------|-------|
| 09H | 0 | 1 |
| 0AH | 4 | 1 |
| 0BH | 2 | 1 |
| 0CH | 1 | 1 |

CLOCK 指针 → 帧 09H（页 0）。环形顺序：09H → 0AH → 0BH → 0CH → 09H...

---

#### Step 1：访问 1234H

1234H / 1000H(4KB) = 1...234H → **页号 = 1**

页 1 在帧 0CH → **命中**。use 位置 1（已经是 1）。

驻留集不变。指针不移动。

---

#### Step 2：访问 0BA5H

0BA5H / 1000H = 0...BA5H → **页号 = 0**（0x0BA5 < 0x1000）

页 0 在帧 09H → **命中**。use 位保持 1。

---

#### Step 3：访问 2A05H

2A05H / 1000H = 2...A05H → **页号 = 2**

页 2 在帧 0BH → **命中**。

---

#### Step 4：访问 4200H

4200H / 1000H = 4...200H → **页号 = 4**

页 4 在帧 0AH → **命中**。

---

#### Step 5：访问 3321H

3321H / 1000H = 3...321H → **页号 = 3**

页 3 不在内存！→ **缺页中断**，需要淘汰一个页面。

#### CLOCK 淘汰过程

指针当前在帧 09H（页 0）。按顺时针 09H→0AH→0BH→0CH。

```
扫描帧 09H(页0): use=1 → 置 use=0，指针移到 0AH
扫描帧 0AH(页4): use=1 → 置 use=0，指针移到 0BH
扫描帧 0BH(页2): use=1 → 置 use=0，指针移到 0CH
扫描帧 0CH(页1): use=1 → 置 use=0，指针移到 09H
扫描帧 09H(页0): use=0 → 淘汰页0！
```

**淘汰页 0（帧 09H）**，装入页 3，置 use=1。指针移到 0AH。

#### 最终驻留集

| 帧号 | 页号 | use位 |
|------|------|-------|
| 09H | 3 | 1 |
| 0AH | 4 | 0 |
| 0BH | 2 | 0 |
| 0CH | 1 | 0 |

指针 → 帧 0AH（页 4）

---

#### （1）b）3321H 的物理地址

页号 = 3（3321H / 1000H = 3...321H），偏移 = 321H

页 3 在帧 09H → 物理地址 = **09H × 1000H + 321H = 9000H + 321H = 9321H**

---

#### （2）若用 LRU

LRU 以"最近被访问的时刻"来判断。回顾访问序列：

```
访问 1234H(页1): 访问页1（最近）
访问 0BA5H(页0): 访问页0（最近）
访问 2A05H(页2): 访问页2（最近）
访问 4200H(页4): 访问页4（最近）
访问 3321H(页3): 缺页！谁最久没用？
```

初始时所有页面"刚被访问过"。按访问历史：
- 页1 在第一步被访问（最久）
- 页0 在第二步
- 页2 第三步
- 页4 第四步（最近）

LRU 淘汰**页 1**（最久未使用）。

页 3 装入帧 0CH（原页 1 的位置）。

3321H → 页号=3，帧号=0CH → 物理地址 = **0CH × 1000H + 321H = C000H + 321H = C321H**

</details>

### 第 2 题 —— PV 操作（14 分）

三个同学合作实验：
- **A** 负责采集数据
- **B** 负责对 A 采集的数据做可视化
- **C** 负责对 A 采集的数据做分析
- **只有当 B 和 C 都完成当前批数据的处理，A 才能采集下一批**

请用信号量实现，给出信号量定义和伪代码。

<details>
<summary>答案与解析</summary>

#### 分析同步关系

这是一个**汇合（rendezvous）**同步模式：
- A 采集完后 → 通知 B 和 C 可以开始了
- B 和 C **都**完成后 → 通知 A 可以采集下一批

#### 信号量定义

```c
Semaphore ready = 0;    // A 采集完成，通知 B/C（初值 0 = 还没数据）
Semaphore doneB = 0;    // B 完成处理
Semaphore doneC = 0;    // C 完成处理
```

#### 伪代码

```c
// 同学 A：采集数据
Process_A() {
    while (1) {
        采集一批数据;
        V(ready);          // 通知 B：数据好了
        V(ready);          // 通知 C：数据好了（发两次，B/C 各取一次）
        P(doneB);          // 等 B 完成
        P(doneC);          // 等 C 完成
    }
}

// 同学 B：可视化
Process_B() {
    while (1) {
        P(ready);          // 等 A 的数据
        对数据进行可视化;
        V(doneB);          // 通知 A：B 完成了
    }
}

// 同学 C：分析
Process_C() {
    while (1) {
        P(ready);          // 等 A 的数据
        对数据进行分析;
        V(doneC);          // 通知 A：C 完成了
    }
}
```

#### 设计要点

- `ready` 初值 = 0，初态下没有数据，B/C 在 P(ready) 处阻塞
- A 执行 **两次 V(ready)**，唤醒 B 和 C
- A **必须等 B 和 C 都完成**（P(doneB) + P(doneC)）才进入下一轮
- 这个设计保证了"采集 → 并行处理 → 等两者都完成 → 下一轮"的严格顺序

</details>

### 第 3 题 —— 多级页表设计（10 分）

页面大小 4KB，页表项大小 16B。映射 32 位地址空间，**要求顶级页表能放入一页**。

**（1）**需要几级页表？（2分）  
**（2）**给出逻辑地址格式。（2分）  
**（3）**根页表基址 442368（十进制）。访问虚地址空间中**第 600 页内的第 20 个字节**，求逻辑地址和物理地址（十进制）。（6分）

<details>
<summary>答案与解析</summary>

#### （1）需几级页表？

- 页面大小 4KB = 2^12 B → 页内偏移 **12 位**
- 每页能放页表项数 = 4KB / 16B = 256 = 2^8 → 每级索引 **8 位**
- 32 位地址 − 12 位偏移 = 20 位用于索引
- 20 / 8 = 2.5 → 需要 **3 级页表**（前 2 级各 8 位，第 1 级 4 位）

或者：顶级页表必须在一页内 → 顶级页表最多 256 项 → 需要 8 位。但 20 位索引每级 8 位需要 3 级（8+8+4=20）。

等等，如果严格按照"每级放在一页内"，设级数为 k：
- 每级最多 2^8 项（256 项），每级用 8 位
- 32 = 12 + 8×(k-1) + r（最后一级可能不满 8 位）
- 20 = 8×(k-1) + r
- k=3：20=8×2+r=16+r → r=4 → 3 级，最后一级 4 位

**答案：3 级**

---

#### （2）逻辑地址格式

```
┌── 4位 ──┬── 8位 ──┬── 8位 ──┬── 12位 ──┐
│ Level 1 │ Level 2 │ Level 3 │ 页内偏移  │
│ (页目录)│ (页表)  │  (页)   │          │
└─────────┴─────────┴─────────┴──────────┘
```

---

#### （3）地址计算

**逻辑地址**：第 600 页内第 20 字节

逻辑地址 = 600 × 4096 + 20 = 2457600 + 20 = **2457620**（十进制）

**物理地址**：需要页表信息。

三级页表的每级索引：
- 逻辑地址 2457620 = 0x258014（十六进制）
- 页内偏移：2457620 mod 4096 = 20
- 页号 = 600

分解页号为三级索引（从高位到低位）：
- L1：600 / (256×256) = 600 / 65536 = 0
- L2：(600 mod 65536) / 256 = 600 / 256 = 2
- L3：600 mod 256 = 600 - 2×256 = 88

根页表基址 = 442368。L1=0 → 读地址 442368+0×16 = 442368 处的内容（得到二级页表地址）。

（由于没有给出具体的页表内容，物理地址无法完整计算。答题时需要根据题中提供的页表内容查表得到最终帧号。）

**物理地址 = 最终帧号 × 4096 + 20**

</details>
