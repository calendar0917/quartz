## 一、选择题（每小题 2 分，共 30 分）

**1.** 关于操作系统的基本特征，下列说法**错误**的是（ ）

A. 并发是指多个事件在同一时间间隔内发生  
B. 共享是指系统中的资源可供多个并发进程共同使用  
C. 虚拟是指通过某种技术把一个物理实体变为若干个逻辑上的对应物  
D. 异步性是指并发执行的程序每次执行必然会得到不同的结果  

<details>
<summary>答案与解析</summary>

**答案：D**

**逐项分析**：
- A：✅ 并发定义——同一时间**间隔**（不是同一时刻），宏观同时、微观交替。
- B：✅ 共享定义。分为互斥共享（临界资源）和同时共享（非临界资源）。
- C：✅ 虚拟定义。时分复用（虚拟CPU）和空分复用（虚拟内存）。
- D：❌ **异步性是指程序的执行过程具有不确定性**——何时执行、执行顺序、完成时间都不确定。但**不意味着结果一定不同**！正确的同步机制可以保证确定性结果。"必然"二字错了。

**考点**：OS 四大特征的精确定义。注意异步性 ≠ 结果不可再现（后者是由封闭性被破坏造成的）。

</details>

**2.** 在下列系统中，对响应时间要求最严格的是（ ）

A. 简单批处理系统  
B. 多道批处理系统  
C. 分时系统  
D. 硬实时系统  

<details>
<summary>答案与解析</summary>

**答案：D**

**核心区别**：
- 批处理系统：追求**吞吐量**最大化，不太关心单个作业的响应时间。
- 分时系统：追求**响应时间**短，但不能错过就出大问题。
- **硬实时系统**：必须在规定时间（deadline）内完成处理，错过 = 系统故障甚至灾难（如火箭控制、核电站）。

**注意**：软实时系统对响应时间也有要求，但偶尔错过可接受。硬实时是最严格的。

</details>

**3.** 某系统中有 3 个并发进程，都需要同类资源 4 个，则系统**不会**发生死锁的最少资源数是（ ）

A. 9  
B. 10  
C. 11  
D. 12  

<details>
<summary>答案与解析</summary>

**答案：B**

**推导公式**：n 个进程，每个最多需要 k 个同类资源，不发生死锁的最少资源数：

$$m \geq n \times (k-1) + 1$$

代入：n=3, k=4 → m ≥ 3×(4-1)+1 = 3×3+1 = **10**

**解释**：最坏情况是每个进程都拿了 k-1=3 个，都在等最后一个资源。此时再有 1 个资源，至少有一个进程能完成（拿到 4 个），完成后释放所有资源，其他进程就都能完成了。

如果 m=9，最坏情况下 3 个进程各拿 3 个共 9 个→全部阻塞→**死锁**。

</details>

**4.** 进程从阻塞态到就绪态的变化，其原因是（ ）

A. 进程被调度程序选中  
B. 等待的 I/O 操作完成  
C. 进程的时间片用完  
D. 有更高优先级的进程就绪  

<details>
<summary>答案与解析</summary>

**答案：B**

**关键状态转换**：
- 就绪 → 运行：被调度程序选中（A）
- 运行 → 就绪：时间片用完（C）或被抢占（D）
- 运行 → 阻塞：发起 I/O 请求，等待某事件
- **阻塞 → 就绪**：所等待的事件发生（I/O 完成、信号到达等）→ **B 正确**

**易混点**：A 是"就绪→运行"，不是"阻塞→就绪"。阻塞态进程不在就绪队列里，不能被直接调度。

</details>

**5.** 用户级线程（ULT）与内核级线程（KLT）的区别，以下说法**正确**的是（ ）

A. ULT 由操作系统内核调度和管理  
B. 一个 ULT 阻塞会导致整个进程的所有线程阻塞  
C. KLT 的线程切换不需要内核参与  
D. ULT 可以充分利用多处理器  

<details>
<summary>答案与解析</summary>

**答案：B**

**逐项分析**：
- A：❌ ULT 由**用户空间线程库**管理，内核不知道线程存在。
- B：✅ 内核以进程为单位调度。一个 ULT 调用阻塞式系统调用（如 read()）→内核看到"该进程阻塞"→进程内所有线程都停了。
- C：❌ KLT 的创建、撤销、切换都由**内核**完成，需要模式切换。
- D：❌ ULT 不能利用多处理器——内核只看到一个进程，只能调度到一个 CPU 上。

**记忆法**：ULT="线程在进程内部自己玩，内核啥都不知道"。

</details>

**6.** 在分页存储管理系统中，若页面大小为 4KB，逻辑地址为 0x3A2F，则页号是（ ）

A. 0x3  
B. 0xA  
C. 0x3A  
D. 0x2F  

<details>
<summary>答案与解析</summary>

**答案：A**

**推导**：页面大小 4KB = 2^12 → 页内偏移占低 12 位。

0x3A2F 写成二进制：
```
3    A    2    F
0011 1010 0010 1111
```

高 4 位 = 0011 = **0x3** = 页号  
低 12 位 = 1010 0010 1111 = 0xA2F = 页内偏移

**快速心算**：0x3A2F / 0x1000 = 0x3...0xA2F → 页号 = 3。

**页号计算公式**：P = 逻辑地址 ÷ 页面大小（整除），d = 逻辑地址 mod 页面大小。

</details>

**7.** 下列页面置换算法中，**不会**出现 Belady 异常的是（ ）

A. FIFO  
B. LRU  
C. 只有 OPT 不会  
D. LRU 和 OPT 都不会，但 CLOCK 可能会  

<details>
<summary>答案与解析</summary>

**答案：D**

**Belady 异常的充要条件**：算法不满足**栈属性**（即：页框数为 n 时驻留的页面集合，一定是页框数为 n+1 时驻留页面集合的子集）。

- **FIFO**：不满足栈属性 → **有 Belady 异常**
- **LRU**：满足栈属性 → 无 Belady 异常
- **OPT**：满足栈属性 → 无 Belady 异常
- **CLOCK**：是 LRU 的近似，**理论上不满足栈属性，存在 Belady 异常的可能**

所以选 D——LRU 和 OPT 不会，但 CLOCK 可能会（虽然实际中 CLOCK 的 Belady 异常较少见，但理论上存在）。

</details>

**8.** 关于 DMA 技术，以下描述**正确**的是（ ）

A. DMA 数据传输过程中 CPU 完全不参与  
B. DMA 控制器可以直接访问内存  
C. DMA 的数据传输单位是**字节**  
D. DMA 方式不需要中断技术支持  

<details>
<summary>答案与解析</summary>

**答案：B**

**逐项分析**：
- A：❌ DMA 传输期间 CPU 不参与**具体的数据移动**，但在传输开始（设置 DMA 寄存器）和传输结束（中断处理）时仍需参与。
- B：✅ DMA 控制器有内存地址寄存器(MAR)，可以直接通过总线读写内存。
- C：❌ DMA 的传输单位是**数据块**（block），不是字节。字节单位是中断驱动 I/O 的方式。
- D：❌ DMA 传输完成后通过**中断**通知 CPU。

</details>

**9.** 文件系统采用**隐式链接**分配方式时，其**主要缺点**是（ ）

A. 存在外部碎片  
B. 不支持文件动态增长  
C. 随机访问效率低  
D. 文件不能共享  

<details>
<summary>答案与解析</summary>

**答案：C**

**隐式链接的原理**：每个盘块末尾存一个指针指向下一块。目录项只记首块号。

- 要读第 100 块 → 必须从第 1 块开始，跟着指针链走 100 次 → **随机访问极慢**。
- 隐式链接**无外部碎片**（A 错），**支持动态增长**（B 错）。FAT（显式链接）解决了随机访问慢的问题——把所有指针集中到内存中的 FAT 表。

</details>

**10.** 某系统采用二级页表，页大小为 4KB，每个页表项 4B，顶级页表的每一项能覆盖的逻辑地址空间大小为（ ）

A. 1MB  
B. 2MB  
C. 4MB  
D. 8MB  

<details>
<summary>答案与解析</summary>

**答案：C**

**推导**：
- 一页能放多少页表项 = 4KB / 4B = 1024 = 2^10 个
- 每个二级页表项覆盖一个页面 = 4KB
- 顶级页表的**一个**表项指向一个二级页表，该二级页表能映射 2^10 个页面
- 覆盖空间 = 2^10 × 4KB = 2^10 × 2^12 B = 2^22 B = **4MB**

**公式**：每级页表项覆盖的空间 = 页面大小 × (页面大小/页表项大小)^(级数-1)

</details>

**11.** 某文件系统采用索引分配，盘块大小为 1KB，每个盘块号占 4B。若一个索引结点包含 10 个直接块、1 个一级间接块、1 个二级间接块，则该文件系统支持的**最大文件大小**约为（ ）

A. 10KB + 256KB + 64MB  
B. 10KB + 256KB + 64GB  
C. 10KB + 1024KB + 1MB  
D. 10KB + 4MB + 4GB  

<details>
<summary>答案与解析</summary>

**答案：A**

**推导**：
- 一个索引块能放的盘块号数 = 1KB / 4B = 256 个
- **直接块**：10 × 1KB = **10KB**
- **一级间接**：1 个索引块 → 256 个盘块 → 256 × 1KB = **256KB**
- **二级间接**：1 个索引块 → 256 个一级索引块 → 256 × 256 个盘块 → 256² × 1KB = 65536KB = **64MB**

**总计** = 10KB + 256KB + 64MB ≈ 64.26MB

**典型 UNIX i-node 结构**就是这个设计——小文件用直接块（快），大文件用间接块（容量大）。

</details>

**13.** 在请求分页系统中，"抖动"现象发生的原因是（ ）

A. 页面置换算法选择不当  
B. 多道程序度过高，分配给每个进程的物理块太少

**15.** 关于 SPOOLing 技术，下列说法**错误**的是（ ）

A. SPOOLing 可以将独占设备改造为共享设备  
B. SPOOLing 利用磁盘作为缓冲  
C. SPOOLing 可以缩短作业的执行时间  
D. SPOOLing 需要输入进程和输出进程  

<details>
<summary>答案与解析</summary>

**答案：C**

**SPOOLing 的原理**：
- 进程的 I/O 数据先写到磁盘（输入/输出井）
- 由 SPOOLing 管理进程统一调度实际 I/O
- 对进程而言，"看起来"独占设备变成了共享设备

**C 错在哪**？SPOOLing 确实让多个进程"同时"使用独占设备（如打印机），免去了排队等待，减少了**等待时间**。但说"缩短执行时间"不准确——执行时间（纯计算时间）是不变的，变的是**周转时间**中的等待部分。

</details>

**1.** 在动态分区分配中，首次适应算法要求空闲分区链按 \\_\\_\\_\\_ 递增的顺序排列。

<details>
<summary>答案与解析</summary>

**答案：地址**

首次适应(FF)：从低地址开始找，第一个够大的就分配。要求空闲分区链按**地址**从低到高排列。

区别于最佳适应(BF)——按**容量**从小到大排列；最差适应(WF)——按**容量**从大到小排列。

**2.** 信号量的物理意义：S.value > 0 表示有 S.value 个 \\_\\_\\_\\_ ，S.value < 0 表示有 |S.value| 个 \\_\\_\\_\\_ 。

<details>
<summary>答案与解析</summary>

**答案：可用资源；等待进程**

- S.value > 0：还有多少个资源可以分配
- S.value = 0：资源刚好用完，没人等
- S.value < 0：资源没了，|S.value| 个进程在信号量队列中等待

**3.** 磁盘访问时间 = 寻道时间 + \\_\\_\\_\\_ + 传输时间。

<details>
<summary>答案与解析</summary>

**答案：旋转延迟时间 / 旋转延迟**

三大组成部分：
1. **寻道时间**：磁头移动到目标磁道的时间（最慢，主要优化目标）
2. **旋转延迟时间**：等待目标扇区旋转到磁头下方（平均 = 半圈时间）
3. **传输时间**：数据读/写的时间（通常最小）

</details>

**4.** 文件控制块（FCB）中保存的物理地址信息通常是 \\_\\_\\_\\_ 号或 \\_\\_\\_\\_ 号。

<details>
<summary>答案与解析</summary>

**答案：盘块（或 起始盘块）；索引结点 / i-node**

在连续分配中，FCB 存(起始盘块号, 文件长度)。
在链接分配中，FCB 存首盘块号。

**5.** 虚拟存储器的最大容量由 \\_\\_\\_\\_ 决定，实际容量由 \\_\\_\\_\\_ 和 \\_\\_\\_\\_ 之和决定。

<details>
<summary>答案与解析</summary>

**答案：计算机地址结构（CPU 寻址范围）；内存容量；外存容量**

## 三、分析计算题（共 34 分）

### 第 1 题（10 分）

一个多道批处理系统中有四个作业 J1、J2、J3、J4，它们的到达时间和服务时间如下：

| 作业 | 到达时间 | 服务时间 |
|------|---------|---------|
| J1 | 0 | 5 |
| J2 | 3 | 2 |
| J3 | 5 | 8 |
| J4 | 7 | 3 |

**（1）** （5分）采用**最短剩余时间优先（SRT）**调度算法，画出调度的甘特图（时间轴），标注每个作业的开始和结束时间，并计算四个作业的**平均周转时间**。

**（2）** （5分）采用**最高响应比优先（HRRN）**调度算法，列出每次调度时的响应比计算过程，并计算四个作业的**平均带权周转时间**。

<details>
<summary>答案与解析</summary>

#### （1）SRT 调度

**SRT 规则**：当前进程执行中，每当新进程到达，比较新进程的服务时间与当前进程的**剩余时间**。谁剩余时间短谁上 CPU。

**逐时刻推导**：

```
t=0: J1到达，就绪=[J1(5)]。执行J1
t=3: J2到达(需2)。J1剩余 5-3=2。比较：J2需2 = J1剩2 → 通常选择新来的或先来的（此处J2服务时间=J1剩余时间，选择J1继续或J2抢占差别不大，按课件惯例选先到的J1继续）→ J1继续
      实际按SRT严格规则：剩余时间相等时选先到达的。J1先到达，J1继续。
t=5: J1完成✓，J3到达(需8)。就绪=[J2(2), J3(8)]。J2更短(2<8)→执行J2
t=7: J2完成✓，J4到达(需3)。就绪=[J3(8), J4(3)]。J4更短(3<8)→执行J4
t=10: J4完成✓。就绪=[J3(8)]→执行J3
t=18: J3完成✓
```

等等，让我严格按照 SRT 来重新推。每次新进程到达时刻都要检查抢占。

```
t=0: J1开始执行，J1剩5。
t=3: J2到达(需2)。J1剩5-3=2。J2需2 ≥ J1剩2，两个一样→不抢占，J1继续。
t=5: J1完成（J1完成时间=5）。此时J3到达(需8)。就绪=[J2(2,J2t=3到的), J3(8)]。
     最短：J2(2)<J3(8)→执行J2。
t=7: J2完成（J2完成时间=7）。J4到达(需3)。就绪=[J3(8), J4(3)]。
     最短：J4(3)<J3(8)→执行J4。
t=10: J4完成（J4完成时间=10）。就绪=[J3(8)]→执行J3。
t=18: J3完成（J3完成时间=18）。
```

**甘特图**：
```
0────5──7────10────────18
  J1   J2   J4      J3
```

**统计**：

| 作业 | 到达 | 服务 | 完成 | 周转=完成-到达 | 带权=周转/服务 |
|------|------|------|------|----------------|----------------|
| J1 | 0 | 5 | 5 | 5 | 1.00 |
| J2 | 3 | 2 | 7 | 4 | 2.00 |
| J3 | 5 | 8 | 18 | 13 | 1.625 |
| J4 | 7 | 3 | 10 | 3 | 1.00 |

**平均周转时间 = (5+4+13+3)/4 = 25/4 = 6.25**

#### （2）HRRN 调度

**HRRN 规则**：每次选择时，计算每个就绪进程的响应比 R = (等待时间+服务时间)/服务时间，选 R 最大的。

```
t=0: 就绪=[J1]→执行J1
t=5: J1完成。就绪=[J2(已在t=3到达), J3(t=5到达)]
      J2: 等待=5-3=2, R=(2+2)/2=2.00
      J3: 等待=5-5=0, R=(0+8)/8=1.00
      → J2的R更高→执行J2

t=7: J2完成。就绪=[J3(t=5), J4(t=7)]
      J3: 等待=7-5=2, R=(2+8)/8=1.25
      J4: 等待=7-7=0, R=(0+3)/3=1.00
      → J3的R更高→执行J3

t=15: J3完成。就绪=[J4(t=7)]→执行J4
t=18: J4完成
```


### 第 2 题（12 分）

系统有 R1、R2、R3 三类资源，总数分别为 8、4、6。在 T0 时刻资源分配情况如下：

| 进程 | Max(R1,R2,R3) | Allocation(R1,R2,R3) |
|------|---------------|---------------------|
| P1 | 4,2,2 | 1,0,0 |
| P2 | 5,1,1 | 3,1,0 |
| P3 | 2,1,3 | 2,0,2 |
| P4 | 3,2,3 | 0,1,2 |

**（1）**（4分）计算 T0 时刻的 Need 矩阵和 Available 向量。

**（2）**（4分）T0 时刻系统是否安全？若是，请给出一个安全序列。

**（3）**（4分）若 P1 请求资源 (1,0,1)，该请求能否被立即满足？请用银行家算法说明。

<details>
<summary>答案与解析</summary>

#### （1）计算 Need 矩阵和 Available

**Need = Max - Allocation**：

| 进程 | Need(R1,R2,R3) |
|------|----------------|
| P1 | 4-1, 2-0, 2-0 = (3,2,2) |
| P2 | 5-3, 1-1, 1-0 = (2,0,1) |
| P3 | 2-2, 1-0, 3-2 = (0,1,1) |
| P4 | 3-0, 2-1, 3-2 = (3,1,1) |

**Available** = 总量 - 已分配总和：
- R1: 8 - (1+3+2+0) = 2
- R2: 4 - (0+1+0+1) = 2
- R3: 6 - (0+0+2+2) = 2

**Available = (2,2,2)**

---

#### （2）安全性检查

**Work = Available = (2,2,2)**

| 轮次 | 候选进程 | 检查 Need ≤ Work | 选取 | 释放 Allocation | 新 Work |
|------|---------|-------------------|------|-----------------|---------|
| 1 | P1(3,2,2) | ❌ 3>2 | — | — | — |
| 1 | P2(2,0,1) | ✅ 2≤2,0≤2,1≤2 | **P3**(0,1,1)更优 | (2,0,2) | (4,2,4) |

等等，我应该按顺序检查。让我重新做：

**轮次1**：Work=(2,2,2)
- P1: Need(3,2,2) → 3>2 ❌
- P2: Need(2,0,1) → ✅ 全 ≤ Work
- **选 P2**。P2 完成，释放(3,1,0)。Work = (2+3, 2+1, 2+0) = **(5,3,2)**

**轮次2**：Work=(5,3,2)
- P1: Need(3,2,2) → ✅
- P3: Need(0,1,1) → ✅
- P4: Need(3,1,1) → ✅
- 任选一个。**选 P1**。释放(1,0,0)。Work = (5+1, 3+0, 2+0) = **(6,3,2)**

**轮次3**：Work=(6,3,2)
- P3: Need(0,1,1) → ✅
- P4: Need(3,1,1) → ✅
- **选 P3**。释放(2,0,2)。Work = (6+2, 3+0, 2+2) = **(8,3,4)**

**轮次4**：Work=(8,3,4)
- P4: Need(3,1,1) → ✅
- **选 P4**。释放(0,1,2)。Work = (8+0, 3+1, 4+2) = **(8,4,6)**

✅ 全部 Finish=true。**安全序列**：**P2 → P1 → P3 → P4**（不唯一，P2→P3→P1→P4 也可）

---

#### （3）P1 请求 (1,0,1)

**Step 1**：P1 请求 (1,0,1) 
- Request ≤ Need(3,2,2)? (1,0,1) ≤ (3,2,2) ✅
- Request ≤ Available(2,2,2)? (1,0,1) ≤ (2,2,2) ✅

**Step 2**：试探分配：
- Available = (2-1, 2-0, 2-1) = (1,2,1)
- Allocation_P1 = (1+1, 0+0, 0+1) = (2,0,1)
- Need_P1 = (3-1, 2-0, 2-1) = (2,2,1)

**Step 3**：安全性检查（Work = (1,2,1)）

| 轮次 | 检查 | 选取 | 新 Work |
|------|------|------|---------|
| 1 | P1(2,2,1)→2>1 ❌, P2(2,0,1)→2>1 ❌, P3(0,1,1)→✅ | **P3** | (3,2,3) |
| 2 | P1(2,2,1)→✅, P2(2,0,1)→✅, P4(3,1,1)→✅ | **P2** | (6,3,3) |
| 3 | P1(2,2,1)→✅, P4(3,1,1)→✅ | **P1** | (8,3,4) |
| 4 | P4(3,1,1)→✅ | **P4** | (8,4,6) 

✅ 安全序列：P3→P2→P1→P4

**结论**：可以立即满足 P1 的请求 (1,0,1)。

### 第 3 题（12 分）

某磁盘参数：转速 5400 rpm（转/分），平均寻道时间 6ms，每个磁道 400 个扇区，每个扇区 512B。相邻两个扇区组成一个块（block）。假设每个文件大小固定为 200KB。

**（1）**（3分）磁盘的旋转延迟为多少 ms？每个块的传输延迟为多少 ms？

**（2）**（4分）文件如何存放**访问最快**？此时读取该文件需要多少 ms？

**（3）**（5分）文件如何存放**访问最慢**？此时读取该文件需要多少 ms（不考虑文件系统元数据开销）？

<details>
<summary>答案与解析</summary>

#### （1）旋转延迟和传输延迟

**旋转延迟（平均）** = 转一圈时间 / 2
- 5400 rpm = 5400/60 = 90 转/秒
- 每转时间 = 1/90 秒 = 1000/90 ms ≈ **11.11ms**
- 平均旋转延迟 = 11.11/2 ≈ **5.56ms**

**每块传输延迟**：
- 每个扇区 512B，每 2 扇区组成 1 块 = 1024B = 1KB
- 每圈 400 扇区 = 200 块
- 每块传输时间 = 每转时间 / 每转块数 = 11.11ms / 200 ≈ **0.056ms**

---

#### （2）最快存放方式

**最快方式**：文件存放在**同一磁道的连续扇区**中。

原因：只需一次寻道 + 一次旋转延迟，然后连续读。

- 文件大小 200KB = 200 块（每块 1KB）
- 所需扇区 = 200 × 2 = 400 扇区 = **恰好一个磁道**

**访问时间** = 寻道时间 + 旋转延迟 + 传输时间
= 6ms + 5.56ms + 200 × 0.056ms
= 6 + 5.56 + 11.11
= **22.67ms**

（注意：200块恰好等于一个磁道的块数，所以传输时间 = 一整圈时间 = 11.11ms）

---

#### （3）最慢存放方式

**最慢方式**：文件的每个块都在不同磁道上，且随机分布。

每次读一个块都需要：寻道 + 旋转延迟 + 传输。

200 个块：

总时间 = 200 × (6ms + 5.56ms + 0.056ms)
= 200 × 11.616ms
= **2323.2ms ≈ 2.32秒**

**对比**：最慢比最快慢了约 **100 倍**！

这就是为什么文件系统会尽量把文件分配在连续的盘块上，以及为什么需要磁盘碎片整理。

</details>

### 第 1 题（14 分）—— PV 操作设计

某实验室有一台贵重仪器，3 位学生都需要使用。但是仪器每次只能容纳 2 人同时操作，并且实验操作规程要求"使用前需登记，使用后需注销"。

**请用信号量实现同步互斥**：
- （1）给出信号量定义及初值（3分）
- （2）用伪代码描述每个学生的工作流程（8分）
- （3）说明你的方案如何防止"超过 2 人同时使用"（3分）

<details>
<summary>答案与解析</summary>

#### 分析

**约束条件**：
1. 仪器最多容纳 2 人 → 这是一个**计数互斥**（不是二元互斥）
2. 登记本一次只能一个人写 → 对登记本的访问是**二元互斥**

#### （1）信号量定义

```c
Semaphore capacity = 2;   // 仪器容量（最多2人），计数互斥
Semaphore register = 1;   // 登记本互斥
```

#### （2）学生工作流程

```c
Student_i() {
    // ===== 进入实验室 =====
    P(capacity);           // ① 申请仪器名额（超过2人则阻塞）
    
    P(register);           // ② 申请登记本
    在登记本上登记信息;
    V(register);           // ③ 归还登记本
    
    // ===== 使用仪器 =====
    操作仪器（可同时2人）;
    
    // ===== 离开实验室 =====
    P(register);           // ④ 申请登记本
    在登记本上注销信息;
    V(register);           // ⑤ 归还登记本
    
    V(capacity);           // ⑥ 释放仪器名额，让下一个同学进入
}
```

#### （3）防止超过 2 人的机制

`capacity` 信号量初值 = 2。每次学生进入前执行 P(capacity)：

- 第 1 个学生：capacity.value 从 2→1，进入
- 第 2 个学生：capacity.value 从 1→0，进入
- 第 3 个学生：capacity.value 从 0→**-1**，**Block！** 挂在 capacity.L 等待队列

直到前 2 个学生中有 1 人离开并执行 V(capacity)，capacity.value 从 -1→0，唤醒第 3 个学生。

**关键**：capacity 用**记录型信号量**（不是整型信号量）。capacity.value < 0 时，|value| = 等待队列中的学生数。

</details>

### 第 2 题（12 分）—— 请求分页 + 页面置换

某请求分页系统，页面大小 4KB。某进程的驻留集固定为 3 个页框，页表如下：

| 页号 | 页框号 | 有效位 | 访问位 | 修改位 |
|------|--------|--------|--------|--------|
| 0 | 7 | 1 | 1 | 1 |
| 1 | — | 0 | — | — |
| 2 | 4 | 1 | 1 | 0 |
| 3 | 9 | 1 | 0 | 1 |

当前 CLOCK 指针指向页框 4（即 2 号页）。

接下来进程依次访问以下虚拟地址（十六进制）：**0x2A3C, 0x1F00, 0x3D80, 0x28B4**

**（1）**（4分）采用 **CLOCK 置换算法**，写出每次访问后的驻留集变化（含访问位和修改位），并计算缺页中断次数。

**（2）**（4分）经过上述访问后，虚拟地址 0x28B4 对应的物理地址是多少（十六进制）？

**（3）**（4分）若将 CLOCK 改为 **改进型 CLOCK**（同时考虑访问位 A 和修改位 M），在处理 0x28B4 之前的缺页时，淘汰过程和 CLOCK 有何不同？结果一样吗？

<details>
<summary>答案与解析</summary>

#### 初始状态

驻留集：页0(帧7, A=1, M=1)、页2(帧4, A=1, M=0)、页3(帧9, A=0, M=1)
指针指向帧4（页2）。页1不在内存。

#### （1）逐地址推导

**访问 0x2A3C**：
- 0x2A3C / 0x1000(4KB) = 2...A3C → 页号=2
- 页2在内存(帧4)→**命中**！A置1（已为1不变）。指针不移动。
- 驻留集不变。

**访问 0x1F00**：
- 0x1F00 / 0x1000 = 1...F00 → 页号=1
- 页1不在内存→**缺页中断**！

**CLOCK 淘汰过程**：
指针在帧4（页2, A=1）：
```
帧4: 页2, A=1 → 置A=0，指针移到帧7
帧7: 页0, A=1 → 置A=0，指针移到帧9
帧9: 页3, A=0 → 找到！淘汰页3！
```
装入页1到帧9，A=1, M=0。指针移到帧4。

新驻留集：页0(帧7, A=0, M=1)、页2(帧4, A=0, M=0)、页1(帧9, A=1, M=0)

**缺页次数：1**

**访问 0x3D80**：
- 0x3D80 / 0x1000 = 3...D80 → 页号=3
- 页3不在内存（刚被淘汰）→**缺页中断**！

**CLOCK 淘汰过程**：
指针在帧4（页2, A=0）：
```
帧4: 页2, A=0 → 找到！淘汰页2！
```
装入页3到帧4，A=1, M=1（访问就是读，但访问本身不改M，假定初始M=0，但后面会改...以此题初始来看M=1是因为被换出时要写回，这里先标一致的）。实际装入时 A=1, M=0。指针移到帧7。

新驻留集：页0(帧7, A=0, M=1)、页3(帧4, A=1, M=0)、页1(帧9, A=1, M=0)

**缺页次数：2**

**访问 0x28B4**：
- 0x28B4 / 0x1000 = 2...8B4 → 页号=2
- 页2不在内存→**缺页中断**！

**CLOCK 淘汰过程**：
指针在帧7（页0, A=0）：
```
帧7: 页0, A=0 → 找到！淘汰页0！
```
页0的 M=1 → 需要写回磁盘（修改过）。

装入页2到帧7，A=1, M=0。指针移到帧4。

**缺页次数：3**

---

#### （2）0x28B4 对应的物理地址

经过上述访问后，页2在帧7。

0x28B4：
- 页号 = 0x28B4 / 0x1000 = 2
- 偏移 = 0x28B4 % 0x1000 = 0x8B4

物理地址 = 帧号 × 页面大小 + 偏移 = 7 × 0x1000 + 0x8B4 = 0x7000 + 0x8B4 = **0x78B4**

---

#### （3）改进型 CLOCK 的区别

改进型 CLOCK 的淘汰优先级：**(0,0) > (0,1) > (1,0) > (1,1)**

对于访问 0x28B4 之前的状态（页0: A=0,M=1; 页3: A=1,M=0; 页1: A=1,M=0）：

**普通 CLOCK**：扫描到 A=0 就淘汰→淘汰页0。

**改进型 CLOCK**：
- 第 1 遍扫描：找 (A=0, M=0) → 没有
- 第 2 遍扫描：找 (A=0, M=1)，同时把扫描过的 A 置 0
  - 帧7(页0): (A=0, M=1)→找到！淘汰页0！

**结果一样**——都淘汰页0。但改进型 CLOCK 优先避免了淘汰干净页面（既未访问又未修改的优先于未访问但修改的），减少了不必要的磁盘写入。

</details>

### 第 3 题（附加题·选做，不计入总分）

考虑一个 32 位虚拟地址空间，页面大小 8KB，页表项大小为 8B。

**（1）** 若采用一级页表，页表有多大？能放在一个页框里吗？

**（2）** 若采用多级页表，要求每级页表都能放在一个页面内，需要几级？画出逻辑地址格式。

<details>
<summary>答案与解析</summary>

#### （1）一级页表分析

- 地址空间 = 2^32 B
- 页面大小 = 8KB = 2^13 B
- 页数 = 2^32 / 2^13 = 2^19 页
- 页表项 = 2^19 项
- 页表大小 = 2^19 × 8B = 2^22 B = **4MB**

一个页面 = 8KB = 2^13 B，页表 4MB >> 8KB，**放不下**。而且还需要 4MB 的连续物理内存。

#### （2）多级页表设计

每页能放多少页表项 = 8KB / 8B = 1024 = 2^10 项。

设需要 k 级页表。每级用 10 位索引（因为每级正好 2^10 项）。
- 第 1 级：页目录
- 最后一级：页内偏移 = 13 位（8KB 页面）

总位数 = 10×(k-1) + 13 = 32 → 10k + 3 = 32 → 10k = 29 → k ≈ 2.9

所以需要 **3 级页表**。但实际用几级取决于怎么分配位数。更实际的是：

- 实际页表项可能不正好 2^10（虽然此题是），但第一级可以放更少：
  - 2^19 个页表项 → 需要 2^19 / 2^10 = 2^9 = 512 个二级页表
  - 顶级页表只需 512 项 → 9 位
  
**逻辑地址格式**（二级页表方案）：
```
┌───── 9位 ─────┬───── 10位 ─────┬───── 13位 ─────┐
│   页目录号     │    页表号      │    页内偏移     │
└───────────────┴────────────────┴─────────────────┘
```

顶级页表占 512 项 × 8B = 4096B < 8KB，能放进一个页面 ✅

</details>
