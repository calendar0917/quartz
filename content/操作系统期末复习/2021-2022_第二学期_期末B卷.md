**1.** 操作系统是一组（ ）

A、应用程序  
B、设备驱动程序  
C、系统程序  
D、工具软件  

<details>

**2.** 关于进程的描述，**错误**的是（ ）

A、进程是程序的一次执行  
B、进程可以并发执行  
C、进程是资源分配的基本单位  
D、进程是 CPU 调度的基本单位  

<details>
<summary>答案与解析</summary>

**答案：D**

在引入线程的现代操作系统中，**线程是 CPU 调度的基本单位**，进程是**资源分配的基本单位**。

但在某些语境下（传统的单线程进程模型），进程也是调度的单位。但在标准教材中：
- 进程 = 资源分配单位
- 线程 = CPU 调度单位

所以 D 在严格意义上错了。

</details>

**3.** 关于信号量的描述，**错误**的是（ ）

A、信号量是一个整型变量  
B、P 操作和 V 操作是原子操作  
C、信号量只能用于进程同步  
D、信号量初值可以为负数  

<details>
<summary>答案与解析</summary>

**答案：C 和 D 都错**（题目选最明显的）

- D ❌：记录型信号量初值不能为负——初值为负意味着初始就有进程在等，这不合理。

**最佳答案：C**——这是明确的错误陈述。

</details>

**4.** 产生死锁的四个必要条件中，（ ）可以通过破坏来预防死锁。

A、互斥条件  
B、请求与保持条件  
C、不可剥夺条件  
D、循环等待条件  

<details>
<summary>答案与解析</summary>

**答案：B, C, D 都可破坏。**

但题目可能暗示"哪个最容易被破坏"：
- B（请求与保持）：一次性申请所有资源 → 最常用
- C（不可剥夺）：抢占机制 → 复杂
- D（循环等待）：有序分配 → 也常用
- A：互斥是资源固有属性，难以破坏（除非用 SPOOLing 虚拟化）

通常教材中回答"请求与保持条件"最容易被破坏。但严格来说三个都能破坏。此处按课件强调的：**B**（一次性申请全部资源）。

</details>

**10.** I/O 控制方式的发展过程中，（ ）方式使得 CPU 与 I/O 设备可以并行工作。

A、程序查询  
B、中断  
C、DMA  
D、通道  

<details>
<summary>答案与解析</summary>

### 第 1 题（10 分）—— 段式地址转换

逻辑地址结构：段号 18bit + 段内地址 14bit。

| 段号 | 段长 | 基址 |
|------|------|------|
| 0 | 8K | 40K |
| 1 | 5K | 105K |
| 2 | 3K | 10K |
| 3 | 2K | 5K |
| 4 | 10K | 200K |

逻辑地址 0x10070H，求段号、是否越界、段内偏移、物理地址。

<details>
<summary>答案与解析</summary>

**Step 1：提取段号和偏移**

逻辑地址 = 0x10070H = 0001 0000 0000 0111 0000（20位十六进制）

段号占 18 位 + 偏移 14 位 = 32 位 = 8 位十六进制。

0x10070H → 写成 8 位十六进制 = 0x00010070H。

高 18 位 = 段号。0x00010070H >> 14 = 0x00010070 / 0x4000 = ?

0x00010070 = 65536 + 112 = 65648 十进制。

14 位 = 2^14 = 16384 = 0x4000

段号 = 0x10070 / 0x4000 = 0x00010070H / 0x4000H = 0x40H / 4H？不，0x00010070H 的高 18 位...

更简单：0x00010070H 的二进制（32位完整格式）：
0000 0000 0000 0001 0000 0000 0111 0000  
←18位段号→ ←14位偏移→
段号 = (0000 0000 0000 0001 00)₂ = 0x4  
偏移 = (00 0000 0111 0000)₂ = 0x0070

实际上：
0x10070H = 65648₁₀
页内偏移 14 位 = 16384  
段号 = 65648 / 16384 = 4（整除）
段内偏移 = 65648 - 4×16384 = 65648 - 65536 = 112 = 0x70H

**段号 = 4，偏移 = 0x70 = 112**

**越界检查**：段 4 的段长 = 10K = 10240。偏移 112 ≤ 10240 ？ ✅ **不越界**。

**物理地址** = 基址 200K + 112 = 204800 + 112 = **204912** = **0x32070H**

</details>

200 柱面 0~199，磁头刚完成 91 号。请求：190, 97, 90, 54, 180, 30, 166, 108。

SSTF 和 SCAN 的总寻道距离。

反向：90(109)→54(36)→30(24)

总寻道 = 6+11+58+14+10+9+109+36+24 = **277**

### 第 3 题（10 分）—— 互斥算法安全性分析

```c
int flag[2] = {FALSE, FALSE};

Enter(int i) {
    while (flag[1-i]);     // 检查对方
    flag[i] = TRUE;        // 设自己
}

Leave(int i) {
    flag[i] = FALSE;
}
```

这个算法安全吗？为什么？

<details>
<summary>答案与解析</summary>

**不安全！**

**问题**：检查和设置不是原子操作。假设以下时序：

```
P0: 执行 while(flag[1]) → flag[1]=FALSE → 跳出循环
P1: 执行 while(flag[0]) → flag[0]=FALSE → 跳出循环
P0: flag[0]=TRUE  → 进入临界区
P1: flag[1]=TRUE  → 进入临界区
```

**两个进程同时进入临界区！违反了"忙则等待"准则。**

**根本原因**：`while(flag[1-i])` 检查和 `flag[i]=TRUE` 设置之间有一个**时间窗口**，在这期间另一个进程也可能通过检查。

**正确做法**：应该**先设自己的 flag，再检查对方**——但那样也有死锁问题（第三次尝试）。真正安全的是 Peterson 算法或硬件原子指令（TSL）。

</details>

Cache 命中率 0.9（20ns）。Cache 未命中但内存命中率 0.6（需 60ns 载入 Cache 后重新定位）。不在内存则需 12ms（磁盘）+ 60ns 复制到 Cache。求平均时间。

<details>

### 第 5 题（10 分）—— 页面置换 FIFO vs LRU

7 个页面，工作集=4（初始已装入 1,2,3,6）。访问序列：1,2,3,6,4,7,3,2,1,4,7,5,6,5,2,1。

求 FIFO 和 LRU 的缺页次数和最终留驻。

<details>
<summary>答案与解析</summary>

同第一学期卷第 4 题。

**FIFO**：缺页 **6 次**，最终留驻 [2,1,5,6]  
**LRU**：缺页 **10 次**，最终留驻 [6,5,2,1]

在这个特定序列中，FIFO 反而比 LRU 表现更好——因为该序列有循环回访（1→2→3→6→4→7 后又回到 1,2），FIFO 的"先进先出"恰好符合这个访问模式。

</details>
