# 第2章 进程描述与控制 —— "正在运行的程序"到底是什么

---

## 2.0 一个核心问题贯穿全章

> 多个程序在同一个CPU上"同时"运行，CPU怎么知道当前该执行谁、之前执行到哪了、下次从哪继续？

答案就在**进程**这个概念里。进程不是程序本身——程序是死的（磁盘上的代码），进程是活的（CPU上的执行实例）。

**先记住这个等式**：

```
进程 = 程序代码 + 数据 + PCB + 栈
```

PCB (Process Control Block) 是进程的"身份证"，记录了"我是谁、我在哪、我跑到哪里了"。

---

## 2.1 为什么要有"进程"这个概念？

### 问题的起源

在没有多道程序设计之前，程序是**顺序执行**的，一切都很简单：
- 顺序性：一条条按顺序跑
- 封闭性：程序独占所有资源，执行结果不受外界影响
- 可再现性：同样的输入永远得到同样的输出

**引入并发后，世界变复杂了**：

两个进程P1和P2共享变量x（初值=1），P1做 x=x+1，P2做 x=x-1。最后x是多少？

```asm
P1: load R1, x    // R1 = 1
    inc  R1        // R1 = 2
    store x, R1    // x = 2

P2: load R2, x    // R2 = ?
    dec  R2
    store x, R2
```

取决于执行交错顺序，结果可能是**0、1 或 2**。

**并发执行的三大特征**：
- **间断性**：走走停停（被调度打断）
- **失去封闭性**：共享资源被多进程改变
- **不可再现性**：同样环境可能得到不同结果

→ 需要一个机制来"描述"和"控制"每个并发执行的实体 → **进程**

---

## 2.2 进程的"身份证"——PCB里有什么？

PCB存在的理由很简单：当进程被切换出去时，OS要知道"它之前跑到了哪里、用了哪些资源"，下次切回来才能继续。

**PCB = 进程存在的唯一标志**。PCB被回收了，进程就死了。

### PCB里的三类信息

```
┌─────────────────────────────────────┐
│           进程控制块(PCB)             │
├─────────────────────────────────────┤
│ ① 进程标识符                          │
│    - 内部ID（OS用的整数）              │
│    - 父进程ID                         │
│    - 用户ID                           │
├─────────────────────────────────────┤
│ ② 处理机状态信息（上下文）             │
│    - 通用寄存器内容                    │
│    - 程序计数器 PC (下一条指令地址)     │
│    - 程序状态字 PSW (条件码/模式等)     │
│    - 栈指针                           │
├─────────────────────────────────────┤
│ ③ 进程控制信息                        │
│    - 进程状态和优先级                   │
│    - 等待事件（阻塞原因）               │
│    - 链接指针（队列组织）               │
│    - 进程间通信字段（信号量、消息队列）  │
│    - 页表/段表指针                     │
│    - 资源清单（打开的文件、I/O设备等）   │
└─────────────────────────────────────┘
```

**理解关键**：第②类是"切换时保存/恢复"的核心——你要把CPU寄存器的内容存下来，下次才知道PC应该指向哪里。

## 2.3 进程状态转换：一张图吃透

### 三状态模型（基础）

```
         ┌──────────┐
  创建──→│   就绪   │←─────┐
         └────┬─────┘      │
              │ 被调度     │ 时间片完/被抢占
              ↓            │
         ┌────┴─────┐      │
         │   执行   │──────┘
         └────┬─────┘
              │ 等待某事件（I/O等）
              ↓
         ┌────┴─────┐
         │   阻塞   │──────→ (事件发生后回到就绪)
         └──────────┘
```

**三个状态的核心理解**：

| 状态 | 缺什么 | 类比 |
|------|--------|------|
| 就绪 | 只缺CPU | 拿到票了，等叫号 |
| 执行 | 什么都不缺 | 正在服务中 |
| 阻塞 | 缺某事件（如I/O完成） | 去上厕所了，回来继续等叫号 |

### 关键辨析

**Q: 就绪能直接变成阻塞吗？**
不能。就绪状态没拿到CPU，你什么都没干怎么就阻塞了？必须先拿到CPU（变成执行），然后在执行中发起I/O请求，才进入阻塞。

**Q: 执行变就绪只有时间片完一种情况吗？**
不是。也可能被更高优先级的进程**抢占**。

**Q: 单CPU系统中可以多个进程处于执行状态吗？**
不能。单CPU任何时刻只有一条指令在执行，所以最多只有一个进程处于执行状态。

### 五状态模型

加上两个"边缘"状态：

```
新建 ──→ 就绪 ⇄ 执行 ──→ 终止
              ↕
             阻塞
```

- **新建**：PCB已建好，但还没被允许进入内存执行（OS还在准备）
- **终止**：进程执行完毕，PCB暂时保留（父进程可能要查子进程的结束状态）

### 挂起状态——内存不够用了怎么办？

**问题的根源**：所有进程都在等I/O，CPU闲着，但内存装满了阻塞的进程。

**解决方案**：把一些暂时跑不了的进程**换出到磁盘**，腾出内存给能跑的进程。

**阻塞 vs 挂起的关键区别**：

| | 阻塞(Blocked) | 挂起(Suspended) |
|--|---------------|-----------------|
| 本质问题 | 在**等事件** | 被**换出内存** |
| 位置 | 在内存中 | 在磁盘上 |
| 被谁操作 | 进程自己block自己 | OS或父进程挂起它 |
| 何时恢复 | 事件发生→wakeup | 被激活(active)→调入内存 |

**四种状态组合**：

```
在内存 + 可调度 = 就绪 (Ready)
在内存 + 等事件 = 阻塞 (Blocked)
在磁盘 + 可调度 = 就绪/挂起 (Ready/Suspended)
在磁盘 + 等事件 = 阻塞/挂起 (Blocked/Suspended)
```

**思考**：一个"阻塞/挂起"的进程要重新运行，需要经历什么？
→ 先等事件发生（在磁盘上等待）→ 变为"就绪/挂起"→ 被激活入内存 → 变为"就绪"→ 被调度 → "执行"

## 2.4 进程控制——六个原语

原语 = 原子操作 = 执行过程中不能被中断。OS通过原语来控制进程的一生。

| 原语 | 谁调用 | 做了什么 | 状态变化 |
|------|--------|----------|----------|
| create() | 父进程/OS | 建PCB、分配空间、初始化 | - → 就绪 |
| terminate() | OS/父进程 | 回收资源、移除PCB、杀子孙 | 任意 → 终止 |
| block() | **进程自己** | 把自己挂到等待队列 | 执行 → 阻塞 |
| wakeup() | **其他进程**（如释放资源的） | 把等待者从队列移到就绪队列 | 阻塞 → 就绪 |
| suspend() | OS/父进程 | 把进程换出内存 | 就绪→就绪/挂起；阻塞→阻塞/挂起 |
| active() | OS/父进程 | 把进程换入内存 | 就绪/挂起→就绪；阻塞/挂起→阻塞 |

**关键考点**：block() 是进程**主动**行为（自己调用block把自己挂起），wakeup() 是**被动**的（别人来唤醒它）。

## 2.5 进程切换 vs 模式切换

这是两个完全不同的概念，但总被混淆。

### 模式切换

用户态 ↔ 内核态之间的切换。发生时机：

| 触发方式 | 例子 |
|----------|------|
| 系统调用 | 程序调用 read()、fork() |
| 中断 | 时钟中断、I/O完成中断 |
| 异常 | 除零、缺页、非法指令 |

**模式切换 ≠ 进程切换**。比如I/O设备完成了一个操作，触发中断，CPU切换到内核态处理这个中断，处理完了可能还是继续执行原来的进程——只发生了模式切换，没有发生进程切换。

### 进程切换

保存当前进程A的上下文 → 选择进程B → 恢复B的上下文 → 开始执行B。

| 何时发生进程切换 | 说明 |
|------------------|------|
| 时间片用完 | 时钟中断，调度器剥夺当前进程 |
| 当前进程主动阻塞 | 发起I/O操作，block自己 |
| 高优先级进程抢占 | 新就绪的高优先级进程立即抢占 |
| 进程终止 | 执行完毕 |

**一句话总结**：进程切换一定伴随模式切换（切换要在内核态完成），但模式切换不一定伴随进程切换。

## 2.6 线程——进程的"轻量级"分身

### 为什么需要线程？

传统的"进程"同时承担两个角色：
1. **资源所有者**（拥有一块地址空间、打开的文件、I/O设备）
2. **调度执行实体**（有状态、有优先级、被CPU执行）

把这两个角色**分开**：
- 资源所有者 → 还是叫**进程**
- 调度执行实体 → 叫**线程**

一个进程里可以有多个线程，它们共享进程的地址空间和资源，但各自拥有独立的栈和寄存器上下文。

### 线程带来的好处（为什么比进程高效）

| 操作 | 进程 | 线程 |
|------|------|------|
| 创建 | 要分配地址空间、建页表 → 慢 | 只需分配栈和TCB → 快 |
| 切换 | 要切换地址空间（清TLB）→ 慢 | 同一进程内不切换地址空间 → 快 |
| 通信 | 需要IPC（管道/消息/共享内存） | 直接读写共享变量即可 |

### 三种线程实现

```
用户级线程(ULT)    │  内核级线程(KLT)    │  混合线程
                   │                     │
 线程库管理          │  OS内核管理          │  ULT映射到KLT
 内核看不到线程      │  内核以线程为单位调度  │  
                   │                     │
 优点：切换快        │  优点：一个线程阻塞   │  兼有两者的优点
      调度灵活       │       不影响其他线程  │  
 缺点：一个线程阻塞  │       可利用多CPU     │  
      整个进程阻塞   │  缺点：切换需模式切换  │  
      无法用多CPU    │                     │  
```

**考试重点**：用户级线程中，一个线程调用阻塞式系统调用（如read），**整个进程的所有线程**都会被阻塞——因为内核不知道有多个线程，它看到的是"这个进程阻塞了"。

## 2.7 fork()——UNIX创建进程的方式

fork() 的语义非常独特：**调用一次，返回两次**。

```c
pid = fork();
// 从此开始，有两个进程在执行同一份代码
// pid在子进程中=0，在父进程中=子进程的实际PID
```

**理解的关键**：fork之后，父子进程各自拥有**独立的地址空间**（写时复制优化，但逻辑上是独立的）。子进程修改变量不会影响父进程。

### 真题类型

**题1**：以下程序输出几个 "hello"？

```c
for (i = 0; i < 3; i++)
    fork();
printf("hello\n");
```

**推导**：每次fork，进程数翻倍。3次 → 2³ = 8个进程，每个打印1个 → **8个hello**。

**题2**：

```c
int global = 4;
int main() {
    int vari = 5;
    if (fork() == 0) { global++; vari--; }
    printf("global=%d, vari=%d\n", global, vari);
}
```

**推导**：fork后子进程独立拷贝了一份 global 和 vari。子进程里 global=5, vari=4。父进程的变量不变 → global=4, vari=5。

## 本章理解题

**1. 进程和线程的根本区别是什么？**

进程是**资源分配单位**，线程是**CPU调度单位**。同一个进程的线程共享地址空间，进程间地址空间独立。

**2. PCB是常驻内存的，为什么？**

因为进程切换时需要快速访问PCB的内容（保存/恢复上下文）。如果PCB被换出到磁盘，切换就太慢了。

**3. 挂起状态存在的价值是什么？**

让内存可以容纳更多"能跑"的进程。把"不能跑"的（阻塞的、暂时不需要的）腾到磁盘上，把"能跑"的换进来。这是中程调度的核心任务。

**4. 模式切换一定伴随进程切换吗？**

不一定。比如I/O中断处理完后继续执行当前进程。进程切换一定伴随模式切换。
