# 第5章 文件系统 —— 数据怎么在磁盘上长期保存

---

## 8.0 文件系统要解决什么问题

磁盘就是一大堆编了号的扇区。如果直接让用户操作"读扇区2371"——没人受得了。

文件系统在磁盘之上建立了一层抽象：
- 用户看到的是**文件和目录**（"报告.docx"在"/home/文档/"下）
- 磁盘看到的是**盘块序列**（0号块、1号块...）
- 文件系统负责**翻译**：文件名 → 盘块位置

这就是文件系统的三大任务：
1. **怎么组织数据**（文件的逻辑结构和物理结构）
2. **怎么分配空间**（哪些盘块给谁用）
3. **怎么找到文件**（目录管理）

---

## 8.1 文件的逻辑组织

用户视角：我的数据长什么样？

| 组织方式 | 特点 | 适用 |
|----------|------|------|
| **堆(Pile)** | 无序堆积 | 临时数据 |
| **顺序文件** | 记录按关键字排序 | 批处理（效率最高） |
| **索引顺序文件** | 顺序+索引表 | 需要随机查找的顺序文件 |
| **索引文件** | 每条记录都有索引 | 多关键字查找 |
| **哈希文件** | Hash(关键字)→地址 | 极快的单记录查找 |

### 索引顺序文件为什么快？

顺序文件有N条记录→平均查找 N/2 次。

索引顺序文件将记录分组，每组建一个索引项。假设分 √N 组，每组 √N 条记录：
- 先在索引中查找→约 √N/2 次
- 再在组内顺序查找→约 √N/2 次
- 总计约 √N 次

N=10000时：顺序查5000次 vs 索引顺序查100次→**50倍提升**。

## 8.2 文件的物理结构——磁盘上怎么放

### 方案一：连续分配

文件占用一段连续的盘块。目录项记录(起始块号, 长度)。

```
文件A: [10][11][12][13]    ← 连续4块
```

**优点**：顺序读极快（磁头不用移动）、支持随机访问。

**致命缺点**：
- 文件大小不能动态增长（后面可能被别的文件占了）
- 删除文件后产生外部碎片
- 创建文件时必须知道最终大小

### 方案二：链式分配

每个盘块末尾存一个指针指向下一块。目录项只记录首块号。

**隐式链接**：指针存在每个盘块内。
```
文件A: 块10 → 块25 → 块7 → 块31 → null
```
- 顺序访问OK
- 随机访问灾难（读第100块要从头跟100次指针）
- 一个指针坏了→后面全丢

**显式链接(FAT)**：把所有指针集中存到一张表里（文件分配表），放在内存中。
```
FAT表：  块10→25, 块25→7, 块7→31, 块31→EOF
```
查找在内存中进行→快得多。**这就是Windows的FAT文件系统。**

### 方案三：索引分配

为每个文件建一个**索引块**，里面列出该文件使用的所有盘块号。

```
文件A的索引块: [10, 25, 7, 31]
```

**优点**：支持随机访问（要第3块→直接看索引块第3项=7号块），无外部碎片。

**大文件怎么办**：一个索引块放不下→多级索引（索引块指向其他索引块）。UNIX的i-node就是这么做的：直接块+一级间接+二级间接+三级间接。

### 三种方式对比——理解什么场景用什么方案

| | 连续 | 链式(FAT) | 索引 |
|--|------|-----------|------|
| 顺序读 | 最快 | 快 | 快 |
| 随机读 | 快 | 慢（隐式）/中（FAT） | 快 |
| 动态增长 | 不行 | 可以 | 可以 |
| 空间开销 | 无 | 指针/FAT表 | 索引块 |
| 碎片 | 外部碎片 | 无 | 无 |

## 8.3 空闲空间管理——哪些盘块没用？

| 方法 | 原理 | 优缺点 |
|------|------|--------|
| **空闲表** | 记录每个连续空闲区的(起始, 长度) | 适合连续分配 |
| **空闲链表** | 空闲块用指针串起来 | 无额外空间开销，但分配慢 |
| **位示图** | 每个盘块对应1位(0=空,1=占) | 空间小、查找快，最常用 |
| **成组链接** | 空闲块分组管理（UNIX） | 适合大磁盘 |

### 位示图计算

4096个盘块 → 需要4096位 = 512字节的位示图。

如果按每行16位组织：
- 盘块号 b 对应行号 = (b-1)/16 + 1，列号 = (b-1)%16 + 1
- 反过来：盘块号 = (行号-1)×16 + 列号

## 8.4 目录管理——按名存取

### FCB（文件控制块）

每个文件一个FCB，存放文件的所有元信息：文件名、类型、大小、物理位置、权限、时间戳等。

**目录文件**就是一组FCB的集合。

### i-node（索引节点）

**问题**：FCB很大（文件名+一堆属性），检索目录时只需要文件名，其余信息用不到。

**优化**：把文件名和描述信息分开。目录项 = (文件名, i-node号)。i-node单独存放。

**好处**：
- 目录项变小→一页能装更多目录项→检索更快
- i-node是UNIX/Linux文件系统的核心数据结构

### 目录结构演进

```
单级目录 → 两级目录 → 树形目录
  简单但     用户隔离     层次清晰
  不能重名   可重名       路径名定位
```

**单级目录**：所有文件放一个目录里。不能重名。几百个文件后就乱了。

**两级目录**：主文件目录(MFD) + 每个用户一个用户文件目录(UFD)。不同用户可以有同名文件。

**树形目录**：层次无限制。引入**路径名**概念：
- 绝对路径：/usr/ast/mbox（从根目录开始）
- 相对路径：../ast/mbox（从当前目录开始）

### 树形目录的文件查找过程

查找 `/usr/ast/mbox`：

```
① 读根目录 → 找到"usr"→ 得到usr的i-node号
② 读usr的i-node → 得到usr目录文件的盘块号
③ 读该盘块 → 找到"ast" → 得到ast的i-node号
④ 读ast的i-node → 得到ast目录文件的盘块号
⑤ 读该盘块 → 找到"mbox" → 得到mbox的i-node号
⑥ 读mbox的i-node → 得到mbox数据的物理位置
```

**每深入一级目录 = 两次磁盘访问**（读i-node + 读目录块）。路径越深越慢。这就是为什么有目录缓存。

## 8.5 文件共享与保护

### 共享方式

**硬链接**：多个目录项指向同一个i-node。i-node中有引用计数，全部链接删除后才释放文件。

**软链接（符号链接）**：创建一个特殊文件，内容是"目标文件的路径名"。类似Windows快捷方式。

| | 硬链接 | 软链接 |
|--|--------|--------|
| 本质 | 共享i-node | 存路径字符串 |
| 删除原文件 | 链接仍有效（引用计数>0） | 链接失效（断链） |
| 跨文件系统 | 不可以 | 可以 |

### 保护

- 存取控制列表(ACL)：每个文件记录"谁可以做什么"
- UNIX权限模型：owner/group/others × read/write/execute = 9位

## 8.6 FAT文件系统——理解Windows磁盘管理

### FAT的核心思想

**显式链接**的实现：磁盘上维护一张FAT表（文件分配表），第i项存"文件的第i个簇之后下一个簇是什么"。

```
目录项：文件A，首簇=2
FAT表：FAT[2]=5, FAT[5]=8, FAT[8]=EOF

→ 文件A占用簇2→5→8
```

### FAT12/16/32的区别

本质区别：**FAT表项的位宽不同→能管理的簇数不同→能管理的磁盘容量不同**。

| | FAT12 | FAT16 | FAT32 |
|--|-------|-------|-------|
| 表项位宽 | 12位 | 16位 | 32位 |
| 最大簇数 | 4K | 64K | ~4G |
| 最大分区 | 小 | 2GB | 2TB(实际) |

为什么不直接用大的？因为FAT表本身也要存在磁盘上且需要加载到内存。FAT32管理2TB磁盘的FAT表就要十几MB内存。

### FAT32磁盘结构

```
MBR(512B) │ DBR(引导区) │ FAT1 │ FAT2(备份) │ 根目录 │ 数据区
```

**格式化只清FAT表，不清数据区**——所以"格式化后的数据可以恢复"。

## 8.7 NTFS——Windows现代文件系统

### 与FAT的根本区别

- 64位地址→支持超大分区
- 所有文件信息记录在MFT（主文件表）中
- 支持日志（$LogFile）→崩溃后可恢复
- 支持权限控制(ACL)

### MFT的设计

MFT每行1KB，对应一个文件。小文件的数据可以直接放在MFT记录里（称为"常驻属性"），连单独的数据盘块都不需要。

---

## 本章关键理解

1. **逻辑结构是用户视角**（顺序/索引/哈希），**物理结构是磁盘视角**（连续/链式/索引）
2. 连续分配性能最好但灵活性最差——和内存管理中的连续分配问题一样
3. FAT本质是"把所有文件的链接指针集中存放在一张表里"
4. i-node把文件名和文件属性分开——加速了目录检索
5. 位示图是最通用的空闲空间管理方法
