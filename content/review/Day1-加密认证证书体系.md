## 一、加密/解密过程

### 1.1 核心概念

**加密**：将明文转换为密文的过程
**解密**：将密文还原为明文的过程

### 1.2 两种加密方式对比

| 特征 | 对称加密 | 非对称加密（公钥加密） |
|------|---------|---------------------|
| **密钥数量** | 1个（加密解密用同一密钥） | 2个（公钥+私钥） |
| **速度** | 快 | 慢（100-1000倍） |
| **安全性** | 密钥传输风险 | 高（私钥保密） |
| **密钥管理** | 困难（n人需C(n,2)个密钥） | 简单（n人需2n个密钥） |
| **典型算法** | DES、3DES、AES、IDEA、RC4 | RSA、ECC、Diffie-Hellman |
| **应用** | 大量数据加密 | 密钥交换、数字签名、少量数据加密 |

### 1.3 实际应用模式（混合加密）

实际应用中通常结合两者优势：
1. **非对称加密**用于密钥交换和身份认证
2. **对称加密**用于数据加密（因为速度快）

**例**：SSL/TLS协议就采用这种混合模式

```
对称快，密钥难
非对称，安全但慢
结合用，效率高
混合加密是王道
```

## 二、数字签名 ★

### 2.1 核心定义

**数字签名**：利用公钥加密技术对发送消息进行篡改的识别手段。发送者用**私钥**加密消息摘要，接收者用**公钥**解密验证。

### 2.2 数字签名原理

```
发送方：
1. 对消息应用散列函数（如MD5、SHA-1）→ 生成消息摘要
2. 用自己的私钥加密消息摘要 → 生成数字签名
3. 发送（消息 + 数字签名）

接收方：
1. 收到消息和数字签名
2. 用发送方的公钥解密数字签名 → 得到原始摘要
3. 对接收到的消息应用相同的散列函数 → 得到新摘要
4. 比较两个摘要是否一致
   - 一致：验证成功，消息未被篡改
   - 不一致：验证失败，消息被篡改
```

### 2.3 数字签名的安全目标

数字签名必须提供三个关键安全目标：

| 安全目标 | 说明 |
|---------|------|
| **完整性** | 验证消息是否被篡改（通过摘要对比） |
| **来源认证** | 确认消息来源（通过私钥的唯一性） |
| **不可否认性** | 发送者事后无法否认发送过此消息（私钥只有发送者有） |

### 2.4 数字签名与加密的区别

| 方面 | 数字签名 | 加密 |
|------|---------|------|
| **目的** | 认证+完整性+不可否认 | 保密性（防止窃听） |
| **使用的密钥** | 发送方私钥签名，接收方公钥验证 | 接收方公钥加密，接收方私钥解密 |
| **可逆性** | 任何持有公钥者可验证（公开可验证） | 只有私钥持有者可解密 |
| **应用** | 软件分发、电子政务、电子商务 | 机密信息传输 |

### 2.5 ⚠️ 考点重点

**填空题/判断题可能考点：**
- 数字签名用私钥签名，公钥验证
- 数字签名可以提供完整性、来源认证、不可否认性
- MD5、SHA-1是常用的散列函数

**简答题考点：**
- 数字签名的原理和过程
- 数字签名与加密的区别
- 数字签名的安全目标

```

## 三、认证技术 ★★★

### 3.1 认证的本质

**认证**：验证用户所宣称的身份是否正确

### 3.2 三大认证方式对比

| 方式 | 定义 | 优点 | 缺点 | 安全性 |
|------|------|------|------|--------|
| **口令/通行字** | 用户所知道的（密码、PIN） | 简单易用、成本低、用户接受度高 | 易被窃取、重放攻击、暴力破解 | ★★ |
| **令牌/智能卡** | 用户所拥有的（智能卡、USB Key、短信验证码） | 比口令安全、可远程验证 | 需要携带、可能丢失、短信可截获 | ★★★ |
| **生物特征** | 用户本身所具有的（指纹、虹膜、人脸识别、声纹） | 唯一性、不可替代、难伪造 | 成本高、隐私问题、准确性受环境影响 | ★★★★ |

### 3.3 口令安全详细分析

#### 威胁类型：

| 威胁 | 说明 | 防范措施 |
|------|------|---------|
| **暴力破解** | 尝试所有可能的组合 | 复杂密码策略、账户锁定机制 |
| **字典攻击** | 使用常见密码列表 | 禁止使用常见密码 |
| **重放攻击** | 嗅探并重放认证信息 | 使用一次性令牌、时间戳 |
| **社会工程学** | 心理欺骗获取密码 | 安全意识教育 |
| **肩窥** | 被人看到输入密码 | 遮挡输入、虚拟键盘 |
| **窃听** | 网络嗅探获取密码 | 使用加密传输（SSL/TLS） |

#### 协议风险：

如果直接传输口令，易遭受：
- **重放攻击**：攻击者截获并重放认证信息
- **窃听**：攻击者嗅探网络获取口令明文

### 3.4 生物特征认证的优缺点

**优点：**
- 唯一性：指纹、虹膜等终身不变
- 不可替代：无法转移给他人
- 难伪造：生物特征难以复制

**缺点：**
- 成本高：设备和部署费用高
- 准确性问题：环境（温度、湿度）、噪声影响
- 隐私问题：生物数据一旦泄露无法更改
- 不可撤销：一旦泄露无法更换（不像密码可以重置）

### 3.5 ⚠️ 考点重点

**填空题/判断题可能考点：**
- 口令认证是最基本、最广泛使用的认证方式
- 生物特征具有唯一性和终身不变性
- 多因素认证（MFA）结合多种方式提高安全性

**简答题考点：**
- 对比三种认证方式的优缺点
- 口令面临的主要威胁及防范措施
- 为什么需要多因素认证

### 3.6 记忆口诀

```

## 四、X.509 证书机制 ★★★

### 4.1 X.509是什么

**X.509**：一个广泛使用的数字证书标准，用于公钥证书和属性证书的格式规范。

### 4.2 数字证书的作用

数字证书解决了公钥的真实性问题：
- **没有证书**：攻击者可以伪造公钥（中间人攻击）
- **有证书**：由可信第三方（CA）签名，验证公钥的真实性

### 4.3 数字证书的内容

一个X.509数字证书包含：

| 字段 | 说明 |
|------|------|
| **版本** | 证书的版本号（v1, v2, v3） |
| **序列号** | CA分配的唯一证书标识 |
| **签名算法** | 用于签名证书的算法（如RSA+SHA-1） |
| **颁发者** | 颁发此证书的CA名称 |
| **有效期** | 证书的生效和失效日期 |
| **主体** | 证书持有者的名称 |
| **主体公钥信息** | 证书持有者的公钥 |
| **颁发者唯一标识** | CA的唯一标识（可选） |
| **主体唯一标识** | 持有者的唯一标识（可选） |
| **扩展** | 额外信息（如密钥用途、限制） |
| **CA签名** | CA对证书内容的数字签名 |

### 4.4 证书颁发过程

```
1. 用户生成密钥对（公钥+私钥）
2. 用户向CA提交证书申请（包含公钥和身份信息）
3. CA验证用户身份
4. CA用私钥对证书内容签名
5. CA颁发数字证书给用户
6. 用户存储证书和私钥
```

### 4.5 证书验证过程

```
1. 接收方获取对方的数字证书
2. 检查证书是否在有效期内
3. 检查证书是否被吊销（查询CRL或OCSP）
4. 使用CA的公钥验证证书签名
5. 验证证书中的公钥是否与持有者匹配
6. 完成验证
```

### 4.6 证书链（信任链）

```
根CA（Root CA）
    ↓ 签名
中间CA（Intermediate CA）
    ↓ 签名
终端实体证书（End Entity Certificate）
```

### 4.7 ⚠️ 考点重点

**填空题/判断题可能考点：**
- X.509是一个数字证书标准
- 数字证书由CA（认证中心）颁发
- 证书中包含持有者的公钥信息

**简答题考点：**
- X.509证书包含哪些主要字段
- 数字证书的颁发和验证过程
- 为什么需要数字证书

### 4.8 记忆口诀

```

数字证书内容多
公钥身份有效性
CA签名保真实

```

## 五、PKI 公钥基础设施 ★

### 5.1 PKI是什么

**PKI（Public Key Infrastructure）**：公钥基础设施，用于管理和分发公钥的系统框架。

### 5.2 PKI的核心目标

解决互联网通信中的安全问题：
1. **身份认证**：确认通信双方的真实身份
2. **完整性**：确保信息未被篡改
3. **保密性**：防止信息被窃听
4. **不可否认性**：防止发送者否认发送过消息

### 5.3 PKI的组成要素

| 组件 | 说明 | 职责 |
|------|------|------|
| **CA（Certification Authority）** | 认证中心 | 颁发、更新、吊销证书；管理证书生命周期 |
| **RA（Registration Authority）** | 注册机构 | 验证用户身份，协助CA颁发证书 |
| **证书库** | 存储证书的数据库 | 存储和管理数字证书 |
| **CRL（Certificate Revocation List）** | 证书吊销列表 | 记录已吊销的证书 |
| **密钥管理中心** | 管理密钥的机构 | 生成、存储、备份、恢复密钥 |

### 5.4 PKI的工作流程

```
1. 用户向RA提交证书申请
2. RA验证用户身份
3. RA将申请转发给CA
4. CA生成并签名数字证书
5. CA将证书存入证书库
6. CA将证书颁发给用户
7. 用户使用证书进行安全通信
8. 接收方验证证书的有效性
```

### 5.5 PKI的应用场景

- **SSL/TLS**：网站身份认证和数据加密
- **电子邮件安全**：S/MIME加密和签名邮件
- **电子政务**：政府网站和在线服务的身份认证
- **电子商务**：在线支付的安全保障
- **VPN**：远程访问的身份认证
- **软件签名**：验证软件的完整性和来源

### 5.6 ⚠️ 考点重点

**填空题/判断题可能考点：**
- PKI由CA、RA、证书库、CRL等组成
- CA是PKI的核心，负责证书管理
- PKI用于解决公钥的真实性问题

**简答题考点：**
- PKI的组成部分及其职责
- PKI的工作流程
- PKI在哪些场景中应用

### 5.7 记忆口诀

```

CA中心管证书
RA注册把身份验
证书库存证书

应用广泛又安全
```

#### 名词解释答案要点：
1. **加密/解密**：加密是将明文转换为密文的过程；解密是将密文还原为明文的过程。用于保护数据的机密性。

2. **数字签名**：利用公钥加密技术对发送消息进行篡改识别的手段。发送方用私钥签名，接收方用公钥验证。提供完整性、来源认证、不可否认性。

3. **对称加密**：使用同一个密钥进行加密和解密的加密方式。速度快，但密钥管理困难。

4. **非对称加密**：使用公钥和私钥两个密钥的加密方式。安全性高，但速度慢。

5. **数字证书**：由CA颁发的包含公钥和持有者身份信息的电子文档。用于验证公钥的真实性。

6. **认证中心（CA）**：可信的第三方机构，负责颁发、更新和吊销数字证书。

7. **公钥基础设施（PKI）**：管理和分发公钥的系统框架，包括CA、RA、证书库、CRL等组件。

#### 简答题答案要点：

**1. 对比对称加密和非对称加密的优缺点**
- 对称加密：优点是速度快；缺点是密钥管理困难、密钥传输不安全
- 非对称加密：优点是安全性高、密钥管理简单；缺点是速度慢

**2. 数字签名的原理和过程**
- 发送方：对消息散列→私钥加密摘要→发送消息和签名
- 接收方：用公钥解密签名→对比摘要→验证成功/失败

**3. 数字签名的安全目标**
- 完整性：通过摘要对比验证消息未被篡改
- 来源认证：通过私钥唯一性确认消息来源
- 不可否认性：发送者无法否认发送过此消息

**4. 三种认证方式对比**
- 口令：简单易用，但安全性低
- 令牌：较安全，但需携带
- 生物特征：唯一性强，但成本高且无法重置

**5. 口令威胁及防范**
- 暴力破解→复杂密码策略
- 字典攻击→禁止常见密码
- 重放攻击→一次性令牌
- 窃听→加密传输

**6. X.509证书内容和作用**
- 包含：公钥、身份信息、有效期、CA签名等
- 作用：验证公钥真实性，防止中间人攻击

**7. PKI组成和工作流程**
- 组成：CA、RA、证书库、CRL
- 流程：用户申请→RA验证→CA颁发→用户使用→接收方验证

**8. 混合加密的原因**
- 对称加密快但密钥传输不安全
- 非对称加密安全但速度慢
- 结合两者：非对称加密交换密钥，对称加密加密数据
