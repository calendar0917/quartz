### 1. 第四章 4.7 — 身份、凭证和访问管理（IAM）

**大纲列出，从未涉及**。需要了解：

- **IAM（Identity, Credential, and Access Management）**：企业级的身份生命周期管理框架
- **身份生命周期**：创建（Provisioning）→ 维护 → 停用（Deprovisioning）
- **凭证管理**：密码策略、证书管理、令牌分发
- **单点登录（SSO）**：一次认证访问多个系统
- **联合身份（Federation）**：跨组织信任传递（如用Google账号登录第三方网站）

**可能出题**：解释IAM的概念，或与访问控制模型的关系。

### 2. 第四章 4.8 — 信任框架

**大纲列出，从未涉及**。核心概念：

- 信任框架是跨组织边界的身份和权限管理机制
- **联邦身份管理**：SAML、OAuth 2.0、OpenID Connect
- 在不同安全域之间建立信任关系
- 典型场景：校园联盟认证（一个学校账号访问联盟其他学校资源）

### 3. 第四章 4.9 — 银行的RBAC系统案例

**大纲单独列出"14.9 银行的RBAC系统"**，但注意编号是14.9可能是教材特定编排。核心要点：

- 银行的角色划分示例：柜员 → 客户经理 → 信贷审批员 → 风控经理 → 系统管理员
- 敏感交易的"双人复核"原则（职责分离的典型应用）
- 交易限额对应的角色权限（如柜员单笔≤5万，经理≤50万，行长≤500万）
- 动态职责分离：同一人不能既是交易发起者又是审批者

**教师重点考访问控制，这个案例很可能作为应用题背景出现**。

### 4. 第五章 5.2/5.3 — 数据库管理系统（DBMS）/关系数据库

虽然偏基础，但大纲明确列出。核心：

- DBMS是管理数据库的系统软件，提供数据定义、操纵、控制功能
- 关系数据库：表、行（元组）、列（属性）、主键、外键
- 安全相关：DBMS提供访问控制、审计、加密等安全功能

### 5. 第八章 8.6 — 分布式或混合式入侵检测

大纲列出。核心：

- **分布式IDS（DIDS）**：多个检测器分布在网络各处，集中分析
- **混合式IDS**：结合HIDS和NIDS的优势
- 解决单一HIDS/NIDS的盲区问题
- 典型架构：分布式Sensor + 集中Manager

### 6. 第八章 8.7 — 入侵检测交换格式

大纲列出。核心：

- **IDMEF（Intrusion Detection Message Exchange Format）**：IDS之间交换告警信息的标准格式
- 基于XML，定义统一的告警数据结构
- 解决异构IDS之间的信息共享
- **IETF RFC 4765**

### 7. 第八章 8.1 — 入侵者分类

大纲列出。核心分类：

| 类型 | 特征 |
|------|------|
| **黑客（Hacker）** | 技术探索者，可能白帽或黑帽 |
| **破解者（Cracker）** | 以破坏/获利为目的 |
| **内部威胁（Insider）** | 内部员工/承包商，拥有合法访问权但滥用 |
| **脚本小子（Script Kiddie）** | 使用现成工具，技术水平低 |
| **国家支持（State-sponsored）** | APT的主力，资源充足 |

### 8. 第三章 3.5 — 远程用户认证

前面材料侧重本地认证的三种方式。远程认证的额外考点：

- **PAP（Password Authentication Protocol）**：明文传输密码——安全风险
- **CHAP（Challenge Handshake Authentication Protocol）**：质询-应答，不传密码
- **EAP（Extensible Authentication Protocol）**：可扩展认证框架，支持多种认证方法
- **RADIUS**：集中式远程认证服务器

**教师课堂提问过"如果使用口令作为票据传输，容易遭受什么攻击"** → 重放攻击和窃听。

### 9. 第六章 6.5 — 社会工程学传播

教师专门问过"社会工程学"作为口令威胁。除了对口令的攻击，还应注意：

- **社会工程学在恶意软件传播中的角色**：诱导用户下载木马、打开钓鱼邮件附件
- **常见手法**：伪装权威（假扮IT部门）、制造紧迫感、利用好奇心
- **垃圾电子邮件**（Spam）作为传播载体

### 10. 第七章 7.4 — 基于应用的宽带攻击

大纲列出。核心类型：

| 攻击 | 原理 |
|------|------|
| **Slowloris** | 发送不完整的HTTP请求头，保持大量连接不关闭，耗尽服务器连接池 |
| **Slow Read** | 正常建立连接后以极慢速度读取响应，拖住服务器资源 |
| **HTTP POST Slow** | 声明大Content-Length但极慢发送body |

**区别于网络层洪泛——应用层慢速攻击不依赖大流量，更难检测**。

### 11. 第七章 7.7 — 对拒绝服务攻击的响应

大纲列出。响应措施：

- **事件响应计划（IRP）**：预定义的DoS响应流程
- **联系ISP**：在上游过滤攻击流量
- **流量重定向**：将流量导入清洗中心（Scrubbing Center）
- **取证分析**：保留攻击证据，分析攻击源和手法
- **事后加固**：修补暴露点，优化架构

### 12. 第九章 9.2 — 防火墙的访问策略

大纲列出"防火墙的特征和访问策略"，已经散落在各处但未系统整理。补充：

**防火墙的基本访问控制策略原则**：
- **默认拒绝（Default Deny）**：凡未明确允许即拒绝——安全优先
- **默认允许（Default Allow）**：凡未明确拒绝即允许——便利优先
- 最佳实践：**始终使用默认拒绝**

**策略设计要素**：源地址、目的地址、源端口、目的端口、协议、方向、动作（允许/拒绝）、日志

### 13. 第22章 — 邮件安全协议补充

教师提到"邮件IP协议"作为第22章内容。补充：

- **SPF（Sender Policy Framework）**：验证发件服务器IP是否被授权
- **DKIM（DomainKeys Identified Mail）**：用数字签名验证邮件未被篡改
- **DMARC**：基于SPF+DKIM的政策框架，定义验证失败时的处理策略

这三个是防垃圾邮件和钓鱼邮件的标准技术栈。

## 快速补充自测（针对以上盲区）

**1.** IAM 的全称是什么？核心功能有哪些？
→ 身份、凭证和访问管理（Identity, Credential, and Access Management）。功能：身份生命周期管理（创建/维护/停用）、凭证管理、SSO、联合身份。

**2.** 银行RBAC中"柜员不能审批自己发起的交易"体现什么原则？
→ 职责分离原则（Separation of Duties） + 最小权限原则

**3.** 社会工程学在计算机安全中指的是什么？
→ 通过心理学手段欺骗受害者，绕过技术防线获取敏感信息或权限。常见手法：伪装权威、钓鱼邮件、电话诈骗、尾随进入（Tailgating）。

**4.** Slowloris 攻击和 SYN Flood 的核心区别？
→ Slowloris 攻击**应用层（HTTP）**，发送不完整的HTTP请求头保持连接；SYN Flood 攻击**传输层（TCP）**，利用三次握手缺陷。Slowloris 不依赖大流量，更难被流量监控检测。

**5.** DoS攻击的响应流程包含哪些环节？
→ 检测确认 → 联系ISP/上游过滤 → 流量清洗重定向 → 取证分析 → 事后加固

**6.** IDMEF 的作用？
→ IDS之间交换告警信息的标准XML格式（RFC 4765），实现异构IDS互操作。

**7.** SPF、DKIM、DMARC 各自验证邮件的哪个维度？
→ SPF：验证发件IP是否授权；DKIM：验证邮件内容是否被篡改（数字签名）；DMARC：基于SPF+DKIM的统一政策。

**8.** 信任框架和联邦身份的关系？
→ 信任框架建立跨组织的身份管理机制，联邦身份（如SAML、OAuth 2.0、OIDC）是其技术实现。

**9.** DBMS提供的安全功能有哪些？
→ 访问控制（用户/角色/权限）、审计日志、数据加密、备份恢复、完整性约束

**10.** 混合式IDS的含义？
→ 结合HIDS（主机层检测）和NIDS（网络层检测），分布式Sensor + 集中分析管理，消除单一IDS盲区。
