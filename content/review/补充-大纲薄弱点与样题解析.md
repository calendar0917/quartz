### 一、数据库安全补充（第5章）

#### 1.1 数据库安全需求（5.1）
数据库安全的CIA三元组在数据库层面：
- **机密性**：防止未授权读取（如工资字段不应被HR以外的人看到）
- **完整性**：防止未授权修改（如学生成绩不能被随意篡改）
- **可用性**：保证授权用户能正常访问

#### 1.2 推理攻击（5.6，大纲明确列出）
**定义**：攻击者通过组合多个合法的查询结果，推断出本应保密的敏感信息。

**类型**：

| 类型             | 说明               | 示例                                                                                |
| -------------- | ---------------- | --------------------------------------------------------------------------------- |
| **直接推理**       | 从单个查询直接推断        | `SELECT AVG(salary) FROM employee WHERE dept='研发' AND COUNT(*) = 1` → 唯一研发人员的工资暴露 |
| **间接推理**（统计推理） | 通过汇总统计反推个体数据     | 查询研发部总工资（SUM），再查询去掉张三后的总工资，差值=张三工资                                                |
| **追踪器攻击**      | 通过精心构造的查询集绕过聚合限制 | 先用大范围查询，再用小范围查询，逐层逼近目标                                                            |

**防御措施**：
- 查询结果抑制（最小查询集大小限制）
- 数据扰动（加噪声）
- 查询审计（记录查询历史，检测异常模式）

#### 1.3 数据库加密（5.7）
| 加密粒度            | 说明               | 优缺点              |
| --------------- | ---------------- | ---------------- |
| **表级加密**        | 加密整张表            | 简单，但查询效率低（需解密整表） |
| **列级加密**        | 加密敏感列（如身份证号列）    | 灵活，性能好           |
| **字段级加密**       | 加密单个字段           | 最精细，但管理复杂        |
| **透明数据加密（TDE）** | 数据库引擎自动加解密，对应用透明 | 业界主流方案           |

#### 1.4 数据中心安全（5.8）
- 物理安全：门禁、监控、防火
- 网络安全：防火墙、IDS/IPS、DMZ
- 数据安全：备份、容灾、加密
- 管理安全：访问控制、审计

### 二、恶意软件补充（第6章）

#### 2.1 高级持续性威胁 APT（6.2，大纲明确列出）
**APT特点**（5个关键特征）：
1. **高级（Advanced）**：攻击者技术精湛，资源丰富（常是国家背景）
2. **持续（Persistent）**：长期潜伏，不急于达到目标
3. **威胁（Threat）**：有明确的攻击目标（知识产权、国家机密）
4. **针对性**：针对特定组织/个人，非广撒网
5. **多阶段**：信息收集→渗透→横向移动→数据窃取→持续控制

**与普通攻击的区别**：
- 普通攻击：打一枪换一个地方
- APT：潜伏数月甚至数年，持续窃取

#### 2.2 恶意软件载荷详解（6.6-6.9，大纲强调）

##### （1）系统损坏（6.6）
破坏数据、破坏系统文件、格式化硬盘等。

##### （2）代理攻击——僵尸网络（6.7）
| 概念 | 说明 |
|------|------|
| **Zombie（僵尸）** | 被控制的计算机，攻击者可以远程操控 |
| **Bot（机器人）** | 运行恶意bot程序的受控主机 |
| **Botnet（僵尸网络）** | 大量zombie组成的网络 |
| **C&C服务器** | 攻击者用于控制botnet的指挥控制服务器 |

**僵尸网络用途**：发起DDoS攻击、发送垃圾邮件、挖矿、窃取信息。

##### （3）信息窃取——键盘记录器/钓鱼/间谍软件（6.8）
| 类型 | 说明 |
|------|------|
| **键盘记录器（Keylogger）** | 记录用户键盘输入，窃取密码 |
| **网络钓鱼（Phishing）** | 伪造网站/邮件诱骗用户输入密码 |
| **间谍软件（Spyware）** | 在后台监控用户活动，收集信息 |

##### （4）隐藏——后门/Rootkit（6.9，大纲明确要求理解rootkit机理）
| 概念 | 说明 |
|------|------|
| **后门（Backdoor）** | 绕过正常认证机制的秘密入口，攻击者可以随时进入系统 |
| **Rootkit** | 一组工具，用于隐藏恶意活动（隐藏进程、文件、网络连接、注册表项） |

**Rootkit工作机理**（大纲考点）：
- **用户态rootkit**：通过替换系统命令（如替换`ls`、`ps`）来隐藏文件和进程
- **内核态rootkit**：修改操作系统内核（通过可加载内核模块LKM），劫持系统调用表，更为隐蔽
- **固件级rootkit**：嵌入BIOS/UEFI或硬件固件中，重装系统也无法清除
- **检测难度**：内核态 > 用户态，固件级几乎无法通过软件检测

#### 2.3 恶意软件对抗措施（6.10）
| 策略 | 具体措施 |
|------|---------|
| **预防（Prevention）** | 防病毒、打补丁、应用白名单、最小权限 |
| **检测（Detection）** | IDS/IPS、行为分析、完整性检查 |
| **响应（Response）** | 隔离、清除、恢复、取证 |

### 三、IDS补充——蜜罐（8.8，大纲明确列出）

#### 3.1 蜜罐（Honeypot）
**定义**：故意设置的诱饵系统，用于吸引攻击者，从而监控攻击行为。

#### 3.2 蜜罐分类
| 分类        | 说明                 |
| --------- | ------------------ |
| **低交互蜜罐** | 模拟有限的服务，风险低，信息少    |
| **高交互蜜罐** | 完整的真实操作系统，风险高，信息丰富 |

#### 3.3 蜜罐相对防火墙/IDS的优势（大纲考点）
| 对比      | 防火墙 | IDS   | 蜜罐                |
| ------- | --- | ----- | ----------------- |
| 误报率     | 低   | 中/高   | **接近零**（所有访问都是异常） |
| 能发现未知攻击 | 不能  | 异常检测能 | **能**（捕获攻击者所有行为）  |
| 提供攻击细节  | 很少  | 有限    | **丰富**（记录完整攻击链）   |
| 主要用途    | 阻断  | 检测告警  | **研究/诱捕**         |

### 四、防火墙与入侵防御系统——IPS/UTM（第9章）

#### 4.1 IPS（入侵防御系统，9.6）
**IPS vs IDS**：

| 方面 | IDS | IPS |
|------|-----|-----|
| **部署方式** | 旁路（被动） | 串接（在线） |
| **功能** | 检测+告警 | 检测+**阻断** |
| **对网络影响** | 无（只复制流量） | 可能成为瓶颈 |
| **故障影响** | 不影响业务 | 可能中断网络 |
| **响应方式** | 人工或联动响应 | **自动实时阻断** |

#### 4.2 UTM（统一威胁管理，9.7）
**定义**：将多种安全功能集成在一个设备中。

**集成功能**：防火墙 + IDS/IPS + 防病毒 + VPN + 内容过滤 + 反垃圾邮件

优点：管理简单，成本低；缺点：单点故障，性能可能不足。

### 五、DB扩展——SQL注入具体技术补充

> Day 7材料只提了"带内、带外、推理"，大纲还要求理解**联合查询、时间盲注、报错注入**。

| 技术 | 说明 | 关键特征 |
|------|------|---------|
| **联合查询注入** | 使用`UNION SELECT`将攻击查询结果合并到正常结果中 | 属于带内注入，结果直接可见 |
| **报错注入** | 利用数据库错误信息泄露数据 | 例如`extractvalue(1,concat(0x7e,(select database())))`触发XPATH错误，错误信息中包含数据库名 |
| **时间盲注** | 利用`sleep()`或`benchmark()`延时函数判断条件真伪 | 属于推理攻击，通过响应时间判断 |
| **布尔盲注** | 通过页面正常/异常响应逐字符推断 | 也属于推理攻击 |

**SQL注入检测方法**（大纲要求）：
- 静态代码分析：扫描源码中不安全的SQL拼接
- 动态测试（渗透测试）：输入特殊字符`' " ; --`观察响应
- WAF日志分析：查看被拦截的SQL注入尝试

### 样题一：单项选择题——DNS反射放大攻击

**题目回顾**：
> 某公司网站服务器遭遇大流量攻击，带宽被占满。抓包发现源IP是大量开放DNS服务器IP，请求包是查询类型为"ANY"的小包，返回包体积巨大（数十倍甚至上百倍）。问攻击类型。

**答案：C. DNS反射放大攻击**

**详细解析**：

这道题考的是对拒绝服务攻击变种的识别能力：

| 选项 | 攻击特征 | 本题不符合的原因 |
|------|---------|----------------|
| A. SYN Flood | 大量TCP SYN包，伪造源IP，消耗连接资源 | 题目说的是DNS流量，非SYN |
| B. HTTP Flood (CC攻击) | 大量HTTP请求，消耗Web服务器CPU | 题目源IP是DNS服务器，非HTTP |
| **C. DNS反射放大** | ✅ 伪造受害者IP→发DNS请求→DNS返回大包→受害者被淹没 | **完全符合** |
| D. Ping of Death | 发送超大ICMP包导致系统崩溃 | 题目说的是DNS |

**攻击原理图**：
```
攻击者 ──DNS ANY查询(小包,源IP伪造为受害者IP)──→ 开放DNS服务器
                                                      │
受害者 ←──DNS响应(大包,数十倍放大)─────────────────┘
```

**放大倍数**：DNS ANY查询约54字节，响应可达3000+字节，放大54倍以上。

**防御方法**：
- 限制DNS服务器响应速率
- 关闭不需要的DNS递归查询
- 入口过滤（BCP38）：路由器拒绝源IP非本网的包
- 流量清洗服务

### 样题二：填空题——病毒与蠕虫

**题目回顾**：
> 需要寄生于宿主程序，依靠人为运行或文件复制传播，例如CIH病毒 → _____  
> 不需要宿主程序，利用网络漏洞自动扫描感染，例如WannaCry → _____

**答案：病毒、蠕虫**

**核心区分标准**（考试常见）：

| 特征 | 病毒 | 蠕虫 |
|------|------|------|
| 是否独立运行 | 否（寄生） | 是 |
| 是否需要用户交互 | 是（运行/复制文件） | 否（自动传播） |
| 传播介质 | 文件/存储介质 | 网络 |
| 典型案例 | CIH、宏病毒 | WannaCry、莫里斯蠕虫 |
| 可否通过重装清除 | 可以 | 不一定（可能重新感染） |

**记忆口诀**：病毒寄生文件传，蠕虫独立网络钻。

### 样题三：简答题——IDS部署与检测原理

**(1) 部署方式**

**答案：方案B（端口镜像/旁路部署）**

**原因**：IDS的核心功能是**检测和告警**，而非阻断。旁路部署通过SPAN端口接收流量副本，即使IDS故障也不影响业务流量。方案A（串联）是IPS的部署方式。

**关键区分**：
- IDS = 旁路，被动监听，只告警不阻断
- IPS = 串联，主动在线，检测并阻断

**(2) 检测原理**

**检测技术**：**签名检测（特征检测/误用检测）**

**优点**：
- 对已知攻击检测准确率高
- 误报率（False Positive）低
- 可以快速识别已知攻击模式

**缺点**：
- 无法检测未知攻击（0day、变种）
- 攻击者可通过编码、分片、混淆绕过
- 需要持续更新特征库

**IDS检测的核心指标**（大纲明确要求）：
| 指标 | 含义 |
|------|------|
| **真阳性（TP）** | 正确检测出攻击 |
| **假阳性（FP）** | 误报——正常行为被判为攻击 |
| **真阴性（TN）** | 正确判定正常行为 |
| **假阴性（FN）** | 漏报——攻击未被检测到 |

### 样题四：应用题——多因素认证失效分析

这道题是40分的应用题，设计得非常精妙，层层递进考察身份认证的综合理解。

**(1) 多因素认证失效分析（4分）**

**绕过原因（2分）**：该公司将"所有"因素（短信验证码）降级为另一个"所知"因素（邮箱密码）。攻击者掌握了邮箱密码，就可以读取短信验证码。本质上是双因素认证退化为单因素认证。

**致命缺陷（2分）**：验证码备份通道（邮箱）的认证强度**低于**主认证通道（VPN）。攻击者不攻击VPN本体，而是攻击了更薄弱的邮箱环节，间接获取了验证码。这违反了"安全等级应由最弱环节决定"的原则。

**(2) 密码复用风险（3分）**

**两个严重错误（2分）**：
- ① **密码与个人信息强相关**：使用生日`19750815`，极易被社工猜解
- ② **密码在不同平台复用**：论坛泄露的密码直接用于企业邮箱

**风险类型（1分）**：**凭证填充（Credential Stuffing，俗称撞库）**——利用用户在多个平台使用相同密码的习惯，用已泄露的凭证尝试登录高价值目标。

**(3) 改进方案设计（3分）**

- **密码策略维度**：部署密码复杂度检测+弱口令黑名单，拦截包含姓名、生日、连续数字的密码；定期对接已知泄露密码库（如HaveIBeenPwned）
- **认证流程维度**：取消验证码邮件备份，或对邮件通道增加独立验证（如要求回答安全问题、人脸识别、或联系管理员人工审核）。关键是**备份通道的认证强度不能低于主通道**
- **会话管理维度**：引入设备指纹+异常行为检测。当检测到新设备/新地点登录时，额外要求管理员审批或Push确认，发送登录告警通知

## 第三部分：需要重点强化的其他薄弱点速查

### 访问控制中容易混淆的概念

| 概念 | 要点 |
|------|------|
| DAC | 所有者决定，权限可传递，Unix文件rwx |
| MAC | 系统强制，基于安全标签，军事场景 |
| RBAC | 角色中间层，企业场景 |
| ABAC | 属性动态决策，最灵活 |

### BLP vs Biba 一句话记忆
- **BLP** = 保密：不敢往上读，不敢往下写（保密信息不会往下流）
- **Biba** = 完整：不敢往下读（怕读到脏数据），不敢往上写（怕污染干净数据）

### 防火墙部署结构
| 结构 | 防火墙数 | DMZ | 安全性 |
|------|---------|-----|--------|
| 屏蔽子网 | 2个 | 有 | 高 |
| 屏蔽主机 | 1个 | 无 | 中 |

### TLS握手流程（记住5步核心）
```
ClientHello → ServerHello → Certificate → ClientKeyExchange → Finished
```

### TCP三次握手与SYN Flood
```
正常：SYN → SYN-ACK → ACK（三次握手完成）
攻击：大量SYN(伪造源IP) → SYN-ACK发往假IP → 服务器一直等待ACK → 半连接队列表满
```
