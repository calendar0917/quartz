## 一、SSL/TLS概述 ★★★★★

### 1.1 SSL/TLS是什么

**SSL（Secure Sockets Layer）**：安全套接字层，由Netscape发明
**TLS（Transport Layer Security）**：传输层安全，SSL的升级版，IETF标准

TLS 1.0 = SSL 3.0的改进版

### 1.2 SSL/TLS在协议栈中的位置

```
协议栈位置：
├── 应用层（HTTP、FTP、SMTP）
├── SSL/TLS层 ← 工作在这里
├── 传输层（TCP）
├── 网络层（IP）
└── 物理层
```

**关键点**：SSL/TLS位于传输层之上、应用层之下

### 1.3 SSL/TLS的作用

为上层应用（如HTTP）提供安全的传输通道：
- 机密性（加密）
- 完整性（防篡改）
- 认证（身份验证）

### 1.4 SSL/TLS的历史

| 版本 | 年份 | 状态 |
|------|------|------|
| SSL 2.0 | 1995 | 不安全，已弃用 |
| SSL 3.0 | 1996 | 不安全，已弃用 |
| TLS 1.0 | 1999 | 基本安全 |
| TLS 1.1 | 2006 | 改进 |
| TLS 1.2 | 2008 | 主流，推荐使用 |
| TLS 1.3 | 2018 | 最新，更安全更快 |

### 1.5 ⚠️ 考点重点

**填空题/判断题可能考点：**
- SSL/TLS位于传输层之上、应用层之下
- TLS是SSL的升级版
- SSL/TLS提供机密性、完整性和认证

## 二、SSL/TLS的四个子协议 ★★★★★

### 2.1 四个子协议概览

| 子协议 | 功能 | 重要性 |
|--------|------|--------|
| **握手协议** | 协商密钥、身份认证 | ★★★★★ |
| **密码规范协议** | 确定加密算法 | ★★★★ |
| **报警协议** | 传递错误和警告信息 | ★★★ |
| **记录协议** | 数据分片、压缩、加密、传输 | ★★★★ |

### 2.2 握手协议（Handshake Protocol）

**核心任务**：在通信开始前，双方协商安全参数、验证身份、建立共享密钥。

**握手过程（简化版）**：

```
握手流程：

客户端                                    服务器
  |                                          |
  |--- 1. ClientHello ------------------->  |
  |    （支持的TLS版本、加密算法、随机数）       |
  |                                          |
  |<-- 2. ServerHello --------------------  |
  |    （选定的加密算法、随机数）                 |
  |                                          |
  |<-- 3. Certificate --------------------  |
  |    （服务器的数字证书）                      |
  |                                          |
  |<-- 4. ServerHelloDone ----------------  |
  |                                          |
  |--- 5. ClientKeyExchange ------------->  |
  |    （预主密钥，用服务器公钥加密）              |
  |                                          |
  |--- 6. ChangeCipherSpec -------------->  |
  |--- 7. Finished --------------------->  |
  |                                          |
  |<-- 8. ChangeCipherSpec ---------------  |
  |<-- 9. Finished ---------------------   |
  |                                          |
  |    （开始加密通信）                         |
```

**关键步骤说明**：

| 步骤 | 内容 | 目的 |
|------|------|------|
| ClientHello | 客户端支持的算法列表、随机数 | 协商开始 |
| ServerHello | 选定的算法、服务器随机数 | 确定参数 |
| Certificate | 服务器的数字证书 | 身份认证 |
| ClientKeyExchange | 预主密钥（用服务器公钥加密） | 密钥交换 |
| Finished | 握手完成消息（用新密钥加密） | 验证握手完整性 |

### 2.3 密码规范协议（CipherSpec Protocol）

**功能**：确定通信中使用的加密算法、密钥长度、散列算法等。

**作用**：
- 双方确认使用的加密套件
- 通知对方切换到新确定的密码规范

### 2.4 报警协议（Alert Protocol）

**功能**：传递错误和警告信息。

**两种级别**：

| 级别 | 说明 | 处理 |
|------|------|------|
| **警告（Warning）** | 非致命错误 | 可能继续通信 |
| **致命（Fatal）** | 致命错误 | 立即终止连接 |

**常见警报**：
- unexpected_message：收到意外消息
- bad_record_mac：记录MAC错误
- handshake_failure：握手失败

### 2.5 记录协议（Record Protocol）

**功能**：对上层数据进行处理后传输。

**处理流程**：

```
记录协议处理流程：

1. 分片（Fragmentation）
   └── 将应用数据分成适当大小的块

2. 压缩（Compression）（可选）
   └── 对数据进行压缩

3. 加密（Encryption）
   └── 使用协商的加密算法加密数据

4. 添加头部
   └── 内容类型、版本、长度

5. 完整性保护
   └── 添加MAC或使用AEAD

6. 传输
   └── 通过TCP发送
```

**记录格式**：

```
┌──────────────────────────────────┐
│ 内容类型（1字节）                    │
│ 版本（2字节）                       │
│ 长度（2字节）                       │
│ 加密数据（可变长度）                 │
│ MAC（可选）                         │
│ 填充（可选）                        │
└──────────────────────────────────┘
```

## 三、SSL/TLS的安全服务 ★★★★★

### 3.1 提供的安全服务

| 服务 | 实现方式 | 说明 |
|------|---------|------|
| **机密性** | 对称加密（AES、3DES） | 防止窃听 |
| **完整性** | MAC或AEAD | 防止篡改 |
| **认证** | 数字证书 | 身份验证 |

### 3.2 密钥交换机制

**预主密钥（Pre-master Secret）**：
- 客户端生成随机的预主密钥
- 用服务器公钥加密后发送
- 服务器用私钥解密
- 双方用预主密钥生成主密钥

**主密钥（Master Secret）生成**：
```
主密钥 = PRF(预主密钥, "master secret", 客户端随机数 + 服务器随机数)
```

**会话密钥生成**：
```
客户端写密钥 = PRF(主密钥, "client write", 客户端随机数 + 服务器随机数)
服务器写密钥 = PRF(主密钥, "server write", 客户端随机数 + 服务器随机数)
```

### 3.3 身份认证机制

**服务器认证**：
- 客户端验证服务器的数字证书
- 确认证书由可信CA签发
- 确认证书在有效期内

**客户端认证**（可选）：
- 服务器请求客户端证书
- 客户端发送证书
- 服务器验证客户端身份

## 四、SSL/TLS的应用 ★★★★

### 4.1 HTTPS（HTTP over SSL/TLS）

**HTTPS = HTTP + SSL/TLS**

**工作原理**：
1. 浏览器发起HTTPS连接
2. 执行SSL/TLS握手
3. 建立安全通道
4. 在安全通道上运行HTTP

**端口**：HTTPS默认使用端口443（HTTP使用80）

**应用场景**：
- 网上银行
- 电子商务
- 需要保护隐私的网站

### 4.2 SSL VPN

**SSL VPN**：基于SSL/TLS的VPN，允许用户通过浏览器远程访问内部网络。

**优点**：
- 无需安装专用客户端
- 穿越防火墙和NAT
- 使用方便

**应用场景**：
- 远程办公
- 移动办公

### 4.3 其他应用

- 安全电子邮件（SMTPS、IMAPS）
- 安全文件传输（FTPS）
- 安全即时通讯

## 五、SSL/TLS vs IPSec

| 方面 | SSL/TLS | IPSec |
|------|---------|-------|
| **层级** | 传输层之上 | 网络层 |
| **主要应用** | Web浏览、HTTPS | VPN、站点互联 |
| **客户端支持** | 浏览器内置 | 需要客户端软件 |
| **部署复杂度** | 简单 | 复杂 |
| **防火墙穿越** | 容易（使用443端口） | 困难 |
