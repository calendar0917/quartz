## 一、IDS基本概念

### 1.1 什么是入侵检测系统

**IDS（Intrusion Detection System）**：入侵检测系统，监控网络流量或系统活动，检测可疑行为和攻击，发出警报。

### 1.2 IDS的作用

| 作用 | 说明 |
|------|------|
| **检测攻击** | 识别已知和未知攻击 |
| **告警通知** | 发现攻击时发出警报 |
| **审计记录** | 记录网络活动，便于分析 |
| **威胁评估** | 评估安全威胁的程度 |
| **协助响应** | 为安全响应提供信息 |

### 1.3 IDS与防火墙的区别

| 方面 | IDS | 防火墙 |
|------|-----|--------|
| **主要功能** | 检测和告警 | 阻断和过滤 |
| **工作方式** | 被动监控 | 主动防御 |
| **部署位置** | 旁路部署 | 串接部署 |
| **对性能影响** | 小 | 大 |
| **检测未知攻击** | 能（异常检测） | 不能（规则有限） |

### 1.4 IDS的局限性

- 不能主动阻断攻击（只告警）
- 误报率高
- 需要大量存储和处理资源
- 需要专业人员分析
- 不能防御内部攻击

## 二、三大分析方法

### 2.1 三种分析方法概览

| 方法 | 英文 | 特点 | 准确性 |
|------|------|------|--------|
| **专家系统法** | Expert System | 基于规则和知识库 | 高（已知攻击） |
| **统计分析法** | Statistical Analysis | 基于统计模型 | 中 |
| **机器学习法** | Machine Learning | 基于训练数据 | 高（但需要大量数据） |

### 2.2 专家系统法

**原理**：使用预定义的规则和知识库来检测攻击。

**工作流程**：
```
网络流量 → 特征提取 → 规则匹配 → 攻击检测
                    ↑
              规则/知识库
```

**优点**：
- 实现简单
- 检测速度快
- 对已知攻击检测率高

**缺点**：
- 不能检测未知攻击
- 规则库需要定期更新
- 无法适应新环境

### 2.3 统计分析法

**原理**：建立正常行为的统计模型，将偏离模型的行为视为异常。

**工作流程**：
```
网络流量 → 统计建模 → 偏差计算 → 异常检测
                  ↓
            历史数据
```

**常用统计方法**：
- 均值、方差
- 时间序列分析
- 回归分析

**优点**：
- 能检测未知攻击
- 适应性较强

**缺点**：
- 误报率高
- 需要大量历史数据
- 建模复杂

### 2.4 机器学习法

**原理**：使用机器学习算法从训练数据中学习攻击模式。

**常用算法**：
- 决策树
- 支持向量机（SVM）
- 神经网络
- 聚类分析

**优点**：
- 自动学习
- 能检测复杂攻击
- 适应性强

**缺点**：
- 需要大量标注数据
- 训练时间长
- 可解释性差

### 2.5 三种方法对比

| 方面 | 专家系统 | 统计分析 | 机器学习 |
|------|---------|---------|---------|
| **原理** | 规则匹配 | 统计建模 | 数据学习 |
| **检测能力** | 已知攻击 | 未知攻击 | 已知+未知 |
| **准确率** | 高 | 中 | 高 |
| **误报率** | 低 | 高 | 中 |
| **适应性** | 低 | 中 | 高 |
| **复杂度** | 低 | 中 | 高 |

## 三、两大检测方法

### 3.1 基于特征/知识的检测（Signature-based）

**原理**：将当前流量与已知攻击的特征库进行匹配。

**工作流程**：
```
网络流量 → 特征提取 → 特征库匹配 → 攻击检测
                    ↑
            攻击特征库
```

**特征示例**：
```
特征1：SQL注入攻击
特征：UNION SELECT * FROM users--
匹配：如果流量中包含此字符串，判定为攻击

特征2：缓冲区溢出
特征：超过1024字节的HTTP请求
匹配：如果请求长度超过1024，判定为攻击
```

**优点**：
- 检测率高（对已知攻击）
- 误报率低
- 实现简单
- 处理速度快

**缺点**：
- 不能检测未知攻击（零日攻击）
- 特征库需要定期更新
- 需要人工维护特征库

**类似**：杀毒软件的病毒特征库

### 3.2 基于异常/启发式的检测（Anomaly-based）

**原理**：建立正常行为的基线，将偏离基线的行为视为入侵。

**工作流程**：
```
网络流量 → 建立基线 → 偏差分析 → 异常检测
                ↓
          历史数据训练
```

**基线建立**：
- 正常流量的统计特征
- 用户行为模式
- 系统活动模式

**异常判定**：
- 流量超过基线阈值
- 行为偏离正常模式
- 未授权的访问尝试

**优点**：
- 能检测未知攻击
- 不需要预定义特征
- 适应性强

**缺点**：
- 误报率高（正常变化可能被误判）
- 需要大量训练数据
- 基线建立复杂
- 检测速度慢

**类似**：异常检测、行为分析

### 3.3 两种检测方法对比

| 方面 | 基于特征 | 基于异常 |
|------|---------|---------|
| **原理** | 特征匹配 | 基线偏差 |
| **检测能力** | 已知攻击 | 未知攻击 |
| **误报率** | 低 | 高 |
| **漏报率** | 高（未知攻击） | 低 |
| **适应性** | 低（需更新特征库） | 高 |
| **复杂度** | 低 | 高 |
| **应用** | 主流IDS | 辅助检测 |

### 3.4 实际应用中的结合

现代IDS通常结合两种方法：
- **基于特征**：检测已知攻击
- **基于异常**：检测未知攻击
- **混合检测**：提高整体检测率

### 3.5 IDS的三个逻辑组件

**检测器（Detector）**：
- 负责采集网络流量或系统活动数据
- 从网络接口、系统日志等获取原始数据
- 是IDS的输入端

**分析器（Analyzer）**：
- 负责对采集的数据进行分析
- 应用特征匹配或异常检测算法
- 判断是否为攻击行为
- 是IDS的核心处理单元

**用户接口/处理器（User Interface/Processor）**：
- 负责展示分析结果
- 发出告警通知
- 记录攻击日志
- 提供管理界面
- 是IDS的输出端

**三个组件的工作流程**：
```
检测器 → 分析器 → 用户接口
  ↑        ↑        ↑
采集数据  分析判断  展示告警
```
- 基于特征的检测匹配已知攻击
- 基于异常的检测能发现未知攻击
- 基于特征的误报率低
- 基于异常的误报率高

## 四、IDS的三个逻辑组件 ★★★

### 4.1 三个组件概览

| 组件 | 功能 | 说明 |
|------|------|------|
| **检测器（Sensor）** | 数据采集 | 收集网络流量或系统日志 |
| **分析器（Analyzer）** | 分析检测 | 分析数据，检测攻击 |
| **用户接口/管理器（Manager）** | 管理告警 | 显示结果、配置策略、发出警报 |

### 4.2 检测器（Sensor）

**功能**：采集数据源，如网络流量、系统日志、应用程序日志等。

**部署位置**：
- 网络关键节点
- 服务器
- 防火墙后

### 4.3 分析器（Analyzer）

**功能**：对采集的数据进行分析，检测攻击和异常。

**分析方法**：
- 特征匹配
- 异常检测
- 统计分析

### 4.4 用户接口/管理器（Manager）

**功能**：
- 显示检测结果
- 发出警报通知
- 配置IDS策略
- 生成报告

## 五、IDS的部署

### 5.1 部署位置

```
互联网
    ↓
防火墙
    ↓
IDS（旁路部署）
    ↓
内部网络
```

**关键点**：
- IDS通常旁路部署（不串接）
- 不影响网络性能
- 只监听不阻断

### 5.2 部署策略

| 位置 | 监控内容 |
|------|---------|
| 防火墙外 | 互联网攻击 |
| 防火墙内 | 内部攻击 |
| DMZ | 对外服务器 |
| 关键服务器 | 服务器安全 |
