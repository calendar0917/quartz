## 一、加密、认证、证书体系

### 1.1 对称 vs 非对称加密

| | 对称加密 | 非对称加密 |
|---|---------|-----------|
| 密钥 | **1个**（加解密同一密钥） | **2个**（公钥+私钥） |
| 速度 | 快 | 慢（100-1000倍） |
| 密钥管理 | n人需C(n,2)个 → 难 | n人需2n个 → 易 |
| 算法 | DES/3DES/**AES**/RC4 | **RSA**/ECC/Diffie-Hellman |
| 用途 | 大数据加密 | 密钥交换、数字签名 |

**混合加密**：非对称交换密钥 + 对称加密数据（SSL/TLS就这模式）

### 1.2 数字签名 ★★★

```
发送方：散列(消息) → 私钥加密摘要 → 数字签名
接收方：公钥解密签名 → 对新消息做散列 → 对比摘要
```

**三安全目标**：完整性（防篡改）+ 来源认证（私钥唯一）+ 不可否认（只有发送方有私钥）

> **私钥签，公钥验**。签名≠加密：签名用私钥（谁签），加密用公钥（发给谁）

### 1.3 三种认证方式

| 方式 | 是什么 | 优点 | 缺点 |
|------|--------|------|------|
| 口令 | 知道的（密码） | 简单/低成本 | 易被破解/窃取/重放 |
| 令牌 | 拥有的（短信/U盾） | 比口令安全 | 可丢失/短信可截获 |
| 生物特征 | 本身的（指纹/虹膜） | 唯一/难伪造 | 成本高/不可撤销（丢了就是永远丢了） |

**口令威胁**：暴力破解、字典攻击、社会工程学、重放攻击（协议风险）、窃听

### 1.4 密码加盐（Salt）

- 加盐 = 随机值 + 密码 → 散列存储
- 防彩虹表（相同密码不同盐 → 不同散列值）
- **加盐不能防暴力破解**（需要慢散列 bcrypt/Argon2）
- 盐值不需要保密

### 1.5 质询-应答（Challenge-Response）

服务器发随机数 → 用户用密码+随机数运算 → 服务器验证。密码不传网络，防重放。

### 1.6 散列函数安全要求

原像抵抗（单向）、第二原像抵抗、抗碰撞（**MD5/SHA-1已不安全**）

### 1.7 X.509 数字证书

证书内容：版本、序列号、签名算法、颁发者(CA)、**有效期**、主体、**主体公钥**、CA签名

⚠️ 证书**不含私钥**！私钥持有者自存。

### 1.8 PKI 公钥基础设施

| 组件 | 职责 |
|------|------|
| CA | 颁发/更新/吊销证书（核心） |
| RA | 验证用户身份 |
| 证书库 | 存储证书 |
| CRL/OCSP | 证书吊销状态查询 |

## 二、访问控制 ★★★★★（保护域 = 大题）

### 2.1 三要素

**主体**（谁访问）+ **客体**（访问什么）+ **访问权限**（做什么操作）

### 2.2 四种模型

| 模型 | 谁分配权限 | 特点 | 场景 |
|------|----------|------|------|
| DAC | 资源**所有者** | 灵活/安全性低 | 个人PC |
| MAC | **系统**强制（安全标签） | 严格/不灵活 | 军事/政府 |
| RBAC | 通过**角色**间接授权 | 易管理/可扩展 | 企业应用 |
| ABAC | 基于**属性**动态决策 | 最灵活 | 云/分布式 |

### 2.3 保护域 ★★★ 大题

**定义**：一个主体在某一时刻拥有的一组访问权限的集合。

**保护域 = 访问控制矩阵的一行**

```
示例：学生"李明"的保护域 = {读自己成绩, 修改自己选课, 查课程信息}
      老师"王芳"的保护域 = {读所有学生成绩, 写成绩, 改课程信息}
```

**保护域的作用**：最小权限原则、职责分离、灵活授权、安全隔离

### 2.4 BLP vs Biba

| | BLP（机密性） | Biba（完整性） |
|---|-------------|--------------|
| 读规则 | **不能向上读** | **不能向下读** |
| 写规则 | **不能向下写** | **不能向上写** |
| 一句话 | 保密信息不往下流 | 脏数据不往上跑 |

> BLP（Bell-LaPadula类似Bell → "保"→保密性）；Biba（类似Bible"比"较完整→完整性）

### 2.5 三原则

- **最小权限原则**：只授予完成任务所需的最小权限
- **默认拒绝原则**：凡未明确允许的，一律拒绝
- **知情权原则（Need-to-Know）**：只访问确实需要知道的信息

## 三、数据库安全与SQL注入 ★★★

### 3.1 SQL注入原理

用户输入被**直接拼接到SQL语句**中执行 → 恶意SQL被当作合法指令执行

```
输入：' OR '1'='1' --
结果：SELECT * FROM users WHERE username='' OR '1'='1' --' AND password='...'
                                        ↑恒为真，绕过认证
```

### 3.2 SQL注入类型

| 类型 | 特征 |
|------|------|
| 带内（In-band） | 结果**直接显示**在页面中（联合查询/报错注入） |
| 带外（Out-of-band） | 结果通过DNS/HTTP等**外部信道**传回 |
| 推理（Inference/Blind） | 通过**响应差异**推断（时间盲注=利用sleep延时） |

### 3.3 SQL注入防御（至少记住3种）

1. **参数化查询（Prepared Statement）**——核心：输入当数据，不当代码
2. 输入验证与转义——过滤`' " ; --`等特殊字符
3. 最小权限——DB账户只给SELECT不给DROP
4. WAF——检测阻断SQL注入

### 3.4 推理攻击（统计推理）

通过组合多次合法查询反推个体。例：两次AVG(salary)求差值=某员工工资。
防御：结果集大小限制、数据扰动、查询审计。

### 3.5 数据库加密粒度

表级 → 列级 → 字段级（越细越灵活，管理越复杂）；TDE透明加密（业界主流）

## 四、恶意软件 ★★★

### 4.1 四类对比

| 类型 | 是否独立 | 传播方式 | 典型 | 关键特征 |
|------|---------|---------|------|---------|
| 病毒 | ❌需宿主 | 文件感染 | CIH | 依赖宿主、可重装清除 |
| 蠕虫 | ✓独立 | 网络自动扫描 | WannaCry、莫里斯 | 自动传播、**爆发趋势** |
| 木马 | 伪装 | 用户下载 | 灰鸽子 | 伪装合法软件、后门 |
| 勒索软件 | 独立 | 多种途径 | WannaCry | 加密文件（Office文档）勒索 |

**病毒**：寄生宿主程序，人为运行/复制传播，重装系统可清除
**蠕虫**：独立程序，利用网络漏洞自动传播，传播呈**爆发趋势**（D2-3爆发曲线图）
**缓冲区溢出与恶意软件的关系**：莫里斯蠕虫利用缓冲区溢出漏洞

### 4.2 APT（高级持续性威胁）

五特征：高级、持续、威胁、**针对性**、多阶段。vs普通攻击：长期潜伏、明确目标。

### 4.3 恶意软件载荷

- 僵尸网络（Botnet）→ DDoS、垃圾邮件
- 键盘记录器 → 窃取密码
- 钓鱼 → 伪造网站/邮件
- **Rootkit**：隐藏自身（用户态=替换系统命令 → 内核态=劫持系统调用表 → 固件级=BIOS/UEFI）

### 4.4 恶意软件对抗措施

预防（杀毒/补丁/白名单）→ 检测（IDS/行为分析）→ 响应（隔离/清除/恢复/取证）

## 五、拒绝服务攻击（DoS）★★★

### 5.1 SYN Flood ★

**攻击TCP层** → 利用三次握手缺陷：
```
攻击者发大量SYN(源IP伪造) → 服务器回复SYN-ACK → 等待ACK → 半连接队列表满 → 正常用户无法连接
```

### 5.2 反射放大攻击

**DNS反射放大**：小请求(54B) → DNS ANY查询 → 大响应(3000B+) → 放大50+倍
**NTP反射放大**：monlist命令放大倍数更高
**Smurf攻击**：伪造受害者IP → 发ICMP到广播地址 → 子网所有主机回复受害者

### 5.3 泛洪攻击类型

| 类型 | 攻击层 | 消耗目标 |
|------|--------|---------|
| SYN Flood | TCP | 连接表资源 |
| UDP Flood | UDP | CPU（检查端口）+ 带宽 |
| ICMP/Ping Flood | ICMP | 带宽 + 处理能力 |
| HTTP Flood | 应用层 | Web服务器CPU |

### 5.4 DoS防御

SYN Cookie（不立即分配资源）、防火墙过滤、IDS检测、流量清洗、CDN分散、限流

## 六、入侵检测系统（IDS）★★★

### 6.1 三大分析方法

- **专家系统法**：规则/知识库匹配 → 检测已知攻击，误报率低
- **统计分析法**：统计建模 → 基线偏差 → 检测未知攻击，误报率高
- **机器学习法**：训练学习 → 检测复杂攻击，需大量数据

### 6.2 两大检测方法

| | 基于特征（签名） | 基于异常（启发式） |
|---|---------------|-----------------|
| 原理 | 匹配已知攻击特征库 | 建立正常基线，偏离即报警 |
| 检测能力 | 已知攻击 | **未知攻击**（0day） |
| 误报率 | **低** | **高** |
| 漏报率 | 高（无法检测未知） | 低 |

### 6.3 三个逻辑组件 ★

**检测器（Sensor）** → 采集数据（流量/日志）
**分析器（Analyzer）**→ 分析判断（核心处理）
**用户接口（Manager）** → 展示告警

### 6.4 HIDS vs NIDS

- HIDS：每台主机部署，查**文件完整性/系统调用/进程行为** → 能看加密后活动
- NIDS：网络节点旁路部署，查**网络流量** → 一个设备覆盖全网段，但对加密流量无能为力

### 6.5 蜜罐

故意设诱饵系统吸引攻击者。优势：误报极低（所有访问都异常）、捕获未知攻击、研究攻击手法。

### 6.6 IDS vs IPS vs 防火墙

| | IDS | IPS | 防火墙 |
|---|-----|-----|--------|
| 部署 | **旁路** | **串接** | 串接 |
| 功能 | 检测+告警 | 检测+**阻断** | 过滤+阻断 |
| 故障影响 | 不影响业务 | 中断网络 | 中断网络 |

## 七、防火墙与IPS ★★★★★（DMZ = 必考）

### 7.1 三种防火墙

| | 包过滤 | 状态检测 | 应用代理 |
|---|--------|---------|---------|
| 工作层 | 网络/传输层 | 网络-应用层 | 应用层 |
| 检查 | IP头+端口 | 包头+**连接状态表** | 全部内容深度检查 |
| 安全 | 低 | 中 | 高 |
| 性能 | 高 | 中 | 低 |

**状态检测核心**：维护连接状态表（源IP/目的IP/源端口/目的端口/协议/状态/超时），根据状态动态决策。

### 7.2 DMZ（隔离区）★ 必考

**定义**：内外网之间的独立安全缓冲区域。放置对外服务器（Web/邮件/DNS）。

**核心价值**：即使DMZ被攻破，攻击者无法直接访问内部网络。

### 7.3 两种部署结构 ★

| | 屏蔽子网 | 屏蔽主机 |
|---|---------|---------|
| 防火墙 | **2个** | **1个** |
| 结构 | 外部防火墙 → DMZ → 内部防火墙 → 内网 | 防火墙 → 堡垒主机 → 内网 |
| 安全 | 高（双重防线） | 中（单点失败全暴露） |
| 成本 | 高 | 低 |

### 7.4 防火墙与路由器

路由器 = 路由转发 + 基本过滤；防火墙 = 深度安全检查 + 精细策略。协同 = 分层防御。

### 7.5 UTM（统一威胁管理）

防火墙+IDS/IPS+防病毒+VPN+内容过滤 集成一台设备。

## 八、缓冲区溢出 ★★★★★（代码题！）

### 8.1 定义

程序写入数据超过缓冲区大小 → 覆盖相邻内存 → 数据破坏/控制流劫持/执行恶意代码。

**持续原因**：遗留代码多 + 编程习惯差 + C/C++不自动检查边界。

### 8.2 漏洞类型

| 类型 | 位置 | 攻击目标 | 危险 |
|------|------|---------|------|
| 栈溢出 | 函数栈 | **返回地址** | ★最高——劫持控制流 |
| 堆溢出 | 动态分配堆 | **函数指针/虚表指针** | 高 |
| 全局数据区溢出 | 全局/静态区 | 相邻关键数据 | 中 |

### 8.3 栈溢出原理（核心）

```
栈布局（高→低）：返回地址 → 旧EBP → 局部变量(如auth_flag) → buffer
溢出方向：buffer → 覆盖auth_flag → 覆盖返回地址 → 劫持控制流
```

### 8.4 Shellcode

攻击用的**机器码**（不是高级语言），与CPU架构+OS紧密相关。通常功能=启动Shell。

### 8.5 防御措施

| 方法 | 类型 | 原理 |
|------|------|------|
| 安全语言(Java/Python) | 编译时 | 自动边界检查 |
| **Stack Canary（栈金丝雀）** | 运行时 | 返回地址前插随机值，返回前检查 |
| NX/DEP（不可执行栈） | 运行时 | 标记栈/堆为不可执行 |
| **ASLR（地址随机化）** | 运行时 | 随机化栈/堆/库加载地址 |
| 隔离带 | 运行时 | 设置不可访问内存区域 |
| **替换危险函数** | 编码 | strcpy→strncpy, gets→fgets |

## 九、Internet安全协议

### 9.1 SSL/TLS ★★★

**位置**：传输层之上、应用层之下。TLS 1.3最新。

**四个子协议**：
- **握手协议**（核心）：协商参数 + 密钥交换 + 身份认证
- 密码规范协议：确定加密算法
- 报警协议：警告/致命错误
- **记录协议**：数据分片+加密+传输

**握手流程**（5步）：ClientHello → ServerHello → Certificate → ClientKeyExchange → Finished

**预主密钥**：客户端生成，用服务器**公钥**加密发送。与双方随机数一起派生会话密钥。

**安全服务**：机密性（对称加密）+ 完整性（MAC）+ 认证（数字证书）

**HTTPS = HTTP + 数字签名 + 数据加密**（端口443）

**TLS vs IPSec**：TLS传输层之上（Web/浏览器内置），IPSec网络层（VPN/网关间）

### 9.2 IPSec ★★

| | AH | ESP |
|---|-----|-----|
| 加密 | ✗ | **✓** |
| 认证 | ✓ | ✓ |
| NAT穿越 | ✗ | ✓ |

**传输模式**：保留原IP头，只保护载荷（主机-主机）
**隧道模式**：封装整个原IP包+新IP头（网关-网关/VPN）

### 9.3 Kerberos ★★

**考点**：知道组件，不需要背6步交互流程。

| 组件 | 全称 | 功能 |
|------|------|------|
| KDC | 密钥分发中心 | 可信第三方（AS+TGS） |
| AS | 认证服务器 | 验证用户，发TGT |
| TGS | 票据授权服务器 | 验证TGT，发服务票据 |
| **TGT** | 票据授权票据 | 证明已认证，可换服务票据 |
| 服务票据 | Service Ticket | 访问特定服务的凭证 |

**核心机制**：对称加密 + 票据 + 时间戳（防重放）+ 会话密钥
**优点**：单点登录（SSO）
**缺点**：依赖时间同步 → 时钟偏差过大会认证失败

### 9.4 S/MIME

邮件端到端安全：数字签名 + 数据加密

### 9.5 IPv4 vs IPv6

IPv6中**IPSec强制实现**（IPv4中可选）。不免疫所有攻击，仍需防火墙。
