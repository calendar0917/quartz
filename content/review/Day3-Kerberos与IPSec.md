## 一、Kerberos认证协议 ★★★

### 1.1 Kerberos是什么

**Kerberos**：一种基于对称密码学的网络认证协议，允许用户通过票据（Ticket）在非安全网络上进行身份验证，确保通信的安全性。

### 1.2 Kerberos的核心思想

**核心问题**：如何在不安全的网络上安全地验证用户身份？

**解决方法**：引入可信的第三方——**KDC（密钥分发中心）**

### 1.3 Kerberos的关键组件

| 组件 | 英文 | 说明 |
|------|------|------|
| **KDC** | Key Distribution Center | 密钥分发中心，可信第三方 |
| **AS** | Authentication Server | 认证服务器，负责验证用户身份 |
| **TGS** | Ticket Granting Server | 票据授权服务器，负责颁发服务票据 |
| **票据** | Ticket | 包含用户身份和服务信息的加密数据 |
| **密钥** | Key | 用于加密和解密的密钥 |

### 1.4 Kerberos的工作流程（简化版）

```
Kerberos认证流程：

1. 客户端 → AS：请求认证（包含用户名）
2. AS → 客户端：返回票据授权票据（TGT）和会话密钥
3. 客户端 → TGS：发送TGT + 服务请求
4. TGS → 客户端：返回服务票据
5. 客户端 → 服务器：发送服务票据
6. 服务器验证票据，完成认证
```

### 1.5 票据（Ticket）的作用

票据是Kerberos的核心概念：

| 票据类型 | 作用 |
|---------|------|
| **TGT（票据授权票据）** | 允许用户向TGS请求服务票据 |
| **服务票据** | 允许用户访问特定服务 |

### 1.6 Kerberos的安全机制

- **对称加密**：所有通信都使用对称加密
- **票据机制**：通过票据传递认证信息，避免重复输入密码
- **时间戳**：防止重放攻击
- **会话密钥**：为每次会话生成临时密钥

### 1.7 Kerberos的优点

- 单点登录（SSO）
- 安全性高
- 可扩展
- 互操作性好

### 1.8 Kerberos的局限性

- 依赖时间同步
- 需要可信的KDC
- 不适用于无Kerberos服务器的环境
- 初始认证需要输入密码

### 1.9 ⚠️ 考点重点

**填空题/判断题可能考点：**
- Kerberos基于对称加密
- KDC是可信的第三方
- TGT是票据授权票据
- Kerberos使用时间戳防止重放攻击

**简答题考点：**
- Kerberos的基本工作流程
- 票据的作用
- Kerberos的优缺点

### 1.10 记忆口诀

```

对称加密保安全

服务票据去访问
```

## 二、IPSec协议 ★★★

### 2.1 IPSec是什么

**IPSec（Internet Protocol Security）**：互联网协议安全，在IP层提供加密和认证，保护IP数据包的机密性、完整性和来源认证。

### 2.2 IPSec在协议栈中的位置

```
OSI模型：
├── 应用层（HTTP、FTP、SMTP）
├── 传输层（TCP、UDP）
├── 网络层（IP）  ← IPSec工作在这里
├── 数据链路层
└── 物理层
```

### 2.3 IPSec的核心协议

| 协议 | 英文 | 功能 | 工作层级 |
|------|------|------|---------|
| **AH** | Authentication Header | 认证和完整性保护 | 网络层 |
| **ESP** | Encapsulating Security Payload | 加密、认证和完整性保护 | 网络层 |
| **IKE** | Internet Key Exchange | 密钥交换和协商 | 应用层 |

### 2.4 AH协议（认证头）

**AH（Authentication Header）**：提供数据源认证和完整性保护，但不提供加密。

**功能：**
- 数据源认证（确认发送者身份）
- 数据完整性保护（防止篡改）
- 防重放攻击（通过序列号）

**AH头格式：**
- 下一个头
- 载荷长度
- 保留
- 安全参数索引（SPI）
- 序列号
- 认证数据（数字签名或MAC）

**AH的局限性：**
- 不提供加密
- 不能穿越NAT（网络地址转换）

### 2.5 ESP协议（封装安全载荷）

**ESP（Encapsulating Security Payload）**：提供加密、认证和完整性保护。

**功能：**
- 数据加密（使用对称加密算法）
- 数据源认证
- 数据完整性保护
- 防重放攻击

**ESP头格式：**
- 安全参数索引（SPI）
- 序列号
- 载荷数据（加密）
- 填充
- 填充长度
- 下一个头
- 认证数据

**ESP的优势：**
- 提供完整的安全服务
- 可以穿越NAT
- 比AH更常用

### 2.6 AH vs ESP对比

| 方面 | AH | ESP |
|------|-----|-----|
| 加密 | 不支持 | 支持 |
| 认证 | 支持 | 支持 |
| 完整性 | 支持 | 支持 |
| 防重放 | 支持 | 支持 |
| 穿越NAT | 不支持 | 支持 |
| 应用场景 | 只需认证不需加密 | 需要加密的场景 |

### 2.7 IPSec的工作模式

| 模式 | 说明 | 适用场景 | 特点 |
|------|------|---------|------|
| **传输模式** | 只加密/认证数据部分，IP头不变 | 主机到主机 | 开销小，不改变路由 |
| **隧道模式** | 加密/认证整个IP包，外加新IP头 | 网关到网关、VPN | 更安全，隐藏内部网络 |

### 2.8 传输模式详解

```
传输模式：
├── 原IP头（不变）
├── IPSec头（AH或ESP）
└── 数据（加密/认证）

特点：
- 只保护数据部分
- IP头不变（源、目的地址可见）
- 开销小
- 适用于主机到主机通信
```

### 2.9 隧道模式详解

```
隧道模式：
├── 新IP头（隧道端点地址）
├── IPSec头（AH或ESP）
├── 原IP头（加密）
└── 数据（加密）

特点：
- 整个原IP包被加密/认证
- 新IP头指示隧道端点
- 隐藏内部网络拓扑
- 适用于VPN
```

### 2.10 IPSec的应用场景

- **站点到站点VPN**：企业分支机构互联
- **远程访问VPN**：员工远程办公
- **安全通信**：保护敏感数据传输
- **IPv6安全**：IPSec在IPv6中是强制性的

### 2.11 ⚠️ 考点重点

**填空题/判断题可能考点：**
- IPSec工作在网络层
- AH提供认证，不提供加密
- ESP提供加密和认证
- 传输模式只保护数据，隧道模式保护整个IP包

**简答题考点：**
- AH和ESP的区别
- 传输模式和隧道模式的区别
- IPSec的工作原理

```
隧道全包住
```

## 三、Kerberos vs IPSec

| 方面 | Kerberos | IPSec |
|------|----------|-------|
| **层级** | 应用层 | 网络层 |
| **加密方式** | 对称加密 | 对称加密 |
| **主要功能** | 身份认证 | 数据保护（加密+认证） |
| **应用场景** | 网络登录认证 | 网络通信保护 |
| **依赖** | KDC服务器 | 密钥交换协议 |

#### 名词解释答案要点：

1. **Kerberos**：基于对称加密的网络认证协议，使用票据和可信第三方进行身份验证。

2. **KDC**：密钥分发中心，Kerberos中的可信第三方，负责颁发票据。

3. **TGT**：票据授权票据，允许用户向TGS请求服务票据。

4. **IPSec**：互联网协议安全，在IP层提供加密和认证，保护IP数据包。

- TGS返回服务票据
- 客户端用服务票据访问服务器

**2. AH vs ESP**

- ESP：加密、认证、完整性、可穿越NAT

**3. 传输 vs 隧道**

- 隧道：保护整个IP包，外加新IP头

**4. Kerberos优缺点**
- 优点：单点登录、安全、可扩展
- 缺点：依赖时间同步、需要KDC

**5. IPSec应用**
- 站点到站点VPN
- 远程访问VPN
- 安全通信
