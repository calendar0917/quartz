## 参考答案与详细解析

---

### 一、单项选择题

**1. C — CRL（证书吊销列表）**

CRL是PKI/X.509体系的组件，不属于Kerberos。Kerberos的核心组件包括KDC（由AS+TGS组成）、TGT、服务票据等。

**2. C — 保护域**

保护域（Protection Domain）的定义：一个主体在某一时刻拥有的一组访问权限的集合。这是大纲和教师录音中明确标注的大题考点。ACL是客体视角（哪些主体可访问该客体），能力表是主体视角的客体-权限列表（更接近保护域但不是标准术语）。

**3. C — IPv6强制实现IPSec支持**

这是IPv6相比IPv4的重要安全改进之一。IPSec在IPv4中是可选的，在IPv6中是强制要求实现的（RFC要求），但不等于天然免疫攻击或不需要防火墙。

**4. D — UDP Flood**

题干关键特征：UDP包 + 目标端口随机变化 + 消耗CPU逐个检查端口。SYN Flood使用的是TCP SYN包，消耗的是连接表而非CPU检查端口。Ping Flood是ICMP。TCP Flood是SYN Flood的一种。

**5. B — 建立正常行为基线，偏离即入侵**

异常检测的核心思想就是baseline deviation。A描述的是签名检测，C描述的是专家系统，D是沙箱技术。

**6. B — 证明用户已通过AS认证，可向TGS请求服务票据**

TGT = Ticket Granting Ticket（票据授权票据）。其作用是"票据的票据"——用它向TGS换服务票据。A描述的是服务票据的功能。

**7. A — 不能向上读阻止信息向下泄露**

BLP模型通过两条规则保护机密性："不能向上读"防止低级别主体读取高级别信息（阻止信息向下泄露给未授权用户）；"不能向下写"防止高级别主体将信息写入低级别区域（阻止已泄露信息的扩散）。两条规则共同阻止机密信息的向下流动。B选项的"向上泄露"表述错误。

**8. B — 蠕虫**

病毒需要宿主程序，蠕虫是独立的。木马需要用户交互下载。勒索软件有多种传播方式。蠕虫是最符合"不需要宿主+自动扫描网络漏洞"特征的。

**9. B — 存储型XSS**

关键特征：恶意代码"存入评论区数据库"+"任何访问该页面的用户都会执行"。这说明脚本已持久化在服务器端，属于存储型（Stored/Persistent）XSS。反射型在URL中，不存储。DOM型是纯客户端。CSRF不涉及脚本注入。

**10. C — 数据加密**

| 功能 | AH | ESP |
|------|-----|-----|
| 完整性 | ✓ | ✓ |
| 认证 | ✓ | ✓ |
| 防重放 | ✓ | ✓ |
| **加密** | ✗ | **✓** |

这就是AH和ESP的核心区别：AH不加密，ESP加密。

**11. C — 证书包含持有者的私钥**

X.509证书包含持有者的公钥、身份信息、CA签名等，但**绝对不包含私钥**。私钥由持有者自行保管。这是最基本的安全常识。

**12. D — 使用MD5加密存储数据库数据**

MD5是散列函数（且已不安全），不是SQL注入的防御手段。D选项描述的是数据存储安全（保护已存储数据的机密性），不是防御SQL注入攻击。A/B/C都是直接的SQL注入防御措施。

**13. C — 防火墙规则引擎**

IDS三个逻辑组件：检测器（Sensor/Detector）、分析器（Analyzer）、用户接口（User Interface/Manager）。防火墙规则引擎是防火墙的组件。

**14. A — CA是PKI核心，负责证书颁发/吊销/生命周期管理**

PKI的核心正确理解：CA负责证书的全生命周期。B错（PKI使用CRL和OCSP），C错（CA是可信第三方），D错（RA只做身份验证不签发证书，签发由CA完成）。

### 二、填空题

**15.** 主体、客体

访问控制三要素：主体（发起访问的实体）、客体（被访问的资源）、访问权限（主体对客体的操作能力）。

**16.** 暴力破解、字典攻击、社会工程学

口令面临的三大威胁：暴力破解（穷举所有组合）、字典攻击（利用常见口令列表）、社会工程学（心理欺骗）。此外还有重放攻击和窃听。

**17.** 非对称、对称

混合加密模式：非对称加密（如RSA/ECC）安全交换对称密钥（因为非对称加密慢但安全），对称加密（如AES）实际加密数据（因为对称加密快）。

**18.** 数字签名、数据加密

HTTPS = HTTP + 数字签名 + 数据加密。数字签名用于身份认证（证书），数据加密用于传输机密性（TLS对称加密）。

**19.** 特征/知识（签名）、异常/启发式

两大检测方法：基于特征（Signature-based，匹配已知攻击模式）+ 基于异常（Anomaly-based，定义正常基线）。

### 三、判断题

**20. √** — Biba模型保护完整性，"不能向上写"确指低完整性主体不能向高完整性客体写入，防止污染。

**21. ×** — Kerberos通过TGT实现单点登录（SSO），用户只需在初始时输入一次密码获得TGT，后续访问服务时用TGT换取服务票据，无需重复输入密码。

**22. ×** — 病毒**必须**依赖宿主程序，不能独立运行。只有蠕虫可以独立运行。

**23. ×** — 数字签名使用发送方的**私钥**签名，接收方用发送方的**公钥**验证。记住："私钥签，公钥验"。

**24. √** — 等保2.0将物联网（IoT）、云计算、移动互联、工业控制等纳入保护范围，这是相比等保1.0的重要扩展。

**25. ×** — 串联模式（inline）是**IPS**的特征，不是IDS。IDS的特征是旁路部署（SPAN/端口镜像）。

**26. ×** — 包过滤防火墙只检查包头（IP头、TCP/UDP头），不能检查载荷内容（payload）。应用代理防火墙才能深度内容检查。

**27. √** — 屏蔽子网结构 = 外部防火墙 → DMZ → 内部防火墙 → 内部网络。两个防火墙之间是DMZ区。

**28. √** — 勒索软件的典型行为是加密用户文件（特别是Office文档、PDF、图片等），然后索要赎金（通常以加密货币支付）。

**29. √** — Snort规则中的`sid`（Signature ID）是规则的唯一标识符。自定义规则从1000001开始编号。

### 四、简答题

**30. 三种认证方式优缺点**

**（1）口令认证（2分）**：
- **优点**：实现简单、成本低、用户接受度高、无需额外硬件
- **缺点**：易被窃取（肩窥、网络嗅探）、易受暴力破解和字典攻击、用户倾向选择弱口令、易被社会工程学获取
- **安全等级**：较低

**（2）基于令牌的认证（2分）**：
- **优点**：比口令更安全（需要物理持有）、支持远程验证（短信验证码）、可结合时间同步防重放（动态令牌）
- **缺点**：令牌可能丢失或被盗、短信可被截获/转发、需要额外成本、用户体验不如口令便捷
- **安全等级**：中等

**（3）生物特征认证（2分）**：
- **优点**：唯一性强（指纹、虹膜等终身不变）、不可替代（无法转移给他人）、难伪造（生物特征难以复制）
- **缺点**：成本高、受环境影响（温度、湿度、光照）、隐私问题突出（生物数据一旦泄露无法更改，不可撤销）、误识率（FAR/FRR）需要权衡
- **安全等级**：较高（但不可撤销是其独特风险）

**31. SQL注入攻击**

**（1）攻击原理（2分）**：
SQL注入是利用Web应用程序对用户输入校验不严的漏洞。攻击者在输入字段中插入恶意SQL代码片段，由于应用程序将用户输入直接拼接到SQL查询语句中执行，数据库会将恶意代码当作合法SQL指令的一部分来执行，导致攻击者绕过认证、获取未授权数据、篡改或删除数据。

**示例**：输入`' OR '1'='1' --`可绕过登录认证（使WHERE条件恒为真）。

**（2）攻击类型（2分）**：
- **带内注入（In-band）**：攻击结果直接显示在Web页面的正常响应中。包括联合查询注入（UNION SELECT）和报错注入。
- **带外注入（Out-of-band）**：攻击结果通过其他信道（如DNS、HTTP请求）传回攻击者，不直接显示在页面中。
- **推理攻击（Inference/Blind）**：攻击结果不直接显示，通过观察应用程序的不同响应推断数据和结构。包括布尔盲注和时间盲注（利用sleep/benchmark延时函数）。

**（3）防御措施（2分）**：
- **参数化查询（Prepared Statement）——核心方法**：将用户输入作为数据参数而非SQL代码执行，从根源上防止注入
- **输入验证与转义（防御性编码）**：对特殊字符（`' " ; --`等）进行转义或过滤
- **最小权限原则**：数据库账户仅授予必要的最小权限（如Web应用账户只需SELECT，不授予DROP/ALTER）
- **Web应用防火墙（WAF）**：部署WAF检测并阻断SQL注入攻击流量
- **存储过程**：使用预编译的存储过程封装SQL逻辑

**32. 防火墙与路由器**

**（1）分工不同（3分）**：
- **路由器**：主要功能是**路由转发**（根据路由表决定数据包的下一跳），提供基本的访问控制列表（ACL）过滤功能。重在网络连通性和转发效率。
- **防火墙**：主要功能是**安全防护**，深度检查数据包内容、维护连接状态、执行详细的安全策略。重在安全性。
- **协作**：路由器做第一层过滤（大流量初筛），防火墙做二层深度检查（精细策略执行），协同实现分层防御。

**（2）屏蔽子网中两防火墙职责（3分）**：
- **外部防火墙**（面向Internet）：第一道防线。允许Internet到DMZ中对外服务器的合法流量（如HTTPS 443、SMTP 25），拒绝所有其他入站流量。过滤明显的恶意攻击流量。
- **内部防火墙**（面向内部网络）：第二道防线（更严格）。限制DMZ到内部网络的访问（如DMZ Web服务器只允许访问内部数据库的特定端口），禁止DMZ直接访问内部敏感区域（如财务系统）。也限制内部到DMZ和Internet的出站流量。

**33. HIDS/NIDS与蜜罐**

**（1）HIDS vs NIDS（4分）**：

| 维度 | HIDS（基于主机） | NIDS（基于网络） |
|------|----------------|-----------------|
| **部署位置** | 部署在每台重要主机上 | 部署在网络关键节点（如核心交换机旁路） |
| **数据源** | 系统日志、文件完整性、进程行为、系统调用 | 网络流量包 |
| **检测能力** | 检测主机层面的异常：文件篡改、异常进程、权限提升、rootkit | 检测网络层面的攻击：端口扫描、DDoS、SQL注入、网络蠕虫传播 |
| **优势** | 可检测加密后解密的主机活动 | 一个设备覆盖整个网段 |
| **劣势** | 每台主机都需部署代理，管理成本高 | 对加密流量几乎无能为力 |

**（2）蜜罐优势（2分）**：
- **误报率极低（接近零）**：蜜罐本身不提供任何正常服务，所有对其的访问本质都是可疑的。不像IDS存在大量误报
- **捕获未知攻击**：蜜罐记录攻击者的完整攻击链和手法，可发现0day漏洞和新型攻击工具，而防火墙和IDS对未知攻击的检测有限
- **攻击者行为研究**：可观察攻击者的TTP（战术、技术和过程），获取攻击工具和C&C信息，这是防火墙和IDS无法提供的情报价值

**34. 保护域与访问控制矩阵** ⭐

**（1）保护域定义（4分）**：

保护域 = 一个主体在某一时刻对所有客体的权限集合（即访问控制矩阵中该主体所在行的全部权限）。

- **学生"李明"的保护域** = {读自己的基本信息(A), 读自己的成绩(B), 读课程信息(C)}（对外部访客的课程信息(C)无权限）
- **老师"王芳"的保护域** = {读所有学生基本信息(A), 读+写成绩(B), 读+写课程信息(C), 写成绩录入系统(D)}

**（2）最小权限与职责分离（4分）**：

- **最小权限原则**：教务员"张华"只能"读"成绩单，不能"写"（修改）——因为他只负责查阅成绩进行学籍管理，不需要修改成绩。授予"写"权限违反最小权限，会增加误操作或被攻击后成绩被篡改的风险。
- **职责分离原则**：修改成绩的权限被分配给老师"王芳"（通过成绩录入系统），而教务员负责学籍和课程管理。这种分离确保**单一人无法完成不合理的完整操作链**——教务员不能既查阅又修改成绩。同时，老师和教务员之间形成互相制约。

**（3）新增"班主任"角色（4分）**：

| 主体\客体 | 学生基本信息(A) | 成绩单(B) | 课程信息(C) | 成绩录入系统(D) |
|-----------|---------------|----------|-----------|---------------|
| 班主任 | 读（仅本班） | 读（仅本班） | 读 | — |

**与现有角色的区别**：
- 相比学生：班主任可以读本班其他学生的信息（学生只能读自己的）
- 相比老师：班主任没有"写"权限（不能修改成绩和课程信息），只有查阅权
- 相比教务员：班主任不能修改学生基本信息，也不涉及系统配置
- 本质是在RBAC中新增一个介于"老师"和"学生"之间的中间角色

**（2）访问控制策略（4分）**：

**外部防火墙（FW1）规则**：
- ① ALLOW Internet → DMZ/Web: TCP/443 (HTTPS) 已建立

- ⑥ ALLOW 内部/员工 → DMZ/邮件: TCP/110 (POP3) 已建立（内部员工取邮件）

**（3）屏蔽子网更安全的原因（3分）**：
- **双重防护**：攻击者需要突破两道防火墙才能从Internet到达内部网络。屏蔽主机只有一道防线。即使攻击者攻破外部防火墙和DMZ中的服务器，仍需突破内部防火墙才能触及内部核心数据
- **DMZ隔离缓冲**：对外服务器集中放置在物理/逻辑隔离的DMZ中。DMZ受攻击不影响内部网络安全。屏蔽主机中堡垒主机直接连通内网，一旦被攻破内网全面暴露
- **分层策略**：两道防火墙可实施不同精细度的策略。外部防火墙做粗粒度大流量过滤，内部防火墙做精细访问控制（如限制DMZ只能访问内部数据库特定端口，不能访问财务系统等敏感区域）

**36. 缓冲区溢出代码分析** ⭐

**（1）漏洞定位（3分）**：

**漏洞类型**：栈缓冲区溢出（Stack Buffer Overflow）

**漏洞位置**：第③行 `strcpy(buffer, password);`

**原因**：
- `buffer`仅声明为16字节（①行），但`strcpy`函数不检查目标缓冲区大小
- 如果`password`（即`argv[1]`）长度超过15个字符（留一位给`\0`），`strcpy`会继续将数据写入超出`buffer`范围的内存区域
- 超出部分会覆盖栈上相邻的`auth_flag`变量，甚至继续覆盖返回地址

**（2）内存布局与攻击分析（6分）**：

**栈内存布局**（典型x86/Linux，栈向低地址增长）：

```
高地址
┌──────────────────┐
│ main的返回地址    │
├──────────────────┤
│ main的旧EBP      │
├──────────────────┤
│ 返回地址 ←────── │ ← 被authenticate调用时压入
├──────────────────┤
│ 旧的EBP          │
├──────────────────┤
│ auth_flag (int)  │ ← 4字节，初始值=0
│  0x00 0x00 0x00 0x00│
├──────────────────┤
│ buffer[15]       │
│ ...              │ ← char buffer[16]
│ buffer[0]        │ ← strcpy从这里开始写入
└──────────────────┘
低地址
```

**攻击原理**（绕过认证）：
- `strcpy`从`buffer[0]`开始向高地址逐字节复制
- 如果输入 ≤15个字符：正常填充buffer，`auth_flag`保持为0
- **如果输入 ≥16个字符**：前16字节填满buffer；第17个字节开始覆盖`auth_flag`
- `auth_flag`原值为0（小端序：0x00 0x00 0x00 0x00），只需将其中任意1字节改为非零值（如0x01），`auth_flag ≠ 0`，认证即被绕过
- 实际攻击：输入任意超过15个字符的字符串，不需要知道密码即可获得`ACCESS GRANTED`

**（3）Shellcode攻击与防御（3分）**：

**进一步攻击（shellcode注入）**：
攻击者如果继续输入更长的字符串，在覆盖`auth_flag`后继续向上覆盖，可以：
- 覆盖返回地址，将其改为指向攻击者提供的shellcode（放在buffer中或环境变量中）
- 当`authenticate`函数返回时，程序跳转到shellcode执行，获得shell

**三种运行时防御技术**：

| 技术 | 原理 |
|------|------|
| **Stack Canary（栈金丝雀）** | 编译器在`auth_flag`和返回地址之间插入随机值（金丝雀）。函数返回前检查金丝雀是否被篡改——溢出覆盖返回地址必然先破坏金丝雀，检测到后立即终止程序 |
| **NX/DEP（不可执行栈）** | 利用CPU的NX位（或Windows DEP），将栈内存标记为不可执行。即使shellcode被写入栈，CPU也拒绝执行栈上的指令。攻击者无法直接执行栈中的shellcode |
| **ASLR（地址空间随机化）** | 每次程序运行时，随机化栈、堆、库、代码段的加载地址。攻击者无法预测shellcode的绝对地址和返回地址应该跳转到哪里，大大增加攻击难度 |

**组合防御**：安全函数（用`strncpy`/`fgets`替换`strcpy`/`gets`，从根源消除溢出）+ Stack Canary（编译时启用`-fstack-protector`）+ NX/DEP（操作系统启用）+ ASLR（操作系统启用），形成纵深防御。
