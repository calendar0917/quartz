## 1. 域名系统 DNS ⭐⭐

### 1.1 核心功能
将**域名**转换为 **IP 地址**。

### 1.2 域名结构

- 层次树状结构，标号用 `.` 分隔
- 例：`mail.cctv.com`（三级.二级.顶级）
- 域名是逻辑概念，不代表物理地点

**顶级域名 TLD**：
- 国家顶级域名：cn, us, uk, jp...
- 通用顶级域名：com（公司）, net（网络服务）, org（非营利）, edu（教育）, gov（政府）

### 1.3 域名服务器

| 类型 | 功能 | 特点 |
|------|------|------|
| **根域名服务器** | 最高层，知道所有顶级域名服务器的IP | 全球13套（不同IP），实际1000+台（任播技术）|
| **顶级域名服务器** | 管理对应顶级域下的二级域名 | |
| **权限域名服务器** | 负责一个**区**的域名解析 | 区≤域，区内的节点必须连通 |
| **本地域名服务器** | 接收用户的 DNS 查询请求 | 离用户最近 |

> DNS 的管辖范围是以**区(zone)**为单位，不是以**域(domain)**为单位。

### 1.4 域名解析过程 ⭐

**递归查询**：主机→本地域名服务器，本地**代为完成全部查询**，返回最终结果。

**迭代查询**（更常用）：
```
主机 m.xyz.com 查询 y.abc.com 的 IP：

① m.xyz.com → 本地域名服务器 dns.xyz.com（递归查询）
② dns.xyz.com → 根域名服务器（迭代）
   → 回复：去问 com 顶级域名服务器
③ dns.xyz.com → com 顶级域名服务器（迭代）
   → 回复：去问 abc.com 权限域名服务器
④ dns.xyz.com → abc.com 权限域名服务器（迭代）
   → 回复：y.abc.com 的 IP 是 xxx
⑤ dns.xyz.com → m.xyz.com（返回结果）
```

> **主机向本地域名服务器的查询一般都是递归查询**；**本地域名服务器向根域名服务器的查询通常是迭代查询**。

### 1.5 DNS 高速缓存

- 存放最近查询过的域名→IP 映射
- 大大减轻根域名服务器的负荷
- 每项内容有计时器（过期删除）
- 即使 DNS 全部瘫痪，仍可**直接使用 IP 地址**通信

### 1.6 其他要点
- DNS 使用 **UDP**（端口53），减少开销
- 使用客户服务器方式
- 可靠性：主域名服务器 + 辅助域名服务器（数据复制）

## 2. 文件传送协议 FTP

### 2.1 概述

- 使用 **TCP** 可靠运输服务
- 使用客户服务器方式
- 服务器进程 = 主进程（接收新请求）+ 若干从属进程（处理单个请求）
- 屏蔽不同操作系统的差异

### 2.2 两大连接 ⭐

```
FTP 客户                        FTP 服务器
          ┌── 控制连接(端口21) ──→  控制进程
          │   （整个会话保持）      
          │
          └── 数据连接(端口20) ──→  数据传送进程
              （传输完即关闭）
```

- **控制连接**（端口21）：传送命令和响应，**整个会话期间一直保持**
- **数据连接**（端口20）：实际传送文件，**传输完毕即关闭**
- FTP 的控制信息是**带外 (out of band) 传送**——因为在分离的控制连接中传送，不在数据连接中

### 2.3 主进程工作步骤

1. 打开熟知端口（21），使客户能连接
2. 等待客户连接请求
3. 启动从属进程处理请求
4. 回到等待状态，接收其他请求

### 2.4 TFTP（简单文件传送协议）

| | FTP | TFTP |
|--|-----|------|
| 运输层 | TCP | **UDP** |
| 端口 | 21/20 | **69** |
| 交互 | 支持 | 不支持 |
| 命令集 | 完整 | 简单 |
| 差错改正 | 由 TCP 保证 | 自己实现 |
| 身份鉴别 | 有 | 无 |
| 优点 | 功能强大可靠 | 代码小、可用于UDP环境 |

**TFTP 工作方式**：类似停止等待协议，每次512字节数据，确认后续发下一块。

## 3. 万维网 WWW ⭐⭐

### 3.1 核心三要素

| 要素 | 全称 | 作用 |
|------|------|------|
| **URL** | 统一资源定位符 | 标志文档位置 |
| **HTTP** | 超文本传送协议 | 实现链接和传输 |
| **HTML** | 超文本标记语言 | 显示文档（不是协议！） |

### 3.2 URL 格式

$$
\fbox{协议}://\fbox{主机}:\fbox{端口}/\fbox{路径}
$$

例：`http://www.tsinghua.edu.cn:80/index.html`

### 3.3 HTTP 协议

#### 主要特点

- 使用 **TCP**（端口80）
- HTTP 本身是**无连接**的
- HTTP 是**无状态**的（不记忆先前的交互，简化服务器设计）
- 面向事务

#### HTTP/1.0 vs HTTP/1.1

| | HTTP/1.0 | HTTP/1.1 |
|--|---------|---------|
| 连接方式 | **非持续连接** | **持续连接** |
| 效率 | 每个文档需新建TCP连接 | 复用同一TCP连接 |

#### 请求文档的时间

**非持续连接**（HTTP/1.0）：
每请求一个文档需要 2RTT（TCP握手+请求响应）。

如果一个主页有 10 张图片：
- 所需时间 ≥ 22RTT + 11个文档传输时间

**持续连接**（HTTP/1.1）：
- **非流水线方式**：收到前一个响应后才能发下一个请求
  - 时间 ≥ 2RTT + 10RTT + 文档传输时间
- **流水线方式**：连续发送请求，服务器连续响应
  - 时间 ≥ 1RTT + 文档传输时间（效率最高）

#### 代理服务器（万维网高速缓存）

- 缓存最近请求的文档
- 减少访问互联网服务器的时延
- 工作流程：浏览器 → 代理 →（未命中则）→ 源服务器 → 代理缓存 → 浏览器

### 3.4 HTTP 报文结构

**请求报文** = 请求行 + 首部行 + 实体主体
```
GET /dir/index.htm HTTP/1.1    ← 请求行（方法 URL 版本）
Host: www.xyz.edu.cn           ← 首部行
Connection: close
User-Agent: Mozilla/5.0
Accept-Language: cn
                               ← 空行（CRLF）
                               ← 实体主体（通常无）
```

**响应报文** = 状态行 + 首部行 + 实体主体
```
HTTP/1.1 200 OK                ← 状态行
Content-Type: text/html
Content-Length: 1234
                               ← 空行
<html>...</html>               ← 实体主体
```

### 3.5 状态码

| 类别 | 含义 | 示例 |
|:--:|------|------|
| 1xx | 通知信息 | |
| 2xx | 成功 | 200 OK |
| 3xx | 重定向 | |
| 4xx | 客户差错 | **404 Not Found** |
| 5xx | 服务器差错 | |

### 3.6 HTTP 方法

| 方法 | 作用 |
|------|------|
| GET | 请求读取 URL 标示的信息 |
| HEAD | 请求读取首部 |
| POST | 向服务器提交数据 |
| PUT | 在指明的 URL 下存储文档 |

### 3.7 Cookie

- 在 HTTP 服务器与客户之间传递**状态信息**
- 解决 HTTP 无状态的问题
- 存储在客户端的 cookie 文件中

## 4. 电子邮件 ⭐⭐

### 4.1 系统三大构件

```
发送方用户代理 ─SMTP─→ 发送方邮件服务器 ─SMTP─→ 接收方邮件服务器 ─POP3/IMAP─→ 接收方用户代理
```

| 构件 | 作用 |
|------|------|
| 用户代理 (UA) | 电子邮件客户端软件 |
| 邮件服务器 | 发送和接收邮件，向发信人报告状态 |
| 邮件协议 | SMTP(发送)、POP3/IMAP(读取) |

### 4.2 电子邮件地址格式

$$
\fbox{收件人邮箱名}@\fbox{邮箱所在主机的域名}
$$

例：`username@163.com`

### 4.3 SMTP 协议（发送邮件）⭐

- 使用 **TCP**（端口25）
- 客户服务器方式
- **三阶段**：

#### (1) 连接建立

```
SMTP客户 → SMTP服务器端口25 → 建立TCP连接
服务器发送："220 Service ready"
客户发送："HELO 发件方主机名"
服务器回复："250 OK"
```

#### (2) 邮件传送

```
MAIL FROM: <发件人地址>      ← 发件人
RCPT TO: <收件人地址1>       ← 收件人（可多个）
RCPT TO: <收件人地址2>
DATA                         ← 开始传送邮件内容
（邮件内容：首部+空行+主体）
.                            ← 结束
```

#### (3) 连接释放

```
QUIT → 释放TCP连接
```

**重要**：邮件在互联网中间的邮件服务器**不会落地**，直接从发送方服务器传送到接收方服务器。

### 4.4 POP3 协议（读取邮件）

- 使用 **TCP**（端口110）
- 下载邮件到本地，服务器**可删除**
- 支持用户鉴别（用户名+口令）
- 工作方式简单，类似"拉"(pull)

### 4.5 IMAP 协议（读取邮件）

- 使用 **TCP**
- **联机协议**：邮件一直保存在服务器
- 可只下载邮件首部
- 可在服务器上创建文件夹、搜索
- 用户可在不同计算机上阅读邮件
- 缺点：查阅邮件必须先联网

### 4.6 POP3 vs IMAP

| | POP3 | IMAP |
|--|------|------|
| 邮件存储 | 下载到本地 | 保留在服务器 |
| 离线阅读 | 支持 | 不支持 |
| 文件夹 | 本地 | 服务器同步 |
| 部分下载 | 不支持 | 支持（只下载首部）|

### 4.7 基于万维网的电子邮件

```
用户浏览器 ─HTTP─→ 网站邮件服务器 ─SMTP─→ 对方网站邮件服务器 ─HTTP─→ 对方浏览器
```

- 用户代理→邮件服务器：使用 **HTTP**（POST发送、GET读取）
- 邮件服务器之间：使用 **SMTP**

### 4.8 MIME（通用互联网邮件扩充）

- 在 SMTP 之上，增加非 ASCII 文本和多媒体邮件支持
- 没有改动或取代 SMTP
- 新增 5 个邮件首部字段：
  - MIME-Version, Content-Description, Content-Id, Content-Transfer-Encoding, Content-Type

**两种编码**：

| 编码 | 适用场景 | 开销 |
|------|---------|:--:|
| Base64 | 任意二进制数据 | 25% |
| Quoted-printable | 少量非ASCII | 不定 |

**MIME 与 SMTP 的关系**：
- MIME 在 SMTP 之上，不是独立的邮件协议
- 邮件传输仍用 SMTP，MIME 只是扩充了内容格式

### 4.9 电子邮件信息格式

```
From: 发件人
To: 收件人
Cc: 抄送
Date: 日期
Subject: 主题
                      ← 空行（分隔首部和主体）
邮件主体（自由撰写）
```

## 5. DHCP 动态主机配置协议

### 5.1 作用
**即插即用联网**：计算机加入网络时自动获取 IP 地址，无需手动配置。

### 5.2 工作方式
- 使用 **UDP**（服务器端口67，客户端口68）
- 客户服务器方式

### 5.3 工作过程

```
DHCP客户                              DHCP服务器
  │                                        │
  ├─ DHCPDISCOVER（广播）────────────────→│ "我需要IP地址"
  │                                        │
  │←─ DHCPOFFER（单播）───────────────────┤ "给你提供这个IP"
  │                                        │
  ├─ DHCPREQUEST（广播）────────────────→│ "我选择你的提供"
  │                                        │
  │←─ DHCPACK（单播）───────────────────┤ "确认，你可以用了"
  │                                        │
已绑定状态                                │
```

### 5.4 租用期

- IP 地址是**临时**的，有租用期
- T₁ = 0.5T → 请求续租
- T₂ = 0.875T → 再次请求续租
- 到期未续 → 释放地址

### 5.5 DHCP 中继代理

每个网络不需要都配 DHCP 服务器。中继代理收到客户广播后，以单播转发给 DHCP 服务器。

## 6. SNMP（简单网络管理协议）

- 使用 **UDP** 传送报文（端口161/162）
- 为什么不用 TCP？UDP 开销小，通过周期性发送保证可靠性。丢失一个报文后经过一段时间会再发一个，比使用 TCP 更快速。

## 7. P2P 文件共享

### 特点
- 不使用集中式文件服务器
- 每个对等方既是客户也是服务器
- 大文件分为许多小文件，从多个对等方下载

### 问题
- 版权保护
- 安全性

## 8. 协议层位置总结

```
应用层：HTTP, FTP, SMTP, DNS, DHCP, SNMP, RIP, TFTP
运输层：TCP(80/20/21/25/110...), UDP(53/67/68/69/161/520...)
网络层：IP, ICMP, ARP, OSPF, IGMP
```

**注意**：
- ICMP 和 OSPF 都**直接装在 IP 数据报**中（不经运输层）
- RIP 装在 **UDP 数据报**中（端口520），在应用层
- DNS 使用 **UDP**（端口53）
- SNMP 使用 **UDP**

### 习题 6：FTP 为什么带外传送？主从进程作用
FTP 控制信息在分离的控制连接（端口21）中传送，不在数据连接（端口20）中传送→这就是"带外"。主进程接受新请求，从属进程处理单个请求。

### 习题 14：HTTP 判断正误
(1) 错误：非持续连接需要 4 个 TCP 连接
(2) 正确：同一服务器可用持续连接
(3) 错误：非持续连接每个请求需新 TCP 连接
(4) 错误：404 等错误响应主体可能为空

### 习题 15：URL 解析时延计算
总时间 = 2RTTw + (RTT₁ + RTT₂ + ... + RTTₙ)

### 习题 35：SNMP 为什么不用 TCP？
UDP 开销小，周期性发送可弥补。比 TCP 更快。

### 习题 46：应用层协议为什么有的用 TCP 有的用 UDP？
需要可靠传送的用 TCP；开销大但不需要可靠保证的用 UDP（如 RIP 周期性重发、DNS 请求小）

### 习题 47：MIME 为什么在 SMTP 之上？RIP 为什么在应用层？
MIME 不是独立协议，是对 SMTP 邮件内容的扩充。RIP 使用 UDP（端口520），位于应用层。
