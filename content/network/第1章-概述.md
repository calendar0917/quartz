## 1. 互联网的组成

互联网划分为两大块：

### 1.1 边缘部分
由所有连接在互联网上的**主机**（端系统）组成，用户直接使用。

**两种通信方式：**

| | 客户-服务器(C/S)方式 | 对等(P2P)方式 |
|--|---------------------|-------------|
| 角色 | 客户=服务请求方，服务器=服务提供方 | 不区分请求方和提供方 |
| 主动/被动 | 客户主动请求，服务器被动等待 | 双方都可以主动 |
| 服务器要求 | 需一直运行，强硬件，复杂OS | 无特殊要求 |
| 本质 | 进程之间服务和被服务的关系 | 本质仍用C/S，只是每个主机既是客户又是服务器 |

> 客户程序必须预先知道服务器地址；服务器不需要知道客户地址。

### 1.2 核心部分
由**网络**和**路由器**组成，为边缘提供连通性。

- 核心设备：**路由器** (router)
- 核心功能：**分组交换**
- 路由器两大功能：
  - **转发分组**：直接为通信服务
  - **路由选择**：交换路由信息，找到最优路径

## 2. 三种交换方式

### 2.1 电路交换 (Circuit Switching)

三个步骤：
1. **建立连接**：建立专用物理通路
2. **通话**：一直占用通信资源
3. **释放连接**：归还通信资源

特点：
- 通信过程中**始终占用端到端的全部带宽**
- 适合实时通信（语音通话）
- 线路利用率低（计算机数据具有突发性，传送数据不到10%时间）

### 2.2 报文交换 (Message Switching)

- 基于**存储转发**原理
- 整个报文作为一个整体传输
- 时延较长（几分钟到几小时），已很少使用

### 2.3 分组交换 (Packet Switching) ⭐

**互联网核心部分采用的方式。**

工作过程：
1. 把较长的报文划分为更小的等长数据段
2. 每个数据段加上**首部**（含目的地址、源地址等控制信息）构成**分组** (packet)
3. 各分组独立在网络中选择路径传输
4. 接收端收到分组后剥去首部，还原成报文

分组交换的优点：

| 优点 | 手段 |
|------|------|
| 高效 | 动态分配传输带宽，逐段占用链路 |
| 灵活 | 每个分组独立选择转发路由 |
| 迅速 | 不先建立连接就能发送 |
| 可靠 | 分布式多路由使网络有很好的生存性 |

分组交换的问题：
- 排队延迟：分组在路由器需排队
- 不保证带宽
- 额外开销：每个分组都要携带控制信息

### 2.4 三种方式对比

```
电路交换：比特流直达终点（先建立连接）
报文交换：整个报文存储转发
分组交换：分成小分组存储转发
```

- 传送大量连续数据、传送时间远大于连接建立时间 → 电路交换较快
- 传送突发数据 → 分组交换利用率高
- 分组比报文交换时延更小

## 4. 性能指标 ⭐⭐

### 4.1 速率

数据的**传送速率**，也称数据率或比特率。

- 单位：bit/s (bps), kbit/s, Mbit/s, Gbit/s
- 千 K = 2¹⁰ = 1024，兆 M = 2²⁰，吉 G = 2³⁰
- 1 字节 (Byte) = 8 比特 (bit)
- 额定速率 ≠ 实际运行速率

### 4.2 带宽

两种含义：
1. 信号带宽：信号具有的频带宽度（Hz）
2. **网络带宽**：单位时间内能通过的最高数据率（bit/s）
两者本质相同：带宽越宽，最高数据率越高。

### 4.3 吞吐量

单位时间内通过某网络（或信道、接口）的**实际数据量**。

- 受额定速率限制（绝对上限）
- 可能远小于额定速率，甚至为零

### 4.4 时延 ⭐⭐⭐

**总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延**

#### (1) 发送时延（传输时延）
主机或路由器**发送数据帧**所需时间。

$$发送时延 = \frac{数据帧长度(bit)}{发送速率(bit/s)}$$

- 发生在**机器内部**的发送器中
- 与传输信道长度**无关**

#### (2) 传播时延
电磁波在信道中**传播一定距离**所需时间。

$$传播时延 = \frac{信道长度(m)}{电磁波传播速率(m/s)}$$

- 自由空间：3.0 × 10⁵ km/s（光速）
- 铜线：约 2.3 × 10⁵ km/s
- 光纤：约 2.0 × 10⁵ km/s
- 发生在机器**外部**的传输媒体上
- 与信号发送速率**无关**

#### (3) 处理时延
主机/路由器处理分组（分析首部、提取数据、差错检验、查找路由）的时间。

#### (4) 排队时延
分组在路由器**输入输出队列**中排队等待的时间。
- 取决于网络当时的通信量
- 队列溢出时分组丢失 → 排队时延为无穷大

#### 四种时延产生的位置：
```
主机A发送器 → 传播时延(链路) → 路由器排队+处理 → 传播时延(链路) → 主机B
         ↑发送时延                ↑排队时延+处理时延
```

#### ⚠️ 常见错误概念
> **"在高速链路（或高带宽链路）上，比特会传送得更快些" — 这是错误的！**

高速链路提高的是**发送速率**，只减小发送时延，不影响传播速率（电磁波速度不变）。

#### 时延计算例题

```
【例】结点 A 通过 1000 km 光纤向 B 发送 100 MB 数据。

(1) 带宽 1 Mbit/s：
  发送时延 = 100×2²⁰×8÷10⁶ = 838.9 s
  传播时延 = 1000/2×10⁵ = 5 ms = 0.005 s
  总时延 ≈ 838.9 s （发送时延占主导）

(2) 带宽 100 Mbit/s：
  发送时延 = 838.9/100 = 8.389 s
  总时延 = 8.394 s （发送时延仍占主导，但显著减小）

(3) 数据 1 Byte，带宽 1 Mbit/s：
  发送时延 = 1×8÷10⁶ = 8 μs
  总时延 = 5.008 ms （传播时延占主导！）

(4) 数据 1 Byte，带宽 1 Gbit/s：
  发送时延 = 0.008 μs
  总时延 ≈ 5 ms （传播时延占主导，与(3)无明显差别）

结论：不能笼统说"发送速率越高总时延越小"，要具体分析。
```

### 4.5 时延带宽积

$$时延带宽积 = 传播时延 \times 带宽$$

- 表示**以比特为单位的链路长度**
- 即管道中最多可容纳的比特数（从发送端发出但尚未到达接收端的比特）
- 当管道充满比特时，链路得到充分利用

### 4.6 往返时间 RTT

从发送方发送数据到收到接收方确认的总时间。

$$RTT = 传播时延(t_P) × 2 + 接收方处理排队时延 + 接收方发送时延$$

- 卫星通信的 RTT 相对较大
- **重要**：考试中常假设 RTT = 2 × 传播时延（忽略处理排队和确认发送时间）

### 4.7 利用率

$$D = \frac{D_0}{1-U}$$

其中 D₀ 是空闲时延，U 是利用率。

- **利用率增大 → 时延急剧增大**（排队论结论）
- 当利用率接近 1 时，时延趋向无穷大

## 5. 计算机网络体系结构 ⭐⭐

### 5.1 协议与划分层次

**网络协议**：为进行网络中的数据交换而建立的规则、标准或约定。

三个组成要素：
- **语法**：数据与控制信息的结构或格式
- **语义**：需要发出何种控制信息，完成何种动作
- **同步**：事件实现顺序的详细说明

分层的好处：
- 各层独立：只需知道层间接口
- 灵活性好：任一层变化不影响其他层
- 结构可分割：各层技术独立
- 易于实现维护
- 促进标准化

各层完成的主要功能：
- **差错控制**：使通信更可靠
- **流量控制**：发送速率匹配接收能力
- **分段和重装**：数据分块与还原
- **复用和分用**：多会话共享连接
- **连接建立和释放**：逻辑连接的创建与释放

### 5.2 五层协议体系结构 ⭐⭐⭐（必背！）

| 层次 | 功能 | 传输单元 | 主要协议 |
|------|------|---------|---------|
| 5. 应用层 | 应用进程间交互完成特定网络应用 | 报文 (message) | DNS, HTTP, SMTP, FTP |
| 4. 运输层 | 进程间通信，复用和分用 | 报文段/用户数据报 | TCP, UDP |
| 3. 网络层 | 主机间通信，路由选择+转发 | IP数据报(分组) | IP, ICMP, ARP, OSPF, RIP, BGP |
| 2. 数据链路层 | 相邻节点间传送帧，差错检测 | 帧 (frame) | PPP, CSMA/CD |
| 1. 物理层 | 透明传送比特流 | 比特 (bit) | 物理层规程 |

每层详细功能见前面对应章节。

### 5.3 各层详细功能

**应用层**：
- 通过应用进程间的交互来完成特定网络应用
- 协议定义应用进程间通信和交互的规则
- 例如：DNS（域名解析）、HTTP（万维网）、SMTP（电子邮件）

**运输层**：
- 为两台主机中**进程之间**的通信提供数据传输服务
- **复用**：多个应用进程可同时使用运输层
- **分用**：运输层把收到的信息分别交付给对应进程
- 两种协议：
  - **TCP**：面向连接、可靠、报文段(segment)
  - **UDP**：无连接、尽最大努力、用户数据报

**网络层**：
- 为分组交换网上不同主机提供通信服务
- 两个任务：**路由选择** + **转发**
- 互联网使用的 IP 协议是无连接的
- 分组 = IP 数据报（简称为数据报）

**数据链路层**：
- 实现两个**相邻节点**间的可靠通信
- 传送帧(frame)
- 发现差错：丢弃出错帧
- 改正差错：需要可靠传输协议

**物理层**：
- 透明地传送比特流
- 确定连接电缆的物理特性（插头引脚等）
- **注意**：物理媒体（双绞线、光纤等）在物理层协议之下

### 5.4 协议和服务

| | 协议 | 服务 |
|--|------|------|
| 方向 | **水平**的（对等实体之间）| **垂直**的（下层对上层）|
| 可见性 | 上层实体看不见下层协议（透明）| 只有能被高一层"看见"的功能才叫服务 |
| 关系 | 协议保证了能向上一层提供服务的实现 | 使用本层协议的实体只能看见服务 |

**实体 (entity)**：任何可发送或接收信息的硬件或软件进程。

**SAP (服务访问点)**：相邻两层实体交互的地方，是一个逻辑接口。

**PDU (协议数据单元)**：对等层之间传送的数据单位。

**SDU (服务数据单元)**：层与层之间交换的数据单位。可与 PDU 不同（多个SDU合成一个PDU，或一个SDU分成多个PDU）。

### 5.5 TCP/IP 体系结构

TCP/IP 是四层结构：

```
    应用层 (各种应用层协议如 HTTP, SMTP, DNS, FTP 等)
    运输层 (TCP 或 UDP)
    网际层 (IP)
    网络接口层
```

- **沙漏计时器形状**：IP 在中间，上层各类应用，下层各类网络接口
- 设计理念：网络核心部分越简单越好
- **路由器**在转发分组时最高只用到**网际层**，没有运输层和应用层
