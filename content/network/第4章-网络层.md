## 1. 网络层提供的两种服务

### 1.1 虚电路服务 vs 数据报服务

| 对比方面 | 虚电路服务 | 数据报服务 |
|---------|----------|----------|
| 思路 | 网络保证可靠通信 | **主机**保证可靠通信 |
| 连接建立 | **必须**先建立 | **不需要** |
| 终点地址 | 仅建立时使用（后续用虚电路号）| 每个分组都有完整目的地址 |
| 分组转发 | 同一虚电路走**同一路由** | 每个分组**独立选路** |
| 结点故障 | 经过故障结点的虚电路**都不工作** | 可能丢失分组，路由可能变化 |
| 分组顺序 | **按序**到达 | 不一定按序 |
| 差错/流量控制 | 可由网络或主机负责 | 由**主机负责** |

> **互联网采用数据报服务**：网络层尽量简单，尽最大努力交付。

### 1.2 网络层的两个层面

| 层面 | 内容 |
|------|------|
| **数据层面** | 路由器根据转发表转发分组（每个分组独立处理）|
| **控制层面** | 路由选择协议交换信息，生成转发表 |

## 2. 网际协议 IP

### 2.1 与 IP 配套的三个协议
- **ARP**：地址解析协议（IP→MAC）
- **ICMP**：网际控制报文协议（差错/询问报告）
- **IGMP**：网际组管理协议（多播）

### 2.2 虚拟互连网络

使用**路由器**实现异构网络互连。
- 从IP层看，互联网是一个统一的"IP网"（虚拟互连网络）
- 通信时好像在一个网络上，看不见底层异构细节
- 使用转发器或网桥只是扩大了一个网络，不称为网络互连

## 3. IP 地址 ⭐⭐⭐

### 3.1 基本概念
- **32 位**二进制，**点分十进制**表示
- 二级结构：**网络号 (net-id) + 主机号 (host-id)**
- 每个接口全球唯一地址

### 3.2 分类的 IP 地址

| 类别 | 网络号 | 主机号 | 第一个网络 | 最后一个网络 | 每网最大主机数 |
|:--:|------|------|----------|-----------|:--:|
| A | 8位 | 24位 | 1.0.0.0 | 126.0.0.0 | 2²⁴-2 |
| B | 16位 | 16位 | 128.1.0.0 | 191.255.0.0 | 2¹⁶-2 |
| C | 24位 | 8位 | 192.0.1.0 | 223.255.255.0 | 2⁸-2 |
| D | 多播地址 | | | | |
| E | 保留 | | | | |

> 虽然现在不用分类编址，但考试中经常以"B类地址"等形式出现。只需知道各分类的网络号和主机号占比即可。

A 类地址前 8 位网络号，后 24 位主机号。
B 类地址前 16 位网络号，后 16 位主机号。
C 类地址前 24 位网络号，后 8 位主机号。

**特殊的 IP 地址：**

| 网络号 | 主机号 | 源/目的 | 含义 |
|--------|--------|---------|------|
| 全0 | 全0 | 可作源 | 本网络上的本主机 |
| 全0 | X | 可作源 | 本网络上主机号为 X 的主机 |
| 全1 | 全1 | 仅目的 | 本网络上广播（路由器不转发）|
| Y | 全1 | 仅目的 | 对网络 Y 广播 |
| 127 | 任意 | 均可 | 本地环回测试 |

### 3.3 无分类编址 CIDR ⭐⭐⭐

**斜线记法**：`a.b.c.d/n`，前 n 位是网络前缀。

#### 子网掩码（地址掩码）
- 32 位，前 n 位全 1，后 (32-n) 位全 0
- 作用：快速计算网络地址

$$网络地址 = IP地址 \ \text{AND} \ 子网掩码$$

例如：`/20` 的掩码 = `255.255.240.0`

#### 关键公式
- 地址块包含地址数 = $2^{32-n}$
- 可用主机数 = $2^{32-n} - 2$（去掉全0和全1）
- **全0** = 网络地址，**全1** = 广播地址

#### 常用 CIDR 地址块速查

| 前缀 | 掩码 | 地址数 | 相当于 |
|------|------|:---:|------|
| /16 | 255.255.0.0 | 64K | 1个B类 = 256个C类 |
| /17 | 255.255.128.0 | 32K | 128个C类 |
| /18 | 255.255.192.0 | 16K | 64个C类 |
| /19 | 255.255.224.0 | 8K | 32个C类 |
| /20 | 255.255.240.0 | 4K | 16个C类 |
| /21 | 255.255.248.0 | 2K | 8个C类 |
| /22 | 255.255.252.0 | 1K | 4个C类 |
| /23 | 255.255.254.0 | 512 | 2个C类 |
| /24 | 255.255.255.0 | 256 | 1个C类 |
| /25 | 255.255.255.128 | 128 | ½个C类 |
| /26 | 255.255.255.192 | 64 | ¼个C类 |
| /27 | 255.255.255.224 | 32 | ⅛个C类 |
| /28 | 255.255.255.240 | 16 | |
| /29 | 255.255.255.248 | 8 | |
| /30 | 255.255.255.252 | 4 | |

**三个特殊的 CIDR 地址块：**
- `/32`：主机路由（就是一个IP地址）
- `/31`：点对点链路（只有两个IP地址）
- `/0`：默认路由

#### CIDR 记法的注意事项

```
128.14.35.7/20      是 IP 地址，前20位是网络前缀
128.14.32.0/20      是地址块，也是该块中主机号全0的地址
128.14.35.7         只是 IP 地址，不知网络前缀
128.14.32.0         不能确定网络地址（不知前缀长度）
```

### 3.4 子网划分

#### 按主机数划分

**步骤**：
1. 确定所需主机位：$2^n - 2 \geq$ 主机数（n = 主机位数）
2. 前缀长度 = 32 - n
3. 从大到小依次分配

#### 例题（作业 4-26）

```
公司前缀：192.77.33/24

LAN1: 50主机 → 需要6位主机号(2⁶-2=62≥50) → 前缀/26
LAN3: 30主机 → 需要5位(2⁵-2=30) → 前缀/27
LAN8: 30主机 → 前缀/27
LAN6: 20主机 → 前缀/27
LAN7: 20主机 → 前缀/27
LAN2: 10主机 → 前缀/28
LAN4: 10主机 → 前缀/28
LAN5: 4主机  → 前缀/29(2³-2=6≥4)

分配结果：
LAN1: 192.77.33.0/26
LAN3: 192.77.33.64/27
LAN8: 192.77.33.96/27
...
```

#### 例题（作业 4-33）

```
地址块 136.23.12.64/26 划分为 4 个一样大的子网

(1) 子网号需2位 → 前缀 = 26+2 = 28
(2) 每子网主机号 = 32-28 = 4位 → 共2⁴ = 16个地址
(3) 子网块：
    ① 136.23.12.64/28  (64~79)
    ② 136.23.12.80/28  (80~95)
    ③ 136.23.12.96/28  (96~111)
    ④ 136.23.12.112/28 (112~127)
(4) 可分配最小/最大地址（去掉全0和全1）：
    ① 65/28 ~ 78/28
    ② 81/28 ~ 94/28
    ③ 97/28 ~ 110/28
    ④ 113/28 ~ 126/28
```

### 3.5 路由聚合（地址聚合）

多个连续地址块合并为一个更大的地址块：找**共同前缀**。

**例题（作业 4-22）**：
```
212.56.132.0/24  11010100 00111000 10000100 ...
212.56.133.0/24  11010100 00111000 10000101 ...
212.56.134.0/24  11010100 00111000 10000110 ...
212.56.135.0/24  11010100 00111000 10000111 ...

前22位相同 → 聚合为 212.56.132.0/22
```

### 3.6 IP 地址的特点

1. 分等级的地址结构（方便管理、路由聚合）
2. 一台主机连到两个网络 → 必须有两个 IP 地址（多归属主机）
3. 一个路由器至少两个接口 → 至少两个 IP 地址
4. 同一局域网上的 IP 地址网络号**必须相同**
5. 有不同网络号的局域网必须用**路由器**互连

## 4. IP 地址与 MAC 地址

| | IP 地址 | MAC 地址 |
|--|--------|---------|
| 所在层次 | 网络层及以上 | 数据链路层 |
| 在哪个首部 | IP 数据报首部 | MAC 帧首部 |
| 性质 | 逻辑地址（软件实现）| 物理地址（固化在ROM）|
| 长度 | 32位 | 48位 |
| 变换 | 端到端不变 | 每段链路都会变 |

**为什么需要两种地址？**
- 各种网络使用不同的 MAC 地址，直接寻址几乎不可能
- IP 编址统一解决了异构网络互连问题
- ARP 自动完成 IP→MAC 映射

**不同网络区间的地址变化：**

| 区间 | IP源 | IP目的 | MAC源 | MAC目的 |
|------|------|--------|-------|---------|
| H1 → R1 | IP₁ | IP₂ | MAC₁ | MAC₃ |
| R1 → R2 | IP₁ | IP₂ | MAC₄ | MAC₅ |
| R2 → H2 | IP₁ | IP₂ | MAC₆ | MAC₂ |

> IP 数据报首部中的源IP和目的IP**始终不变**；MAC 帧首部的源MAC和目的MAC**每段链路都变**。

## 5. ARP 地址解析协议 ⭐⭐

### 5.1 作用
从已知 IP 地址解析出对应的 MAC 地址。

### 5.2 ARP 工作原理

**同一局域网内**：

```
1. 发送方查 ARP 高速缓存
   ├── 找到 → 直接用该MAC地址封装帧
   └── 未找到 → 在本局域网广播 ARP 请求
   
2. ARP 请求（广播）："谁的 IP 是 X.X.X.X？请告诉我你的 MAC 地址"

3. 目的主机收到 → 单播回复自己的 MAC 地址

4. 发送方将 IP→MAC 映射写入 ARP 缓存，然后发送数据
```

**不同局域网内**：
- 发送方用 ARP 找到**默认网关（路由器）**的 MAC 地址
- 数据报发给路由器，路由器继续用 ARP 或已有缓存转发
- 路由器收到分组后，在不同网络中继续 ARP 过程

### 5.3 ARP 高速缓存
- 存放最近获得的 IP→MAC 映射
- 每项有**生存时间 (Age)**，超时删除
- 减少 ARP 广播通信量

### 5.4 四种典型 ARP 场景

| 发送方 | 目的 | 做什么 |
|--------|------|------|
| 主机 | 本网络主机 | ARP 找目的主机 MAC |
| 主机 | 另一网络主机 | ARP 找本网络路由器 MAC |
| 路由器 | 本网络主机 | ARP 找目的主机 MAC |
| 路由器 | 另一网络主机 | ARP 找下一跳路由器 MAC |

## 6. IP 数据报格式 ⭐⭐⭐

### 6.1 首部结构

```
 0         4         8        16        19        24        31
┌──────┬──────────┬──────────────────────────────────────────┐
│ 版本  │ 首部长度  │              区分服务                    │
├──────┴──────────┼──────────────────────────────────────────┤
│              总长度                                         │
├─────────────────┬──────────┬──────────────────────────────┤
│      标识        │  标志    │           片偏移              │
├─────────────────┼──────────┼──────────────────────────────┤
│    生存时间 TTL   │   协议    │        首部检验和            │
├─────────────────┴──────────┴──────────────────────────────┤
│                       源地址（32位）                        │
├────────────────────────────────────────────────────────────┤
│                      目的地址（32位）                        │
├────────────────────────────────────────────────────────────┤
│                   可选字段（长度可变）    │     填充         │
└──────────────────────────────────────────┴─────────────────┘
```

**固定部分 = 20 字节**，可变选项最长 40 字节。

### 6.2 各字段说明

| 字段 | 位数 | 说明 |
|------|:--:|------|
| 版本 | 4 | IPv4 = 4 |
| 首部长度 | 4 | 单位 4 字节，最大值 60 字节（15×4） |
| 区分服务 | 8 | 一般不用 |
| **总长度** | 16 | 首部+数据，最大 65535 字节 |
| **标识** | 16 | 计数器，分片时各片相同 |
| **标志** | 3 | DF=不分片；MF=还有分片 |
| **片偏移** | 13 | 以 8 字节为偏移单位 |
| TTL | 8 | 每跳减1，为0丢弃 |
| 协议 | 8 | 6=TCP, 17=UDP, 1=ICMP, 89=OSPF |
| 首部检验和 | 16 | 只检验首部，不检验数据 |
| 源地址 | 32 | |
| 目的地址 | 32 | |

### 6.3 IP 数据报分片 ⭐⭐⭐

**分片原因**：数据报长度超过网络 MTU。

**关键公式**：
- 片偏移 = 该片第一个字节在原始数据中的位置 / 8
- 每片的总长度 = 数据长度 + 20（首部）
- 每片数据长度为 8 字节的整数倍

**标志位**：
- **DF** (Don't Fragment)：DF=1 不分片
- **MF** (More Fragment)：MF=1 后面还有分片，MF=0 最后一个分片

#### 例题（作业 4-20）

```
原始数据报总长 4000 字节（固定首部20B）
经过 MTU=1500B 的网络

数据部分 = 4000 - 20 = 3980 字节
每片最大数据 = 1500 - 20 = 1480 字节（必须是8的整数倍）
3980 = 1480 + 1480 + 1020

┌──────┬──────┬──────┬─────┬──────┐
│ 片号  │ 总长度 │ 标识  │ MF │片偏移│
├──────┼──────┼──────┼─────┼──────┤
│  1   │ 1420 │12345 │  1  │  0   │
│  2   │ 1420 │12345 │  1  │ 185  │
│  3   │ 1040 │12345 │  0  │ 370  │
└──────┴──────┴──────┴─────┴──────┘

片偏移计算：
  片1: 0/8 = 0
  片2: 1480/8 = 185
  片3: (1480+1480)/8 = 2960/8 = 370

数据量验证：
  片1数据: 1420-20 = 1400 × 
  不对，应该是 1420-20 = 1400，但1400不是8倍数...
  
  正确：每片数据 = 1480（MTU-20，向下取8倍数 = 1480）
  片1数据=1480，总长=1500，但在MTU内所以总长=1420？不对。
  
  实际：原始MTU=1500，每片总长≤1500
  片1: 首部20+数据1480=1500，但题目答案总长=1420？
  
  更正思路：
  3980=1480+1480+1020
  片1: 总长=1480+20=1500(不合MTU?)
  不，MTU=1500是包括首部的最大值，总长=1500刚好。
  但答案写1420，说明MTU=1500是数据部分最大值？不对...
  
  实际上：MTU 是整个数据报的总长度上限（包括首部）
  所以：每片总长 ≤ 1500
       每片数据长度 = 总长 - 20
       片1数据1480, 总长1500刚好
       片2数据1480, 总长1500刚好
       片3数据1020, 总长1040
  
  片偏移应为：
       片1: 0/8 = 0
       片2: 1480/8 = 185
       片3: 2960/8 = 370
```

### 6.4 首部检验和计算

**计算方法**：
1. 将 IP 首部按 16 位（或题目指定的位数）分组
2. 将检验和字段置 0
3. 所有字进行**反码求和**（二进制加法，最高位进位加到最低位）
4. 结果取**反码**即为检验和

**反码求和规则**：
- 逐位二进制加法
- 有进位时，在结果最低位加 1

**注意**：
- 数据报每经过一个路由器，检验和都要**重新计算**（TTL变了）
- 考试时注意题目要求按 8 位还是 16 位分组！

#### 例题（作业 4-11）

```
IP首部各字段（16位分组）：
0100 0101 0000 0000
0000 0000 0001 1100
0000 0000 0000 0001
0000 0000 0000 0000  ← 检验和字段(先置0)
0000 0100 0001 0001
0000 0000 0000 0000
0000 1010 0000 1100
0000 1110 0000 0101
0000 1100 0000 0110
0000 0111 0000 1001

逐行反码求和 → 0111 0100 0100 1110
取反码 → 1000 1011 1011 0001  ← 写入检验和字段
```

## 7. IP 层转发分组

### 7.1 基于终点的转发
- 转发表存储：（目的网络地址，下一跳地址）
- 查找转发表 = 逐行寻找前缀匹配

### 7.2 最长前缀匹配 ⭐⭐

当多个前缀都能匹配时，选择**前缀最长**的。

**为什么需要**：使用 CIDR 时可能得到多个匹配。

```
例：目的地址 128.1.2.196 查转发表

前缀         掩码              AND结果         匹配?
128.1.2.0/24   255.255.255.0    128.1.2.0      ✓  (24位匹配)
128.1.2.128/25 255.255.255.128  128.1.2.128    ✓  (25位匹配)
128.1.2.192/26 255.255.255.192  128.1.2.192    ✓  (26位匹配，最长!选这个)
```

### 7.3 路由器分组转发算法

```
1. 提取目的 IP 地址 D
2. 有 D 的特定主机路由(/32)？ → 是 → 按此转发
3. 有 D 的最长前缀匹配？ → 是 → 按此转发
4. 有默认路由(0.0.0.0/0)？ → 是 → 按此转发
5. 否则 → 丢弃分组
```

**两种特殊路由**：
- **主机路由**：a.b.c.d/32，特定主机
- **默认路由**：0.0.0.0/0，所有不匹配的分组

## 8. ICMP 协议

### 8.1 概述
- 网际控制报文协议
- 允许主机/路由器报告**差错**和**异常**
- 是 **IP 层的协议**（不是高层协议）
- ICMP 报文装在 IP 数据报中

### 8.2 报文类型

| 种类 | 类型值 | 说明 |
|------|:--:|------|
| 差错报告 | 3 | **终点不可达** |
| 差错报告 | 11 | **时间超过**（TTL=0）|
| 差错报告 | 12 | 参数问题 |
| 差错报告 | 5 | 改变路由(Redirect) |
| 询问 | 8/0 | **回送请求/回答**（PING）|
| 询问 | 13/14 | 时间戳请求/回答 |

### 8.3 不应发送差错报告的情况
1. 对 ICMP 差错报告报文不再发送
2. 对分片后续片不发送
3. 对多播地址不发送
4. 对特殊地址（127.0.0.0, 0.0.0.0）不发送

### 8.4 PING
- 测试两个主机连通性
- 使用 ICMP 回送请求/回答报文
- **应用层直接使用网络层 ICMP**，不经运输层

### 8.5 Traceroute
- 跟踪从源点到终点的路径
- 利用 TTL 字段 + ICMP 时间超过报文 + ICMP 终点不可达报文

## 9. 路由选择协议 ⭐⭐

### 9.1 基本概念

**自治系统 AS**：在单一技术管理下的网络/IP/路由器集合。

两大类路由协议：
- **IGP（内部网关协议）**：AS 内部使用 → RIP, OSPF
- **EGP（外部网关协议）**：AS 之间使用 → BGP

> 同一 AS 内只能选用**一种**路由协议！

### 9.2 RIP 协议

**特点**：
- 基于**距离向量**（Bellman-Ford 算法）
- 距离 = **跳数**；最大跳数 15（16=不可达）
- 仅和**相邻**路由器交换信息
- 交换**全部**路由表
- 按**固定时间间隔**（30秒）交换

**距离向量算法**（对每个相邻路由器 X 发来的 RIP 报文）：
1. 报文中的"下一跳"全改为 X，"距离"全 +1
2. 对每个项目：
   - 路由表没有该网络 N → 加入
   - 路由表有 N 且下一跳是 X → 替换
   - 收到距离 < 路由表中距离 → 更新
   - 否则 → 不做任何事
3. 3 分钟没收到相邻路由器更新 → 标记为不可达（距离=16）

**RIP 缺点**：
- 网络规模小（最多15跳）
- 交换完整路由表，开销大
- **坏消息传播得慢**（慢收敛）—— 主要缺点

**坏消息传播得慢示例**：
```
R1 到网络1(Direct) = 1
R2 到网络1(经R1) = 2

网络1故障 → R1设为16 → 但R2还未收到更新，仍发送距离2
R1收到R2的更新 → 误以为可经R2到达 → 更新距离为3
R2收到R1更新 → 更新距离为4
...循环攀升直到都到16
```

### 9.3 OSPF 协议

**特点**：
- 基于**链路状态**，使用 **Dijkstra 最短路径算法**
- 采用**洪泛法**向 AS 内所有路由器发送信息
- 发送的是与相邻路由器的**链路状态**（不是全部路由表）
- OSPF 分组直接装在 **IP 数据报**中（协议字段=89）
- 收敛速度快，没有"坏消息传播慢"的问题

**区域划分**：
- 主干区域：标识符 0.0.0.0，连通下层区域
- 区域边界路由器 (ABR)
- 主干路由器 (BR)
- 自治系统边界路由器 (ASBR)

**工作过程**：
1. 确定邻站可达（Hello 分组，10秒交换一次，40秒未收到=不可达）
2. 同步链路状态数据库
3. 链路状态变化时，用洪泛法更新

**五种分组类型**：Hello、数据库描述、链路状态请求、链路状态更新、链路状态确认。

**优点**：适用于大规模网络、负载均衡、支持CIDR

### 9.4 RIP vs OSPF 对比

| | RIP | OSPF |
|--|-----|------|
| 类型 | 距离向量 | 链路状态 |
| 算法 | Bellman-Ford | Dijkstra |
| 交换信息 | 全部路由表 | 链路状态 |
| 交换对象 | 相邻路由器 | 所有路由器（洪泛）|
| 最大距离 | 15跳 | 无限制 |
| 封装方式 | UDP (端口520) | 直接IP (协议89) |
| 收敛速度 | 慢 | 快 |

### 9.5 BGP 协议
- 外部网关协议，AS 之间使用
- BGP 路由 = [前缀, AS-PATH, NEXT-HOP]
- eBGP：AS 之间，iBGP：AS 内部
- 基于 **TCP** 连接（端口 179）
- 选择策略：本地偏好 → AS跳数最小 → 热土豆路由

## 10. 路由器构成

### 结构
```
控制层面（软件）
  路由选择处理机
  路由选择协议 → 路由表

数据层面（硬件）
  输入端口 → 交换结构 → 输出端口
  （转发表 → 分组转发）
```

- "转发"和"路由选择"的区别：
  - **转发**：数据层面，查表转发，以纳秒计
  - **路由选择**：控制层面，生成路由表，以秒计

### 交换结构
三种方法：通过存储器、通过总线、通过纵横交换结构（互连网络）。

## 11. IPv6（了解）

### 核心变化
- 地址：**128 位**（vs IPv4 32位）
- 首部：固定 **40 字节**，8 个字段（简化）
- 取消：首部长度、服务类型、总长度、检验和、选项字段
- 新增：流标号、下一个首部

### 地址表示
- 冒号十六进制：每 16 位一组，共 8 组
- 零压缩：`::` 代替连续零（只能用一次）
- 例：FF05:0:0:0:0:0:0:B3 → FF05::B3

### 过渡策略
- 双协议栈：同时支持 IPv4 和 IPv6
- 隧道技术：IPv6 数据报封装在 IPv4 数据报中传输

## 12. NAT（网络地址转换）

- 内部私有地址 ↔ 全球 IP 地址转换
- NAPT：多个内网主机共享一个全球 IP + 不同端口
- 优点：节省地址、安全
- 缺点：延迟增大、配置复杂
